# 분할 사양 — splits_v1.npz

생성: `./exe/a2_split.sh` (`src/a2_split_wm811k.py`). 시드 0, val_frac 0.2.
모든 실험은 이 파일 하나를 참조한다. 실험마다 분할을 새로 만들면 수치를 비교할 수 없다.

## 내용

| 키 | 의미 |
|---|---|
| `train` | 학습 인덱스 43,223 |
| `val` | 검증 인덱스 11,132 |
| `test` | 공식 test 인덱스 118,595 |
| `seed`, `val_frac` | 재현용 파라미터 |

전부 `wm811k_64.npz` 에 대한 정수 인덱스다.

## 규칙

1. **공식 `trianTestLabel` 을 그대로 존중한다.** Test 행은 학습에 절대 들어가지 않는다.
   문헌 수치와 비교 가능한 유일한 기준이다. (컬럼명 오타는 데이터셋 원본 그대로)
2. **val 은 Training 안에서 lot 단위로 뗀다.** 웨이퍼 단위 랜덤 분할을 쓰면 같은 lot 의
   거의 동일한 웨이퍼맵이 train 과 val 에 나뉘어 들어가 검증 수치가 낙관적으로 왜곡된다.
3. **val 은 체크포인트 선택에만 쓴다.** 성능 판단은 test 로만 한다. 근거는 아래.

## 실측 (2026-08-21)

| 분할 | 웨이퍼 | lot | none | 결함 |
|---|---:|---:|---:|---:|
| train | 43,223 | 4,647 | 29,149 | 14,074 |
| val | 11,132 | 1,162 | 7,581 | 3,551 |
| test | 118,595 | 4,953 | 110,701 | 7,894 |

- **lot 겹침 0.** train/val 0개, Training/Test 0개. 데이터 누수는 없다.
- **분포 이동이 크다.** none 비율이 Training 67.6% 대 Test 93.3% 이고,
  Edge-Ring 은 Training 8,554장 대 Test 1,126장으로 역전돼 있다.
  Test 가 Training 보다 2배 이상 크다는 점도 특이하다.

## 이 사양이 실험에 미친 영향

val 은 Training 분포를 물려받으므로 **일반화 성능의 추정치가 아니다**.
실제로 val 이 두 번 방향을 잘못 알려줬다(E3 은 val +0.016 인데 test +0.101,
E4 는 val -0.007 인데 test +0.099). 상세는 [CLASSIFICATION.md](../reports/CLASSIFICATION.md).

향후 lot-wise 5-fold CV 를 병기하면 단일 분할 의존을 줄일 수 있다. 아직 미구현.
