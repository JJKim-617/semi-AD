# OOD(one-class) 웨이퍼 이상탐지 기획 — 사전등록

- 작성일 2026-08-22, 브랜치 `exp/ood-oneclass`, worktree `JJ/etc/Semi-AD-OOD`
- 범위: **정상(none) 웨이퍼만 학습에 쓰고 결함을 이상으로 탐지한다.** 결함 라벨을 학습에 쓰지 않는다.
- 기존 9-class 지도학습(`exp/ad-baseline`)과 **별개 실험**이며 서로의 결과를 섞지 않는다.

## 0. 왜 이 프레이밍인가

실제 팹은 결함 유형을 미리 열거할 수 없다. 새 공정, 새 설비에서 처음 보는 패턴이 나오면
9-class 분류기는 그것을 아는 9개 중 하나로 우겨 넣는다. one-class 는 "정상이 아니다" 만
말하므로 그 조건에 맞고, 같은 연구실의 3D-AD 작업(`JJ/part/MARS`)이 쓰는 설정과도 같다.

## 1. 이미 확립된 것 (다시 재지 않는다)

- 웨이퍼맵 811,457장 중 라벨 172,950장. 셀 값 {0 다이없음, 1 정상, 2 불량} **명목형** —
  리사이즈는 최근접 이웃, 입력은 3채널 원-핫. 보간 금지.
- 공식 split 은 lot 단위(`splits_v1.npz`), lot 중복 0.
- **분포 이동**: none 비율 train 67.4% → test 93.3%. 결함률 32.6% → 6.7%.
- **one-class 학습 자료 = train 의 none 29,149장.**
- **val 은 품질을 재지 못하고 파국만 감지한다** (정상 모델들 사이 상관 +0.070, 이상치 포함 시 +0.779).
  설정 선택에 쓰지 않는다.
- run-to-run 범위 0.050. 최소 2~3 seed. 같은 가중치를 쓰는 짝지은 비교는 예외.
- **크기에 민감한 표현은 학습 커버리지 밖에서 붕괴한다.** train 의 58.1% 가 dieSize 400~562 한 구간에
  몰려 있고 test 의 45.9% 가 train 14.2% 인 구간에 있다. 극좌표가 정확히 이것으로 실패했다
  (none 오검출률이 구간별로 0.009 → 0.505).

## 2. E0 — 자명한 스칼라 기준선 (측정 완료)

**학습이 전혀 없는 스칼라 통계가 이미 어디까지 가는가.** 공식 test 118,595장 전수.

| 자명한 스칼라 | AUROC | AUPR | FPR@95TPR |
|---|---:|---:|---:|
| **불량 다이 개수** | **0.8167** | 0.3633 | 0.7367 |
| 불량 다이 비율 | 0.7899 | **0.3856** | 0.7364 |
| 웨이퍼 크기(die 수) | 0.5037 | 0.0650 | 0.9562 |
| 불량 공간 퍼짐(major sd) | 0.4727 | 0.0625 | 0.9926 |
| 불량 이심률 | 0.5064 | 0.0709 | 0.9548 |
| 무작위 | 0.5000 | 0.0666 | 0.95 |

**세 가지가 이 표에서 나온다.**

**(1) 바닥이 높다.** 불량 다이를 세기만 해도 AUROC 0.8167 이다. 원래 기획서(`ad_baseline_plan.md` §6)가
제안한 "AUROC 0.90 1차 기준" 은 이 바닥 위로 겨우 +0.083 이다. **0.90 은 목표로 삼기에 약하다.**

**(2) 운영 지점은 쓸모없다.** FPR@95TPR 0.7367 — 결함의 95% 를 잡으려면 정상 웨이퍼의 **74%** 를
같이 띄운다. test 의 정상이 110,701장이니 8만 장이 헛경보다. AUROC 0.82 가 실무에서 무의미하다는 뜻이다.

**(3) 내가 만든 공간 통계는 정보가 없다.** 퍼짐 0.4727 은 **무작위보다 낮고** 이심률 0.5064 는 무작위다.
전역 2차 모멘트로는 결함 구조가 안 잡힌다.

### 클래스별 (불량 다이 개수 기준, none 대비 AUROC)

| 결함 | n | AUROC |
|---|---:|---:|
| Near-full | 95 | **1.0000** |
| Random | 257 | 0.9968 |
| Donut | 146 | 0.9842 |
| Edge-Ring | 1,126 | 0.8946 |
| Edge-Loc | 2,772 | 0.8173 |
| Loc | 1,973 | 0.8095 |
| Center | 832 | 0.7540 |
| **Scratch** | 693 | **0.6559** |

**절반은 이미 끝난 문제다.** Near-full, Random, Donut 은 "불량이 많다" 는 것만으로 거의 완벽히 갈린다.
남은 값어치는 **Scratch, Center, Loc** — 불량 개수가 아니라 **공간 구조**로 정의되는 것들에 있다.
Scratch 가 0.6559 로 가장 어렵고, 이는 9-class 분류에서도 같았다(seed 마다 F1 이 0.28~0.63 으로 붕괴).

## 3. 주 지표 결정

**주 지표 = AUPR. 함께 보고 = FPR@95TPR, AUROC.**

근거:
- **AUROC 는 유병률에 불변**이라 9-class 때의 accuracy 함정(자명한 분류기가 0.9334)과 성질이 다르다.
  그러나 **절대 헛경보 부담을 반영하지 않는다.** 정상이 110,701장이면 FPR 1% 도 1,107장이다.
- **AUPR 은 유병률에 직접 묶인다.** 무작위 기준선이 곧 결함 비율 **0.0666** 이고, 어떤 재현율에서
  정밀도가 얼마인지가 실사용 가능성을 결정한다.
- **FPR@95TPR 은 팹 언어다.** "결함의 95% 를 잡으려면 정상 몇 %를 버려야 하는가."

**자명한 값을 테스트로 박는다.** 9-class 에서 "전부 none 분류기 accuracy 0.9334" 를 테스트로 고정해
지표 회귀를 막은 전례를 따른다 — 무작위 AUPR = 결함 비율 0.0666, 그리고 위 E0 표의
불량 다이 개수 AUROC 0.8167 을 회귀 테스트로 고정한다.

## 4. 문헌 검토와 그 한계

**웹 검색 예산이 이 세션에서 소진**되어 광범위 조사를 못 했다. 아래는 arXiv 초록을 직접 확인한 것과
레포 내 기존 조사이며, **확인 못 한 것은 그렇게 표시한다.**

| 방법 | 확인된 내용 | 출처 |
|---|---|---|
| PatchCore | 정상 patch feature 의 **memory bank**, **ImageNet 모델 임베딩** 사용, MVTec AD image AUROC 최대 99.6% | arXiv 2106.08265 초록 |
| PaDiM | **사전학습 CNN** patch 임베딩, **patch 위치별 다변량 가우시안**, one-class 설정 | arXiv 2011.08785 초록 |

두 방법 다 **ImageNet 사전학습 특징**에 의존한다. 그런데 이 레포의 기존 조사
(`docs/research/encoder_selection/README.md`)가 이 데이터에서 그 가정이 약하다는 근거를 이미 모아뒀다.

- 17만 장 규모에서 ImageNet 전이의 **최종 성능** 이득은 사라진다(Transfusion, Matsoukas 등).
- 웨이퍼맵 실측 사례: scratch CNN macro-F1 **83.14** vs MobileNetV2 fine-tuned **59.46**.
- 입력이 명목형 3값 격자라 자연영상 통계와 무관하고 ImageNet 정규화가 의미 없다.

**PaDiM 은 추가 위험이 있다.** patch **위치별** 가우시안은 입력이 공간적으로 정렬돼 있다고 가정한다
(MVTec 은 물체를 고정 자세로 촬영한다). 우리 웨이퍼는 크기가 크게 다르고, **크기에 민감한 표현이
학습 커버리지 밖에서 붕괴한다는 것을 이 프로젝트가 이미 실측했다**(§1, 극좌표). 위치별 통계는
정확히 그 함정에 해당한다. **미검증 예측이지만 근거 있는 우려다.**

→ **ImageNet 특징과 고정 자세를 전제하지 않는 방법부터 시작한다.**

## 5. 실험 사다리

| | 방법 | 학습 | 무엇을 묻는가 |
|---|---|---|---|
| **O0** | 자명한 스칼라 (완료) | 없음 | 바닥. **AUROC 0.8167 / AUPR 0.3856** |
| **O1** | 정상 통계 template 잔차 | 없음 | 정상 웨이퍼의 다이별 불량 확률 지도를 만들고 편차를 점수로. 3D-AD 의 잔차 발상을 2D 로 |
| **O2** | 자기지도 인코더 + kNN/Mahalanobis | 정상만 | 특징 기반이되 **ImageNet 대신 이 데이터로 학습한 인코더** |
| **O3** | 오토인코더 재구성 오차 | 정상만 | 명목형이므로 **범주 교차엔트로피** 재구성. MSE 금지 |

O1 을 먼저 하는 이유: 학습이 없어 가장 싸고, 3D-AD 에서 통한 발상이며, **크기 문제를 설계에서
정면으로 다뤄야 하는 것이 드러나 있다**(§1). 크기 정규화를 어떻게 하느냐가 O1 의 핵심 설계 결정이다.

## 6. 반증 조건 (실행 전에 박는다)

1. **어떤 방법이든 O0 을 넘지 못하면 기각한다.** 기준은 **AUPR 0.3856**, 보조로 AUROC 0.8167.
   "무작위보다 낫다" 는 의미 없다 — 바닥은 무작위가 아니라 불량 다이 개수다.
2. **Scratch, Center, Loc 에서 개선이 없으면 기각한다.** Near-full, Random, Donut 은 이미 0.98 이상이라
   전체 평균만 보면 개선이 그쪽에서 온 것처럼 보일 수 있다. **클래스별 표를 반드시 함께 낸다.**
3. **O2 에서 결함 라벨로 학습한 인코더를 쓰면 그것은 one-class 결과가 아니다.**
   쓰더라도 **별도 arm 으로 분리 보고**하고 one-class 수치와 섞지 않는다.
4. **2~3 seed.** 단일 실행 차이는 판정에 쓰지 않는다.
5. **크기 구간별로 확인한다.** 전체 지표가 올라도 dieSize 562~1090 구간(train 14.2% / test 45.9%)에서
   무너지면 극좌표와 같은 실패다.

## 7. 하지 않을 것

- **PatchCore/PaDiM 을 ImageNet 특징 그대로 첫 시도로 쓰지 않는다.** §4 의 근거 때문이다.
  나중에 비교군으로 넣을 수는 있으나, 그때도 이 데이터로 학습한 인코더 arm 과 **짝지어** 낸다.
- 임의 각도 회전, 탄성 변형, 밝기 조정 — 명목형 셀 값을 파괴한다.
- val 로 방법을 고르는 것(§1).

## 8. 격리 규약

- worktree `JJ/etc/Semi-AD-OOD`, 브랜치 `exp/ood-oneclass`. 상대 브랜치 파일을 고치지 않는다.
- 산출물은 `result/ood/` 아래에만 쓴다(`result` 는 공용 심링크).
- **02:00 까지 GPU 를 쓰지 않는다.** 9-class 실험이 GPU 0번을 점유 중이다.

# 9. 범위 확장 — OOD 는 파이프라인 1단계가 됐다 (2026-08-22 22:50)

**이것은 정정이 아니다.** §0~§8 의 판단은 그때 알던 것에 비추어 틀리지 않았다.
프로젝트 정의가 바뀌어 **이 워크스트림이 담당하는 범위가 넓어진 것**이다.
아래 §1~§6 의 데이터 규칙, 주 지표, 반증 조건은 **그대로 유효하다.**

## 9.1 무엇이 바뀌었나

Semi-AD 프로젝트가 두 갈래로 확정됐고, one-class OOD 는 그중 한 갈래의 **1단계**가 됐다.

```
OOD 탐지  →  다이 단위 국소화  →  MLLM 이 8종 결함으로 분류  →  유저 질의응답
 (여기)        (여기)
```

유저 질의응답은 "어디에 문제가 있어?", "무슨 모양이지?" 같은 질문에 답해야 한다.
그러려면 **어디가 이상한지**가 산출물로 남아야 한다.

## 9.2 다이 단위 잔차 맵이 1급 산출물이 된다

O1 의 template 잔차는 원래 **다이별 잔차 맵**인데 §5 까지의 설계는 그것을 스칼라로 뭉개
AUPR 만 봤다. 스칼라만 최적화하면 **뭉개는 방식(max? mean? 상위분위?)만 튜닝**하게 되고
하류가 실제로 쓸 맵의 품질은 방치된다.

→ **맵 자체를 파일로 저장하고(웨이퍼 id 동반) 시각화한다.**
→ 뭉개는 방식은 **하이퍼파라미터가 아니라 설계 선택**으로 다루고 근거를 후보 문서에 적는다.

## 9.3 국소화에는 정답이 없다 — P-AUROC 를 만들어내지 않는다

WM-811K 원본 컬럼은 `waferMap`, `dieSize`, `lotName`, `waferIndex`, `trianTestLabel`,
`failureType` 6개뿐이고 `failureType` 은 **웨이퍼당 문자열 하나**다.
**다이 단위 마스크는 데이터에 존재하지 않는다.** 셀 값 `2` 는 "떨어진 다이"이지
"결함 패턴에 속한 다이" 가 아니다.

- **픽셀 단위 정답을 합성해 P-AUROC 를 내지 않는다.** 합성 정답으로 재면
  모델이 아니라 **내 합성 규칙**을 재게 된다. 이건 그 자체로 기각 사유다.
- 국소화는 **정성 평가(대표 사례 시각화) + 간접 평가**로만 판정한다.

## 9.4 간접 평가가 국소화의 진짜 반증 조건이다

잔차 맵이 값어치가 있다면 **하류 8종 분류를 개선해야 한다.**

| | MLLM 입력 |
|---|---|
| 대조군 | 원본 웨이퍼맵만 |
| 실험군 | 원본 + **잔차 맵** |

**실험군이 8종 macro-F1 에서 유의하게 낫지 않으면 잔차 맵은 값어치가 없다.**
이 조건은 MLLM 을 붙이는 사이클의 후보 문서에 **실행 전에** 박는다.

8종 분류는 결함 웨이퍼에 한해 Center, Donut, Edge-Loc, Edge-Ring, Loc, Near-full,
Random, Scratch 의 macro-F1 으로 잰다. **여기서도 클래스별 표를 반드시 함께 낸다** —
Scratch/Center/Loc 이 어려운 쪽이라는 것은 §2 에서 이미 확립됐다.

## 9.5 1단계 지표는 그대로다

탐지는 **AUPR(자명한 기준선 0.3856)** 주 지표, **FPR@95TPR(0.7364)** 병기.
§3 과 §6 의 반증 조건 5개는 바뀌지 않는다.

## 9.6 최종 북극성

파이프라인 전체를 **9-way(none + 8종)** 로 평가해
**지도학습 9-class 의 macro-F1 0.790 과 직접 비교**한다.

이 워크스트림의 주장은 그때 **"결함 라벨을 학습에 한 장도 쓰지 않고 어디까지 가나"** 가 된다.
비교 자체가 공정하려면 §1 의 격리 규칙(결함 라벨은 평가에서만)이 파이프라인 전 구간에서
지켜져야 한다. MLLM 을 붙일 때 프롬프트에 결함 예시를 넣는 순간 그것은 few-shot 지도학습이므로
**별도 arm 으로 분리 보고**한다(§6-3 과 같은 규칙).

**지금 이 숫자를 내는 것이 목표가 아니다.** 나중 단계이며, 여기에 적는 이유는
사다리의 각 칸이 무엇을 향해 가는지 실행 전에 고정해 두기 위해서다.

## 9.7 오늘 밤(2026-08-23 03:30 까지) 의 범위

MLLM 은 아직 붙이지 않는다. O1 을 계속하되:

1. 잔차 맵을 **파일로 저장**(웨이퍼 id 동반)
2. 대표 사례 시각화를 `docs/` 아래에 — 정상 / 맞춘 결함 / 놓친 결함
3. 특히 **Scratch, Center, Loc** 사례. 개수 기준으로 안 잡히는 것들이고
   국소화가 값어치를 내야 할 지점이 정확히 여기다
4. 맵 → 스칼라 뭉개는 방식 비교(max, 상위 k% 평균, 연결성분 최대 크기 등)

# 10. "정상만 사용" 의 범위 — 어디까지가 one-class 인가 (2026-08-23 01:4x)

O2 로 가면서 **합성 결함 계열**(DRAEM, CutPaste 식 — 정상 웨이퍼 위에 가짜 결함을 그려 넣고
그것을 복원/판별하도록 학습)이 후보에 올랐다. 이 데이터에서는 자연영상보다 유리할 수 있다.
결함 기하가 단순하고 이미 알려져 있기 때문이다 — **선(Scratch), 중앙 원반(Center),
테두리 띠(Edge-Loc), 고리(Edge-Ring, Donut)**.

**그런데 이건 "정상만 사용" 의 경계에 걸린다.** 애매하게 두면 나중에 주장 전체가 흔들리므로
여기서 못을 박는다.

## 10.1 세 가지를 구분한다

| | 무엇을 쓰는가 | one-class 인가 |
|---|---|---|
| **A. 정상 데이터** | train 의 none 29,149장의 픽셀 | **예.** 지금까지 전부 여기 |
| **B. 결함 모양에 대한 사전지식** | "긁힘은 선이다", "Center 는 중앙 원반이다" — **사람이 아는 것**, 데이터에서 읽은 게 아님 | **조건부로 예.** 아래 §10.2 |
| **C. 결함 데이터** | 결함 웨이퍼의 픽셀이나 라벨 | **아니오.** 쓰면 그 순간 무효 |

**C 는 절대 금지다.** 기획서 §1 그대로다.
지금까지의 모든 결과(O0~O1, 반경 보정까지)는 **A 만** 썼다.

## 10.2 B 를 쓰면 무엇을 잃는가

**B 는 공짜가 아니다.** "결함 유형을 미리 열거할 수 없다" 는 것이 §0 에서
one-class 를 고른 이유였는데, 결함 모양을 프로그램에 박으면 **바로 그 전제를 일부 포기**한다.
처음 보는 패턴은 여전히 못 그린다.

그래서 규칙은 이렇다.

1. **B 를 쓰는 arm 은 반드시 별도 arm 으로 분리 보고한다.** A 만 쓰는 arm 과 수치를 섞지 않는다.
   §6-3 에서 "결함 라벨로 학습한 인코더는 별도 arm" 이라고 한 것과 같은 규칙이다.
2. **어떤 사전지식을 넣었는지 문서에 열거한다.** "선, 원반, 고리, 띠" 처럼 구체적으로.
   나중에 "그 모양을 어디서 알았나" 를 추적할 수 있어야 한다.
3. **사전지식의 파라미터를 test 성능으로 고르지 않는다.** 선의 굵기, 원반의 반지름 분포 같은
   것을 test 로 맞추면 그건 결함 데이터를 간접적으로 쓴 것이다.
   정상 웨이퍼의 통계(다이 크기, 불량률)에서 유도하거나 미리 고정한다.
4. **8종 클래스 이름을 합성에 쓰더라도, 그 클래스의 실제 표본은 보지 않는다.**
   `failureType` 컬럼을 열어 모양을 확인하고 베끼면 그건 C 다.

## 10.3 이미 B 를 쓴 것이 있다 — 소급해서 표시한다

**3차 사이클의 방향성 선형 필터가 B 였다.** "긁힘은 선이다" 라는 사전지식을
창 모양에 넣었다. 그때는 이 구분을 명시하지 않았다.

다행히 **그 arm 은 기각됐으므로 현재 최선 수치에 영향이 없다.**
현재 최선(반경 대역 보정 밀도)은 A 만 쓴다 — 창은 정사각이고 보정은 정상 통계다.

`docs/reports/OOD.md` 의 표에 A/B 구분을 넣는다.

## 10.4 그래서 O2 를 어떻게 가는가

- **A-arm 먼저**: 정상 웨이퍼만으로 자기지도 학습(마스킹 복원, 회전 예측 같은
  **결함 모양을 안 쓰는** 과제) + kNN/Mahalanobis. 이게 기본선이다.
- **B-arm 은 그 다음**, 그리고 **A-arm 과 짝지어** 보고한다.
  B 가 A 를 못 넘으면 사전지식을 넣을 이유가 없다는 뜻이다.
- 어느 쪽이든 **새 바닥 AUPR 0.7147**(반경 보정은 0.7407)을 넘어야 의미가 있다.
  §6 의 반증 조건 1 에 적힌 0.3856 은 **무효다** — `docs/reports/OOD.md` 정정 1 참조.

## 10.5 문헌에 대해 — 이 세션에서는 확인할 수 없다

**웹 검색이 이 세션에서 막혀 있다.** DRAEM, CutPaste 의 구체적 설계(합성 방식, 손실 함수,
보고된 수치)를 **확인하지 못했다.** 위에서 "DRAEM, CutPaste 식" 이라고 부른 것은
**"정상 위에 가짜 결함을 합성해 학습한다" 는 일반적 발상**을 가리키는 것이지
그 논문들의 구체적 방법을 재현한다는 뜻이 아니다.
검색이 되는 세션에서 확인하기 전까지 **그 논문들의 수치나 설계를 인용하지 않는다.**
