# OOD(one-class) 이상탐지 현황 — WM-811K

**현재 상태를 담는 문서다.** 사이클별 경위는
[experiments/details/ood_cycle_log.md](../experiments/details/ood_cycle_log.md) 에 있다.

설정: **train 의 none 29,149장만 학습에 쓰고** 공식 test 118,595장(정상 110,701 / 결함 7,894)에서 평가.
결함 라벨을 학습에 쓰지 않는다. 갱신일 2026-08-23, 브랜치 `exp/ood-oneclass`.

## 이 워크스트림의 자리 — 파이프라인 1단계

프로젝트가 두 갈래로 확정되면서 OOD 는 **파이프라인의 1단계**가 됐다
([기획서 §9](../plans/2026-08-22-ood-oneclass-preregistration.md)).

```
OOD 탐지  →  다이 단위 국소화  →  MLLM 8종 분류  →  유저 질의응답
 (여기)         (여기)
```

그래서 **다이 단위 맵이 스칼라와 같은 급의 산출물이다.**
"어디에 문제가 있어?" 에 답하려면 넘겨줄 것이 맵이어야 한다.
최종 북극성은 파이프라인 전체를 9-way 로 평가해 **지도학습 9-class 의 macro-F1 0.790 과
직접 비교**하는 것이다 — "결함 라벨을 한 장도 안 쓰고 어디까지 가나".

## 주 지표

**AUPR (주), FPR@95TPR, AUROC (병기), 운영 지점 표 (상설).**
정상이 110,701장이라 FPR 1% 도 1,107장이다.
AUPR 은 무작위 기준선이 곧 결함 비율 0.0666 이라 실사용 가능성을 직접 보여준다.

## 무엇을 썼는가 — A / B / C 구분

기획서 §10. **C(결함 데이터)는 어디에도 안 썼다.**

| | 무엇 | 지금까지 |
|---|---|---|
| **A** | 정상 데이터만 | **현재 최선을 포함해 채택된 것 전부** |
| **B** | + 결함 모양 사전지식(선, 원반, 고리 …) | 3차 사이클 방향성 선형 필터. **기각됨** |
| **C** | + 결함 데이터/라벨 | **없음** |

B 를 쓰는 arm 은 A-arm 과 **분리 보고**한다. B 는 "결함 유형을 미리 열거할 수 없다" 는
이 워크스트림의 전제를 일부 포기하는 것이라 공짜가 아니다.

## 현재 최선

| 방법 | 학습 | AUROC | **AUPR** | FPR@95TPR |
|---|---|---:|---:|---:|
| **반경 대역 보정 밀도 max 7x7** | **정상만 (A)** | **0.9396** | **0.7407** | **0.3603** |
| (미확인) 다중척도 밀도 결합 k=3,5,7,9 | 정상만(보정) | 0.9289 | *0.7264* | *0.4295* |
| 국소 불량 밀도 max 7x7 | 없음 | 0.9206 | 0.7145 | 0.4844 |

| 국소 불량 밀도 max 5x5 | 없음 | 0.9230 | 0.6885 | 0.4398 |
| 반경 template 잔차 + 평활 max 5x5 | 정상만 | **0.9322** | 0.6808 | 0.3668 |
| 반경 template 잔차 + 평활 max 3x3 | 정상만 | 0.9237 | 0.6034 | **0.3396** |
| 국소 불량 밀도 max 3x3 | 없음 | 0.9098 | 0.4968 | 0.4018 |
| E0 불량 다이 비율 | 없음 | 0.7899 | 0.3856 | 0.7364 |

| 무작위 | — | 0.5000 | 0.0666 | 0.95 |

**현재 최선 = 반경 대역 보정 밀도 max 7x7.** 각 다이의 창 7x7 불량 밀도를
**같은 정규화 반경 대역에 있는 train-none 다이들의 경험분포에서의 백분위**로 바꾼 뒤 최대를 취한다.
정상 웨이퍼 자체를 귀무로 쓰는 것이고, **Scratch·Center·Loc 을 동시에 최고로 만든 유일한 arm**이다.
전역(대역 없는) 보정은 오히려 손해라, 이득은 보정이 아니라 **반경 조건부**에서 온다.

**용도에 따라 답이 다르다. 하나만 쓰면 거짓말이 된다.**
- 이전 최선(대조군) = **국소 밀도 7x7** (template 없음, 학습 0)
- 운영 지점 최고 = **반경 template + 평활 3x3** (FPR@95TPR 0.3396)
- Scratch/Center/Loc 최고 = **반경 template 계열** (아래 클래스별 표)

*기울임 = **미확인**. 다중척도 결합은 3차 사이클에서 **탐색 arm** 으로 나왔다
(대조군 대비 짝지은 +0.0119 [+0.0096, +0.0142], p=0.0000). 탐색 arm 7개 중 1개가 이겼고
**무엇을 부각할지는 결과를 보고 정했으므로**, 주 arm 으로 사전등록해 다시 재기 전에는
채택하지 않는다. 표에는 남기되 "현재 최선" 으로 인용하지 않는다.*

## 운영 지점 — 상설 표

**AUPR 총합은 어디서 무너지는지를 가린다.** 팹이 감당하는 것은 곡선 아래 넓이가 아니라
헛경보 장수다. 공식 test 118,595장(정상 110,701 / 결함 7,894) 기준.

| arm | 재현율 50% | 재현율 80% | 재현율 95% |
|---|---|---|---|
| | precision / 헛경보 | precision / 헛경보 | precision / 헛경보 |
| E0 불량 다이 비율 | 0.247 / 12,024 | 0.121 / 46,016 | 0.084 / 81,522 |
| 국소 밀도 k=3 | 0.486 / 4,174 | 0.278 / 16,414 | **0.133** / 48,894 |
| 국소 밀도 k=5 | 0.791 / 1,043 | 0.364 / 11,059 | 0.133 / 48,927 |
| 국소 밀도 k=7 | 0.863 / 628 | 0.356 / 11,402 | 0.123 / 53,621 |
| 국소 밀도 k=9 | 0.839 / 759 | 0.327 / 12,980 | 0.116 / 56,933 |
| **반경보정 밀도 k=7** | **0.880 / 540** | **0.464 / 7,290** | **0.158 / 39,889** |

**50% → 80% 사이에서 precision 이 반토막 난다**(k=7: 0.863 → 0.356).
**여기가 실질 목표다** — 곡선이 무너지는 이 구간이 Scratch/Center 가 사는 곳이다.
반경 보정이 그 구간을 가장 크게 올린다(0.356 → 0.464, 헛경보 11,402 → 7,290).

**창 크기는 운영 지점마다 우열이 갈린다 — 하나가 지배하지 않는다.**
50% 는 k=7, 80% 는 k=5, 95% 는 k=3 이 최고 precision 이다.
**단일 최적 k 를 고르지 않는다.**

원자료 `docs/research/ood_operating_points/evidence/operating_points.{txt,json}`.

## 바닥이 바뀌었다 — 0.3856 이 아니라 0.7147 이다

**이것이 이 워크스트림의 가장 중요한 정정이다.**

O0 은 "학습 없는 자명한 스칼라" 를 잰다면서 **전역 스칼라만 쟀다**(개수, 비율, 크기,
2차 모멘트 — 전부 웨이퍼를 숫자 하나로 접는 것). 그리고 바닥을 AUPR 0.3856 이라고 적고
그 위에서 사다리의 채택 기준을 세웠다.

**창 하나 크기의 국소 스칼라가 AUPR 0.7147 을 낸다.** 이것도 학습이 0 이다 —
template 도, 파라미터도, train 자료도 쓰지 않는다.

E0 에서 전역 2차 모멘트가 무작위보다 낮은 것(0.4727)을 보고
"전역 통계로는 결함 구조가 안 잡힌다" 고 **옳게** 적어 놓고도,
그 다음 질문("그럼 국소 통계는?")을 O1 학습 사다리로 미룬 것이 실수였다.

→ **어떤 방법이든 이제 AUPR 0.7147 / FPR@95TPR 0.4852 를 넘어야 의미가 있다.**
→ 2차 사이클에서 "융합이 0.4058 로 바닥을 이겼다" 고 적은 것은 **잘못된 바닥에 대고
이긴 것**이다. 새 바닥에 한참 못 미친다.

수치는 `tests/test_a24_local_density_pin.py`(새 바닥)와
`tests/test_a21_ood_baseline_pin.py`(E0)로 **고정돼 있다.**

## 클래스별 — 어디에 값어치가 남아 있는가

none 대비 AUROC.

| 결함 | n | E0 개수 | 국소밀도 7x7 | **반경보정 7x7** | 반경+평활 3x3 | *다중척도* |
|---|---:|---:|---:|---:|---:|---:|
| Near-full | 95 | 1.0000 | 1.0000 | 0.9997 | 1.0000 | 1.0000 |
| Random | 257 | 0.9968 | 0.9988 | **0.9994** | 0.9967 | 0.9988 |
| Donut | 146 | 0.9842 | 0.9869 | **0.9972** | 0.9943 | 0.9862 |
| Edge-Ring | 1,126 | 0.8946 | 0.9690 | 0.9600 | 0.9006 | **0.9735** |
| Edge-Loc | 2,772 | 0.8173 | 0.9845 | 0.9802 | 0.9358 | **0.9875** |
| Loc | 1,973 | 0.8095 | 0.9151 | 0.9529 | **0.9702** | 0.9245 |
| Center | 832 | 0.7540 | 0.7458 | 0.8112 | **0.8558** | 0.7971 |
| **Scratch** | 693 | 0.6559 | 0.7586 | **0.8184** | 0.8090 | 0.7451 |

반경 보정은 **Scratch 0.8184, Center 0.8112, Loc 0.9529 를 동시에** 낸다.
Edge 계열은 원리적 대가로 조금 깎인다(진짜 Edge 결함도 가장자리에 있으므로).

**전체 AUPR 은 Edge 계열이 지배한다** — 결함 7,894장 중 Edge-Loc 2,772 + Edge-Ring 1,126
= 3,898장(49.4%). 반경 template 은 Edge 를 깎고 Scratch/Loc/Center 를 올리므로
**합계는 지고 값어치 남은 곳에서는 이긴다.** 그래서 클래스별 표를 항상 함께 낸다.

**Center 가 이제 가장 어렵다.** Scratch 0.656 → 0.811 로 크게 올랐지만
Center 는 0.754 → 0.856 (3x3 에서만) 이고 7x7 에서는 기준선과 같다.

## 정정 기록

이전 결론을 고쳐 쓰지 않고 남긴다. **무엇이 왜 틀렸는지가 이 워크스트림의 주 산출물이다.**

1. **바닥이 틀렸다** (2026-08-23). 0.3856 → **0.7147**. 자명한 기준선을 셀 때
   **공간 국소성을 후보에 안 넣었다.** 위 절 참조.
2. **빠진 대조군** (2026-08-23). `smooth_k_max` 의 성과를 template 의 것으로 읽었는데,
   대수적으로 **균일 template + smooth_k_max = 국소 밀도의 최대**다
   (창 평균 = -log(1-p) + f·log((1-p)/p), 기울기 양수인 아핀).
   **뭉개기를 바꾸면 대조군도 같이 바뀌어야 한다.**
3. **반증 조건 6 이 틀린 검정이었다** (2026-08-22). "독립 CI 가 안 겹쳐야 이긴 것" 으로
   박았는데, 두 점수가 같은 test 집합 위에 있으므로 **짝지은 검정**을 써야 한다.
   `paired_aupr_diff_ci` 를 추가했다.
4. **등가성을 argsort 로 박으려다 실패** (2026-08-23). 항등식 오차는 8e-16 인데
   아핀 변환이 **동점 구조**를 바꿔 순열과 AUROC 가 갈린다(0.5006 vs 0.5019).
   등식과 기울기 부호를 박고 **값이 실제로 다른 쌍의 대소만** 비교하도록 고쳤다.
5. **실행 전 예측이 4개 중 3개 틀렸다** (2026-08-22). "정상은 가장자리에서 더 죽는다" 는
   전제가 반쪽이었다. 아래 참조.
6. **선 필터 포화의 첫 설명이 350배 틀렸다** (2026-08-23). "창 후보가 많아 다중비교로
   우연히 걸린다" 고 읽었는데, 독립 Bernoulli 아래 기대값은 `8x800x0.116^7 = 0.002`,
   즉 0.2% 다. 실측은 70% 였다. 우연이 아니라 **정상의 불량이 실제로 뭉쳐 있다**
   (포화 창의 95.49% 가 반경 0.85 바깥).
7. **중심 다이 제외 가설이 틀렸다** (2026-08-23). 정상의 중심 다이가 58.9% 불량이니
   빼면 Center 가 좋아질 줄 알았는데 오히려 나빠졌다(0.7458 → 0.7380).
   **중심 다이 교란은 셀 하나짜리 통계에서만 문제였고 창 통계에서는 아니다.**
8. **동점이 많은 점수의 AUPR 이 관례 의존적이다** (2026-08-23, **미해결 — 5차에서 고친다**).
   k=3 국소 밀도는 고유값이 108개뿐이고, 결정론적 AUPR 0.4986 이
   **동점 무작위 해소 범위 [0.4112, 0.4248] 바깥**이다. 동점 안에서 원래 인덱스 순서를
   쓰는데 test 배열 위치와 결함 여부에 약한 상관이 있어(0.0116) **라벨이 샌다.**
   k>=5 에서는 폭이 0.004 이하라 영향이 없다.
   덧붙여 점수를 **float32 로 저장하면 동점이 새로 생긴다**(k=3 고유값 108 → 24).

## 알아낸 사실 — 정상 웨이퍼의 정체

**1. 정상 웨이퍼는 중심에서 가장 자주 죽는다.**
train-none 의 **중심 최근접 다이는 58.9% 가 불량**이다(전체 다이 불량률 11.6%).
반경 프로파일이 U 자다: 중심 0.55 → 중간 0.085 → 가장자리 0.34.
이 때문에 Center 결함이 "정상스럽게" 보인다.
**왜 중심 다이가 그런지는 모른다** — WM-811K 는 6개 컬럼뿐이라 확인할 방법이 없다.

**2. `none` 은 "불량 다이가 없다" 가 아니라 "알아볼 만한 패턴이 없다" 이다.**

| | 중앙값 | 하위 10% |
|---|---:|---:|
| none (n=110,701) | 0.0883 | 0.0404 |
| **Scratch** (n=693) | **0.1037** | 0.0576 |
| Center (n=832) | 0.1184 | 0.0695 |

Scratch 의 불량 다이 비율 중앙값이 정상의 **1.17배**다.
불량률 0.10 초과가 정상 43,923장(39.7%) 대 결함 6,225장(78.9%) — 정상 절대 수가 7배다.
**밀도 축만으로는 원리적 천장이 있다.**

**3. 정상 웨이퍼의 바깥 링에는 연속으로 죽은 다이가 줄줄이 있다.**
길이 7 짜리 직선 창을 8방향으로 놓으면 **정상 웨이퍼의 70.21% 에서 창이 전부 불량으로 찬다.**
독립 Bernoulli 아래 기대값(0.2%)의 350배다. 포화 지점의 **95.49% 가 반경 0.85 바깥**이고,
안쪽만 보게 하면 포화가 70.63% → 19.19% 로 준다.
**가장자리는 따로 다뤄야 한다.** 왜 링에 연속 불량이 이어지는지는 모른다.

**4. 가장 좋은 탐지기가 가장 나쁜 지도를 만든다.**
반경 보정 백분위는 탐지 최선인데 맵으로 그리면 **온통 노랗다** —
다이 800개의 백분위 최대는 귀무에서도 1-1/800 근처라 값이 1 근처에 몰린다
(정상 90분위가 0.99472). `-log10(1-u)` surprisal 척도로 펴면 **원시 밀도 맵보다 선명하다.**
**탐지 성능과 국소화 가독성은 다른 축이다.** 저장은 무손실 백분위로, 표시와 하류 입력은
surprisal 로 한다.

**5. 구조 점수는 탐지기가 아니라 클래스 판별자다.**
불량률을 맞춘 뒤의 구조 점수 S_llr 은 Edge-Ring AUROC 0.023 으로 탐지에는 최악인데,
이는 정보가 없는 게 아니라 **부호가 반대**라는 뜻이다.
결함끼리만 보면 **학습 없는 스칼라 하나가 Edge-Ring 대 Scratch 를 AUROC 0.983 으로 가른다**
(불량 다이 개수는 0.171, 뒤집어도 0.829). **3단계 MLLM 분류가 필요로 하는 신호다.**

## 국소화 산출물 (2단계 입력)

`result/ood/o1_maps/o1_maps_pad.npz` — 결함 7,894장 전부 + 정상 5,000장, **원 좌표(pad)**.

| 키 | 내용 |
|---|---|
| `density_k5` | 창 5x5 안 불량 다이 비율. template 없음 |
| `radial_residual_k5` | 반경 template NLL 잔차를 5x5 평활 |
| `radial_cal_k7` | 창 7x7 밀도의 **반경 대역별 정상 백분위**. 현재 최선 |
| `wafer`, `y`, `cache_index`, `die_size`, `lot_name` | 원본과 식별자 |

**둘 다 저장한 이유: 어느 쪽이 하류 8종 분류를 돕는지 아직 모른다.**
탐지 AUPR 은 `density` 가 높지만 그림으로는 `radial_residual` 이 읽기 좋다.
기획서 §9.4 의 간접 평가로만 답할 수 있다.

대표 사례: `docs/research/ood_template/evidence/cases_{scratch,center,loc,edgering}.png`
(잘 잡은 것 / **놓친 것** / 헛경보 정상 / 전형적 정상).

**픽셀 단위 정답은 만들지 않는다**(기획서 §9.3). WM-811K 에 다이 단위 마스크가 없고,
합성 정답으로 P-AUROC 를 내면 모델이 아니라 합성 규칙을 재게 된다.

정성 관찰:
1. 잡은 Scratch 에서 **선이 맵에 그대로 보인다.** 국소화가 실제로 된다.
2. 놓친 Scratch 는 불량 비율 0.016~0.048 이고 **선이 창보다 가늘다.**
   5x5 창 안 밀도가 0.23 밖에 안 된다. **놓치는 이유가 명확하다.**
3. 헛경보 정상은 **가장자리 링이 켜진다.** 반경 template 이 그 자리를 깎는 것이 보인다.

## 설명 없는 관측

- **왜 창 7x7 이 최적인가.** 0.4968(k=3) → 0.6885(k=5) → 0.7147(k=7) → 0.7007(k=9).
  결함 크기 분포와 관련이 있을 것 같지만 확인하지 않았다.
- **왜 k=3 에서만 반경 template 이 도움이 되는가.** "작은 창에서 밀도 추정이 잡음이라
  사전정보가 작동한다" 는 해석은 **검증하지 않았다.**
- **중심 다이 58.9% 불량의 원인.** 위 참조.

## 다음

1. **동점 관례를 고친다**(정정 8). 동점을 블록으로 묶는 AUPR 로 바꾸고 바닥 수치를 다시 박는다.
2. **다중척도 결합을 주 arm 으로 사전등록해 재확인한다.** 지금은 탐색 결과라 채택 못 한다.
2. **새 바닥 0.7147 위에서 O2(자기지도 인코더)/O3(오토인코더)를 다시 설계한다.**
   이전 사다리의 채택 기준(0.3856)은 무효다.
3. **`max` 뭉개기의 포화를 보정한다.** 무작위 배치 귀무는 너무 느슨하다 —
   정상의 뭉침이 진짜이기 때문이다. **정상 웨이퍼 자체를 귀무로 쓰는 보정**이 맞는 방향이다.
4. **가장자리를 따로 다룬다.** 정상에서도 링이 포화한다.
5. Center 가 여전히 가장 어렵다. 작은 창(k=3, 반경 template)이 유리한 것까지는 보이는데
   이유를 모른다.
6. 두 맵 중 무엇이 하류 8종 분류를 돕는지 — MLLM 사이클의 간접 평가(§9.4).

## 이 워크스트림이 쓰지 않는 것

- **PatchCore, PaDiM 을 ImageNet 특징 그대로 첫 시도로 쓰지 않는다.** 둘 다 ImageNet
  사전학습 특징에 의존하는데(arXiv 2106.08265, 2011.08785), 이 데이터에서 그 전이가
  약하다는 근거가 레포에 있다. PaDiM 의 patch 위치별 가우시안은 공간 정렬을 가정하는데,
  **절대 좌표 template 이 균일 상수와 구분되지 않은 이번 결과가 그 우려를 실측으로 뒷받침한다.**
- **합성 픽셀 정답과 P-AUROC.**
- **val 로 방법 고르기** — val 은 품질을 재지 못하고 파국만 감지한다.
