# OOD(one-class) 이상탐지 현황 — WM-811K

**현재 상태를 담는 문서다.** 사이클별 경위는
[experiments/details/ood_cycle_log.md](../experiments/details/ood_cycle_log.md) 에 있다.

설정: **train 의 none 29,149장만 학습에 쓰고** 공식 test 118,595장(정상 110,701 / 결함 7,894)에서 평가.
결함 라벨을 학습에 쓰지 않는다. 갱신일 2026-08-22, 브랜치 `exp/ood-oneclass`.

## 주 지표

**AUPR (주), FPR@95TPR, AUROC (병기).** 근거는
[기획서 §3](../plans/2026-08-22-ood-oneclass-preregistration.md).

AUROC 는 유병률에 불변이라 9-class 때의 accuracy 함정과 성질이 다르지만,
**절대 헛경보 부담을 반영하지 못한다** — 정상이 110,701장이라 FPR 1% 도 1,107장이다.
AUPR 은 무작위 기준선이 곧 결함 비율 **0.0666** 이라 실사용 가능성을 직접 보여준다.

## 현재 최선 — 아직 자명한 스칼라다

| 방법 | 학습 | AUROC | **AUPR** | FPR@95TPR |
|---|---|---:|---:|---:|
| **불량 다이 비율** | 없음 | 0.7899 | **0.3856** | 0.7364 |
| **불량 다이 개수** | 없음 | **0.8167** | 0.3633 | 0.7367 |
| 웨이퍼 크기(die 수) | 없음 | 0.5037 | 0.0650 | 0.9562 |
| 불량 공간 퍼짐 | 없음 | 0.4727 | 0.0625 | 0.9926 |
| 불량 이심률 | 없음 | 0.5064 | 0.0709 | 0.9548 |
| 무작위 | — | 0.5000 | 0.0666 | 0.95 |

이 값들은 `tests/test_a21_ood_baseline_pin.py` 로 **고정돼 있다.** 되돌아가면 테스트가 깨진다.

### 이 표에서 나오는 세 가지

**1. 바닥이 높다.** 불량 다이를 세기만 해도 AUROC 0.8167 이다.
원래 기획서가 제안한 "AUROC 0.90 1차 기준" 은 이 바닥 위로 **겨우 +0.083** 이라 목표로 약하다.
**판정 기준은 AUPR 0.3856 이다.**

**2. 운영 지점은 쓸모없다.** FPR@95TPR 0.7367 — 결함의 95% 를 잡으려면 정상 웨이퍼의 **74%**,
약 8만 장을 같이 띄운다. AUROC 0.82 가 실무에서 무의미하다는 뜻이고,
**개선을 주장하려면 이 숫자가 내려가야 한다.**

**3. 전역 공간 통계는 정보가 없다.** 퍼짐 0.4727 은 **무작위보다 낮고** 이심률 0.5064 는 무작위다.
2차 모멘트로는 결함 구조가 안 잡힌다. 9-class 쪽에서도 같은 결과가 나왔다
(none→Scratch 오검출 웨이퍼와 진짜 Scratch 를 전역 통계로 구분하지 못했다).

## 클래스별 — 어디에 값어치가 남아 있는가

불량 다이 개수 기준, none 대비 AUROC.

| 결함 | n | AUROC | |
|---|---:|---:|---|
| Near-full | 95 | **1.0000** | 개수만으로 끝 |
| Random | 257 | 0.9968 | 〃 |
| Donut | 146 | 0.9842 | 〃 |
| Edge-Ring | 1,126 | 0.8946 | |
| Edge-Loc | 2,772 | 0.8173 | |
| Loc | 1,973 | 0.8095 | **여지 있음** |
| Center | 832 | 0.7540 | **여지 있음** |
| **Scratch** | 693 | **0.6559** | **가장 어렵다** |

**절반은 이미 끝난 문제다.** 남은 값어치는 **Scratch, Center, Loc** — 불량 개수가 아니라
**공간 구조**로 정의되는 것들이다. Scratch 는 9-class 분류에서도 가장 불안정했다
(seed 마다 F1 0.28~0.63).

전체 평균만 보면 개선이 이미 쉬운 클래스에서 온 것처럼 보일 수 있으므로
**클래스별 표를 항상 함께 낸다.**

## 이 워크스트림이 쓰지 않는 것

- **PatchCore, PaDiM 을 ImageNet 특징 그대로 첫 시도로 쓰지 않는다.** 둘 다 ImageNet 사전학습
  특징에 의존하는데(arXiv 2106.08265, 2011.08785 초록 확인), 이 데이터에서 그 전이가 약하다는
  근거가 레포에 이미 있다. PaDiM 의 patch 위치별 가우시안은 공간 정렬을 가정하는데
  우리 웨이퍼는 크기가 크게 달라 **극좌표가 실패한 것과 같은 함정**에 해당한다(미검증 우려).
- val 로 방법 고르기 — val 은 품질을 재지 못하고 파국만 감지한다.
