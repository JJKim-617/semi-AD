# 분류 성능 현황 (WM-811K 9-class)

**현재 상태를 담는 문서다.** 사이클별 경위는
[experiments/details/cycle_log.md](../experiments/details/cycle_log.md) 에 있다.

주 지표는 **공식 test split(118,595장, none 93.3%)의 macro-F1**.
val 은 체크포인트 선택에만 쓴다. 갱신일 2026-08-22.

## 현재 최선

| | 값 |
|---|---|
| **test macro-F1** | **0.7809** |
| **test accuracy** | **0.9697** |
| 구성 | **수렴한 체크포인트 10개 전부의 확률 평균** (pad64 x3, resize64 x4, resize96 x1, SizeAwareNet x2) |
| 공통 | ResNet-18(stem 3x3 s1, maxpool 제거), one-hot 3채널, dihedral 증강, Adam 1e-3, batch 256, 40 epoch, cosine + warmup 3 |
| 재현 | `bench_ensemble.py` (구성원은 `docs/experiments/ensemble_members.json`) |

8개에서 10개로 늘린 이득은 +0.0024 인데, 이것은 **아무 모델이나 둘 더 넣어도 나오는 값**이다
(크기 곡선 k=8 0.7785, k=9 0.7801, k=10 0.7809). 새로 들어간 두 개가 특별해서가 아니다.
[구조 다양성 절](#구조-다양성은-아무것도-보태지-않았다) 참고.

**앙상블을 최선으로 삼는 이유는 성능만이 아니다. 고를 필요가 없기 때문이다.**
아래에서 보듯 이 프로젝트에는 설정을 고를 수 있는 검증 지표가 없다.

| | test macro-F1 |
|---|---:|
| 무작위로 모델 하나를 고를 때의 기대값 | 0.7256 |
| 운 좋게 최고 모델을 골랐을 때 | 0.7485 |
| pad 3 seed 앙상블 | 0.7564 |
| 표현을 섞은 8개 앙상블 | 0.7785 |
| **가진 것 전부 10개 앙상블** | **0.7809** |

구성원에는 단독 성능이 가장 나쁜 모델(e7_ce_long80, 0.7088), Scratch 가 붕괴한
모델(e10_pad_s1, 0.6991), 그리고 **일부러 무의미한 값을 먹인 대조군**(e11_shuffle)도
그대로 들어 있다. **아무것도 고르지 않았다.**

### 구조 다양성은 아무것도 보태지 않았다

E11 의 `SizeAwareNet` 두 개는 입력 표현이 아니라 **구조**가 다른 첫 구성원이다.
크기 입력 재현이 맞는지 학습 때 보고값과 소수 4자리까지 대조해 확인했다(0.7398, 0.7328).

| 구성원 | 축 | leave-one-out 기여 |
|---|---|---:|
| e8_res96 | 표현 (resize96) | **+0.0044** |
| e10_pad_s2 | 표현 (pad64) | +0.0035 |
| e8_pad | 표현 (pad64) | +0.0022 |
| **e11_size** | **구조 (SizeAwareNet)** | **-0.0003** |
| **e11_shuffle** | **구조 (SizeAwareNet)** | **-0.0003** |
| e6_focal_long | 표현 (resize64) | -0.0041 |

두 구조 모델의 기여가 0 이다. 당연한 결과다 — 백본이 pad 모델들과 **동일한 ResNet-18** 이고
헤드만 다른데, E11 에서 크기 스칼라에 쓸 정보가 없다는 것이 확인됐으므로
오류 패턴이 달라질 이유가 없다. 진짜 구조 다양성은 백본 계열을 바꿔야 한다.

**leave-one-out 은 풀에 상대적인 값이다.** e8_pad 는 8개 풀에서 +0.0070,
10개 풀에서 +0.0022 다. 모델 자체의 속성이 아니라 "나머지가 무엇인가" 에 달려 있다.
같은 이유로 아래 표현 가짓수별 집계에서 1종 평균이 0.7420 -> 0.7491 로 오른 것도
실력이 아니라 pad64 구성원이 3개에서 5개로 늘어난 탓이다.

참고로 전부 none 으로 찍는 자명한 분류기의 accuracy 는 **0.9334** 다. accuracy 는 단독으로 읽으면 안 된다.

| Center | 832 | **0.702** | 0.698 |

**9개 중 8개에서 앙상블이 어떤 단독 모델보다도 낫다.** 유일한 예외 Near-full 은
0.942 대 0.944 로 95 장짜리 클래스에서의 무의미한 차이다. 그리고 "최고 단독" 은
클래스마다 다른 모델이라 한 모델로는 애초에 달성할 수 없는 값이다.

가장 희귀한 Near-full(95장)이 0.942 로 가장 높다. **병목은 희소성이 아니다.**
아래 [none 누출](#그-분산의-정체는-표현이-아니라-none-누출이다) 절에서 보듯,
병목은 none 110,701 장의 오차가 어느 결함 클래스로 배분되는지다.

### 앙상블이 통한 이유가 확인됐다

가설은 "모델마다 다른 none 누출 패턴이 평균에서 상쇄된다" 였다. 정확히 그렇다.

| none -> 이 클래스 | **all-8** | 개별 8개의 범위 |
|---|---:|---|
| Edge-Loc | **847** | 1,029 ~ 2,700 |
| Center | 184 | 115 ~ 419 |
| **Scratch** | **115** | 109 ~ **2,007** |
| Loc | **160** | 187 ~ 425 |
| Edge-Ring | 63 | 59 ~ 147 |
| 합계 | **1,385** | 1,861 ~ 5,037 |

**앙상블의 총 누출 1,385 는 8개 모델 어느 것보다도 적다.** 평균이 아니라 최소보다도 적다.
Edge-Loc, Loc 은 개별 최저치보다 낮고, Scratch 의 2,007 장 참사는 흔적도 없다.
그런데 recall 은 잃지 않았다 — 위 표에서 F1 이 전부 올랐다.
확률 평균이 한 모델의 특유한 오류 영역을 나머지의 확신으로 덮기 때문이다.

### 표현 다양성이 seed 다양성보다 낫다 (E14)

3개짜리 조합 **56가지 전부**를 구성 표현의 종류별로 집계했다. 사후 선택이 없다.

| 구성원의 표현 종류 | 조합 수 | macro-F1 평균 | 최고 | 구성원평균 대비 이득 |
|---|---:|---:|---:|---:|
| 1종 (같은 표현, seed 만 다름) | 5 | 0.7420 | 0.7564 | +0.0179 |
| 2종 | 39 | 0.7641 | 0.7773 | +0.0388 |
| **3종 (pad + resize64 + resize96)** | 12 | **0.7732** | 0.7782 | **+0.0459** |

단조롭게 오른다. **표현 3종 조합의 평균(0.7732)이 표현 1종 조합의 최고(0.7564)를 넘는다.**
같은 개수의 모델이라면 seed 를 바꾸는 것보다 입력 표현을 바꾸는 편이 낫다.

흥미로운 점은 `resize 96` 이다. 단독으로는 +0.005 로 잡음 안이라 "판정 보류" 였는데,
앙상블 구성원으로는 값어치가 있다. **단독 성능과 앙상블 기여는 다른 것이다.**

### 앙상블 크기 곡선

역시 모든 조합에 대해 계산했다.

| k | 조합 수 | 평균 | 최저 | 최고 |
|---:|---:|---:|---:|---:|
| 1 | 8 | 0.7256 | 0.6991 | 0.7485 |
| 2 | 28 | 0.7554 | 0.7263 | 0.7734 |
| 3 | 56 | 0.7641 | 0.7359 | 0.7782 |
| 4 | 70 | 0.7708 | 0.7401 | 0.7826 |
| 5 | 56 | 0.7733 | 0.7504 | 0.7832 |
| 6 | 28 | 0.7762 | **0.7637** | 0.7835 |
| 7 | 8 | 0.7771 | 0.7718 | 0.7812 |
| 8 | 1 | **0.7785** | | |

k=1 -> 2 에서 +0.030 으로 가장 크게 오르고 k=5~6 부터 평평해진다.
가장 중요한 줄은 **k=6 의 최저값 0.7637** 이다. 이것이 최고 단독 모델(0.7485)보다 높다.
즉 **6개 이상이면 어떤 조합을 골라도 최고의 단일 모델보다 낫다.**
선택 문제가 사라진다. 이것이 E13 에서 val 로 고르기를 포기한 뒤의 답이다.

대가는 추론 비용이다. 8개면 forward pass 가 8배다. k=4 (0.7708 평균)가
비용 대비 타협점으로 보인다.

## 무엇이 통했고 무엇이 통하지 않았는가

### 통한 것 (셋뿐이다)

| 기법 | 이득 | 근거 |
|---|---:|---|
| **dihedral 증강** | +0.101 | 웨이퍼의 회전 대칭성에 맞는 사전지식 |
| **수렴** (15 -> 40 epoch) | +0.055 | |
| **앙상블** | **+0.053** | 단일 모델 기대값 0.7256 -> all-8 0.7785. **선택이 필요 없다** |

증강과 수렴만이 seed 분산(범위 0.050)을 단일 실행 비교로 넘는다.
앙상블 +0.053 은 다른 종류의 증거다 — 단일 실행 간 비교가 아니라 **같은 체크포인트들을
재조합하는 짝지은 비교**라 학습 분산이 들어가지 않고, 56~70개 조합 전부에 대해
집계했으므로 사후 선택도 없다.

### 판정 보류 (측정 정밀도 부족)

seed 분산이 0.050 이라 아래 차이들은 단일 실행 비교로는 부호조차 확정할 수 없다.
이전 판(2026-08-22 이전)에서 "통한 것"으로 적었던 항목이 여기로 내려왔다.

| 기법 | 관측된 차이 | 상태 |
|---|---:|---|
| **pad 입력 표현** | 단일 실행 +0.022 | **3 seed 평균은 -0.003** (0.7261 vs resize focal 0.7295). 이득 없음 쪽으로 기운다 |
| **크기 명시 입력 (E11)** | -0.009 | 기준선을 못 넘음. 대조군(셔플)과도 0.007 차이라 구분 불가. [아래](#e11-크기-명시-입력-기각) |
| resize 96 | +0.005 | 단독으로는 잡음의 1/10. **단 앙상블 구성원으로는 기여한다** |
| focal vs CE (수렴 후) | +0.003 | 잡음의 1/17 |
| 80 epoch | -0.018 | 잡음의 1/3. 스케줄 길이 교란도 있다 |

### E11 크기 명시 입력 (기각)

`dieSize` 를 분류 헤드에 붙였다. 사전 등록한 기각 조건 둘 다에 걸렸다
([candidate/size_feature.md](../experiments/candidate/size_feature.md)).

| 태그 | 조건 | test macro-F1 |
|---|---|---:|
| e8_pad (기준선, 같은 seed, 같은 캐시) | pad 만 | **0.7485** |
| e11_size | pad + dieSize | 0.7398 |
| e11_shuffle | **대조군**, 크기 값 셔플 | 0.7328 |

크기를 명시적으로 줘도 기준선을 **0.009 밑돈다.** 대조군과의 차이도 0.007 뿐이라
관측된 것을 크기 "정보" 탓으로 돌릴 수 없다. 세 값의 최대 차이가 0.016 으로
잡음 폭 0.050 안이라, 정직하게는 **"이 설계로는 아무것도 구분되지 않았다"** 가 결론이다.
조건당 1 seed 였던 것이 설계 결함이다.

다만 `SizeAwareNet` 은 구조가 다른 모델이므로 체크포인트는 버리지 않는다.
지금까지 시험한 다양성 축은 입력 표현뿐이고 **구조 다양성은 아직 안 재봤다.**

### 통하지 않은 것

| 기법 | 결과 | 이유 |
|---|---:|---|
| 역빈도 class weight | 미수렴 시 +0.099, 수렴 후 무의미 | 극소수 클래스 가중치 106.7 로 gradient 분산 폭증 |
| focal loss | 수렴 후 CE 와 차이 0.0027 | 샘플 단위 조정이라 클래스 불균형을 직접 다루지 않음 |
| focal + alpha | -0.089 | 같은 축을 두 번 조작해 과잉 이동 |
| gradient clipping | -0.064 | 불안정이 성능의 주 원인이 아니었다 |
| 스칼라 logit adjustment | +0.0007 | 최적 tau 가 -0.05 로 0 근처. 표준 long-tail 과 방향이 반대 |
| 클래스별 오프셋 (val 튜닝) | -0.015 | val 이 학습 분포라 test 최적 경계와 반대로 밀린다 |
| 타겟 재가중 오프셋 | 미수렴 +0.015, 수렴 -0.039 | 경계가 잘못 놓인 모델만 도움 |
| **BN 통계 타겟 적응** | **-0.295** | covariate shift 용 기법인데 우리 이동은 label shift |

이 중 잡음보다 확실히 큰 실패는 focal+alpha(-0.089), grad clip(-0.064), 타겟 재가중 오프셋(-0.039),
BN 적응(-0.295) 넷이다. 나머지는 "이득이 없다"까지만 말할 수 있고 "해롭다"고는 말할 수 없다.

## seed 분산이 지금까지의 비교 대부분을 무효화한다

E10 은 E8(pad, 0.7485)을 seed 만 바꿔 두 번 반복했다. config diff 는 `seed: 0 -> 1/2` 와 tag 뿐이다.

| 설정 | seed 수 | 값 | 평균 | 범위 | 표준편차 |
|---|---:|---|---:|---:|---:|
| pad 64 | 3 | 0.7485 / 0.6991 / 0.7308 | 0.7261 | **0.0495** | 0.0251 |
| resize 64 focal | 2 | 0.7251 / 0.7340 | 0.7295 | 0.0089 | 0.0063 |

**기존 잡음 기준선 0.0089 는 n=2 에서 나온 과소추정이었다.** 실제 범위는 그 5.6배다.
결과적으로 이 문서가 기록한 차이 중 **+0.055(수렴)과 +0.101(증강)을 뺀 전부가 잡음 범위 안**이다.
앞으로 설정 비교는 **최소 3 seed** 로 하고, 단일 실행 최고치는 기록하되 결론의 근거로 쓰지 않는다.

### 분산은 고르게 퍼져 있지 않고 두 클래스에 몰려 있다

pad 3 seed 의 클래스별 F1 범위다.

| 클래스 | seed 0 | seed 1 | seed 2 | 범위 |
|---|---:|---:|---:|---:|
| **Scratch** | 0.613 | **0.280** | 0.608 | **0.334** |
| Near-full | 0.920 | 0.927 | **0.797** | 0.130 |
| Edge-Loc | 0.677 | 0.583 | 0.655 | 0.094 |
| 나머지 6개 | | | | ≤ 0.033 |

macro-F1 이 9개 클래스의 단순 평균이므로 Scratch 하나가 0.334 흔들리면 macro 가 0.037 흔들린다.
관측된 macro 범위 0.0495 의 3/4 이 이 한 클래스에서 나온다.

### 그 분산의 정체는 표현이 아니라 none 누출이다

Scratch 가 무너진 seed 1 에서 **recall 은 멀쩡했다.**

| | seed 0 | seed 1 | seed 2 |
|---|---:|---:|---:|
| Scratch recall | 0.683 | 0.649 | 0.538 |
| Scratch **precision** | 0.557 | **0.178** | 0.699 |
| none -> Scratch 오검출 | 292 | **2,007** | 115 |

Scratch 참값은 693 장인데 none 은 110,701 장이다. none 의 오분류 중 **1.8% 가 Scratch 로 향하면
그것만으로 참값의 3배**가 되어 precision 이 무너진다. 모델이 Scratch 를 못 배운 것이 아니라,
none 의 오차가 어느 클래스로 흘러가느냐가 seed 마다 다른 것이다.

### 같은 구조가 모든 병목 클래스에 적용된다

수렴한 6개 실행에서, none 이 새어 들어가는 양과 precision 이 정확히 대응한다.

| 클래스 | 참값 | none -> 이 클래스 (6개 실행 범위) | precision 범위 |
|---|---:|---:|---:|
| Near-full | 95 | **0** | 0.868 ~ 0.935 |
| Donut | 146 | 3 ~ 12 | 0.645 ~ 0.731 |
| Random | 257 | 6 ~ 18 | 0.744 ~ 0.796 |
| Edge-Ring | 1,126 | 59 ~ 147 | 0.779 ~ 0.866 |
| Center | 832 | 163 ~ 419 | 0.532 ~ 0.700 |
| Loc | 1,973 | 187 ~ 425 | 0.652 ~ 0.740 |
| Edge-Loc | 2,772 | 1,029 ~ 2,158 | **0.473 ~ 0.628** |
| Scratch | 693 | 109 ~ 2,007 | **0.178 ~ 0.699** |

recall 은 이미 대부분 0.54 ~ 0.78 로 고르다. **격차는 precision 쪽에 있고, precision 은
none 110,701 장의 2~5% 오차가 어디로 배분되는지가 결정한다.**

이것이 지금까지 실패한 기법들을 한 줄로 설명한다. class weight, focal, focal+alpha,
logit adjustment, per-class offset 은 전부 결정 경계를 **소수 클래스 쪽으로 미는** 같은 축을 조작한다.
그 방향은 none 누출을 **늘린다.** test 에서 필요한 방향은 반대다(test 는 train 보다 none 이 더 많다).
스칼라 logit adjustment 의 최적 tau 가 -0.05 로 음수였던 것이 이 방향과 일치한다.

## 이 프로젝트의 네 가지 교훈

**0. 잡음 기준선을 먼저, 그리고 충분한 표본으로 재라.** 이 프로젝트가 가장 크게 틀린 지점이다.
n=2 로 잰 0.0089 를 기준선으로 삼은 탓에 잡음인 차이를 8 사이클 동안 결론으로 기록했다.
기준선이 틀리면 그 뒤의 모든 비교가 틀린다. 기법을 하나 시험할 비용으로 seed 를 하나 더 도는 편이
거의 항상 낫다.


**1. 미수렴 상태에서 측정한 기법 이득은 수렴 후 살아남지 않는다.** 예외가 없었다.
focal, class weight, 사후 보정 전부 그랬다. 수렴을 먼저 확보하고 기법을 비교해야 한다.
순서를 뒤집으면 사라질 차이를 쫓게 된다.

**2. val 을 믿을 수 없다.** val 은 Training 분포(none 67.4%)를 물려받고 test 는 93.3% 다.
val 이 방향을 잘못 알려준 사례가 셋이다.

| 변경 | val | test |
|---|---:|---:|
| dihedral 증강 | +0.016 | +0.101 (과소평가) |
| class weight | -0.007 | +0.099 (부호 반대) |
| 80 epoch | +0.003 | -0.018 (부호 반대) |

**단 구분이 필요하다.** E9 에폭 곡선에서 val 이 고른 epoch 50 의 test 는 0.7129,
실제 최적 epoch 55 는 0.7191 로 차이가 0.0062 다. 잡음 기준선 안이다.
**한 실행 안에서 체크포인트를 고르는 데는 val 이 쓸 만하다.**

**E10 이 실패 범위를 넓혔다.** val 은 설정 간 비교뿐 아니라 **같은 설정의 seed 간 비교**에서도 실패한다.

| pad seed | best val macro-F1 | test macro-F1 |
|---:|---:|---:|
| 0 | 0.9361 | **0.7485** |
| 1 | **0.9401** | 0.6991 |
| 2 | 0.9357 | 0.7308 |

val 이 가장 높은 seed 1 이 test 가 가장 낮다. **val 로 seed 를 고르면 최악을 고른다.**
val 이 성립하는 범위는 이제 "한 실행 안에서 epoch 고르기" 하나로 좁혀졌다.

### val 을 고칠 수 있는가 — 아니다 (E13, 기각)

분포 차이가 원인으로 보였으니 val 표본에 `w[y] = q_test[y]/p_val[y]` 를 걸어
"test 분포에서의 macro-F1" 을 근사해봤다. 상세는
[candidate/selection_metric.md](../experiments/candidate/selection_metric.md).

캐시된 로짓만 쓰므로 학습 비용이 0 이다. 순위 상관(Spearman)으로 쟀다.

| 선택 지표 | 발견에 쓴 5 실행 | **held-out pad 3 seed** |
|---|---:|---:|
| 현행 val | +0.100 | -0.500 |
| 재가중, q 를 classify-and-count 로 추정 | +0.100 | |
| 재가중, q 를 **BBSE** 로 추정 | +0.100 | |
| 재가중, **결함률만** 무라벨 추정 | +0.600 | **-0.500** |
| 재가중, q 를 실제 test 분포로 (oracle) | +0.900 | |

**전부 기각했다.** BBSE 는 CC 를 전혀 개선하지 못했고(TV 0.0129 vs 0.0128),
결함률만 보정하는 사후 발견은 발견에 쓴 5개에서만 통하고 held-out 에서 무너졌다.

**실패 원인이 진단을 바꾼다. 문제는 val 의 분포가 아니라 표본이다.**
재가중은 val 이 이미 가진 답의 무게를 바꿀 뿐, 없는 정보를 만들지 못한다.

| none -> Scratch 오검출 | seed 0 | seed 1 | seed 2 |
|---|---:|---:|---:|
| val (none 7,581장 중) | 26 | **24** | 2 |
| test (none 110,701장 중) | 292 | **2,007** | 115 |

**test 에서 붕괴하는 seed 1 이 val 에서는 26 대 24 로 seed 0 과 구별되지 않는다.**
신호가 애초에 val 에 없다. 게다가 val 은 포화돼 있다 — 9개 클래스 F1 이 전부 0.84 이상,
대부분 0.95 이상이라 seed 간 차이를 잴 해상도가 없다. 결정적인 Scratch 가 92 장,
Near-full 이 9 장이다.

결론은 단순하다. **이 split 에서는 val 기반 설정 선택이 성립하지 않는다.**
따라서 (1) 고르지 않고 3 seed 의 평균과 범위를 보고하고, (2) 선택 대신 앙상블로 집계한다.
현재 최선이 앙상블인 것은 그래서다.

**3. 대조군 없이는 원인을 알 수 없다.** BN 적응이 이를 잘 보여준다.
test 로 재추정하면 -0.295, val 로 재추정하면 -0.016 이다. 대조군이 없었다면
"BN 적응은 안 통한다" 에서 멈췄을 것이다. 지금은 클래스 구성이 통계를 오염시킨다는
메커니즘을 알고, 따라서 클래스 구성이 유지되는 이동이라면 같은 기법이 유효할 수 있다는 것도 안다.

## 방법론 기준선

- **run-to-run 범위 0.050, 표준편차 0.025** (pad 3 seed). **이보다 작은 차이는 잡음이다.**
  설정 비교는 **최소 3 seed** 로 하고 평균과 범위를 함께 적는다.
  (이전 판의 0.0089 는 n=2 과소추정이었다.)
- 클래스별 수치는 훨씬 더 흔들린다. Scratch 범위 0.334, Near-full 0.130, Edge-Loc 0.094.
  **클래스별 F1 의 단일 실행 비교는 하지 않는다.**
- 같은 체크포인트에 결정 규칙만 바꾸는 짝지은 비교는 학습 분산이 없어 더 신뢰할 수 있다.

## 문헌 대비

9-class WM-811K 의 공개 수치는 macro-F1 0.84~0.93 대역이지만 **대부분 자체 랜덤 분할**이다.
우리 val 0.946 이 그 대역 안이고, 공식 split test 0.749 와의 격차 0.20 이 분포 이동의 크기다.
98% 이상 수치는 balanced 파생 벤치마크이거나 none 을 뺀 8-class 조건이라 비교 대상이 아니다.

## 진행 중

| 실험 | 질문 | 대조군 | 상태 |
|---|---|---|---|
| E10 | pad 의 0.7485 가 잡음인가 | seed 2개 추가 | **끝. 잡음이었다.** 앙상블 0.7564 로 새 최선 |
| E13 | val 을 재가중하면 고를 수 있는가 | held-out pad 3 seed | **끝. 기각.** 표본 문제라 재가중으로 안 된다 |
| E14 | 앙상블 이득이 표현 다양성에서 오는가 | 조합 56가지 전수 집계 | **끝. 지지됨.** all-8 로 0.7785 |
| E11 | 크기를 명시 입력으로 주면 나은가 | 크기 값 셔플 | **끝. 기각.** 기준선도 못 넘고 대조군과도 구분 안 됨 |
| E15 | 극좌표가 4번째 표현이 되는가 | 극좌표 포함/미포함 조합 전수 | 진행 중 (2 seed) |
| E12 | 미라벨 638,507장이 도움이 되는가 | 라벨만으로 사전학습 | 대기. **조건당 2 seed 로 재설계함** |

**E11, E12 는 설계를 고쳐야 한다.** 둘 다 단일 seed 로 설계돼 있는데, 기대 이득이
0.05 를 넘을 가능성은 낮다. 3 seed 로 늘리거나, 늘릴 여력이 없으면 결과를
"판정 보류"로 기록할 각오를 하고 돌려야 한다.

## 에폭 곡선 (E9, resize 64 기준)

5 epoch 마다 스냅샷을 남기고 전부 test 로 평가했다. 60 epoch cosine 스케줄이다.

| epoch | val macro-F1 | test macro-F1 | test accuracy |
|---:|---:|---:|---:|
| 5 | 0.8026 | 0.5400 | 0.8881 |
| 10 | 0.8738 | 0.6244 | 0.9194 |
| 15 | 0.9108 | 0.6520 | 0.9481 |
| 20 | 0.9223 | 0.6825 | 0.9573 |
| 25 | 0.9167 | 0.6620 | 0.9474 |
| 30 | 0.9299 | 0.6948 | 0.9410 |
| 35 | 0.9337 | 0.6732 | 0.9309 |
| 40 | 0.9289 | 0.7046 | 0.9546 |
| 45 | 0.9412 | 0.7146 | 0.9565 |
| 50 | 0.9498 | 0.7129 | 0.9547 |
| 55 | 0.9445 | 0.7191 | 0.9571 |
| 60 | 0.9437 | 0.7174 | 0.9565 |

val 최고는 epoch 50, test 최고는 epoch 55 이고 그 차이는 0.0062 로 잡음 안이다.
test 는 epoch 45 부근부터 평평해진다.

### 이 곡선이 앞선 결론을 정정한다

**"80 epoch 가 40 보다 나쁘다" 의 원인은 학습량이 아니라 스케줄이다.**
E7(40 epoch)과 E7b(80 epoch)는 cosine 길이가 달라 lr 궤적 자체가 다르다.
40-epoch 런은 40 에서 lr 이 0 으로 감쇠하지만 80-epoch 런은 그 시점에 아직 높다.

E9 가 이를 드러낸다. 60-epoch 런의 epoch 40 스냅샷은 0.7046 인데,
같은 40 epoch 를 스케줄 끝까지 돈 E7 은 0.7269 다. **차이는 lr 이 끝까지 감쇠했는지 여부다.**

스케줄 길이별로는 40 -> 0.7269, 60 -> 0.7191, 80 -> 0.7088 로 완만히 내려가지만
간격이 잡음 근처라 "길수록 나쁘다" 고 단정하기 어렵다.
확실한 것은 **cosine 을 끝까지 감쇠시키는 것이 중요하다** 는 것이다.

## 남은 후보

앙상블이 통했으므로 그 방향을 먼저 밀고, 그 다음이 경계 자체다.

1. **표현 다양성을 더 밀어본다.** E14 에서 표현 3종이 최선이었는데 우리가 가진 표현은
   pad64, resize64, resize96 셋뿐이다. 넷째, 다섯째 표현을 만들면 곡선이 더 올라갈 수 있다.
   후보: 극좌표 변환(웨이퍼는 원형이라 Edge-Ring, Center 에 자연스럽다),
   다운샘플 32, 결함 밀도 채널 추가. **각각 단독 성능이 나빠도 상관없다** —
   resize96 이 단독 +0.005 로 잡음 안이면서 앙상블에는 기여했다.
   대조군: 같은 개수의 기존 표현 앙상블.
2. **none-vs-결함 경계.** e8_pad 오류 4,267 장 중 **3,565 장(83.5%)이 none/결함 경계**에 있다
   (defect->none 1,704, none->defect 1,861). 결함끼리의 혼동은 702 장뿐이다.
   상한도 계산됐다 — none 오검출을 0 으로 만들면 macro 0.8052, recall 을 전부 1.0 으로
   만들면 0.8533, 2단계 계층 분류에서 stage-2 가 완벽하면 0.8519.
   **다만 2단계는 신중해야 한다.** stage-1 이 flat 의 암묵적 이진 경계보다 나을
   선험적 근거가 없고, stage-2 가 새로 고칠 수 있는 것은 702 장뿐인데
   flat 은 이미 그 구간에서 88.7% 를 맞힌다.
3. 웨이퍼 크기 버킷별 층화 평가와 크기 조건부 결정 규칙
4. 라벨 노이즈 검토 — none 중 실제로는 희미한 결함이 있는 것이 얼마나 되는지.
   1차 조사에서 전역 통계(불량 다이 비율, 공간 분포의 이심률)로는 누출 웨이퍼와
   정상 웨이퍼를 구분하지 못했다. 다만 none->Scratch 오검출은 확신도가 낮고
   (p 중앙값 0.755, 0.9 초과 27%) 진짜 Scratch 는 높아서(0.992, 75%),
   **확신 있는 라벨 오류가 아니라 경계 근처의 불확실성**으로 보인다. (부분 검증)
