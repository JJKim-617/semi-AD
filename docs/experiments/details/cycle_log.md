## 발견

### 1. val 이 방향을 두 번 잘못 알려줬다

E3 은 val 이 +0.016 오르는 동안 test 가 **+0.101** 올랐고, E4 는 val 이 **내려갔는데**(-0.007)
test 가 +0.099 올랐다. val 만 보고 판단했다면 증강 효과를 과소평가하고 class weight 는 폐기했을 것이다.

원인은 분할 간 분포 이동이다. val 은 Training 에서 떼어냈으므로 Training 분포(none 67.6%)를 물려받는데
test 는 none 93.3% 다. val 은 일반화 성능의 추정치가 아니라 학습 분포 내 성능일 뿐이다.

### 2. 증강과 class weight 는 대체로 같은 문제를 푼다

각각 단독으로 test macro-F1 을 0.53 에서 0.63 대로 올리는데, 둘을 합쳐도 0.6545 로 +0.02 만 더해진다.
합이 아니라 겹침에 가깝다. 두 기법 모두 다수 클래스 편향 완화라는 같은 축을 건드리기 때문으로 보인다.

다만 **작동 방식은 다르다.** 클래스별로 보면 서로 다른 클래스를 살린다.
- 증강(E3)은 **Edge-Ring 0.412 -> 0.930**, Random 0.599 -> 0.844 로 회전 대칭 패턴에 강하다.
  링과 랜덤 산포는 회전시켜도 같은 클래스라 dihedral 증강이 정확히 맞는 사전지식이다.
- class weight(E4)는 **Near-full 0.863 -> 0.989**, Donut 0.336 -> 0.514 로 극소수 클래스를 살린다.
  Near-full 은 test 95장, Donut 은 146장이다.

E4b 가 최고인 것은 두 이득을 부분적으로 함께 얻기 때문이다.

### 3. class weight 는 학습을 불안정하게 만든다

E4 는 ep4 에서 val macro-F1 0.287, accuracy 0.180 으로 붕괴했다 회복했고,
E4b 는 ep4 에서 0.161/0.143 까지 떨어지고 ep11~13 에서도 크게 요동쳤다.
역빈도 가중치가 Near-full(학습셋 기준 극소수)에 큰 가중치를 주면서 gradient 분산이 커진 것으로 보인다.
증강이 소수 클래스 샘플을 다양화하면 이 진동이 더 심해진다.

체크포인트를 val macro-F1 기준으로 고르고 있어 결과적으로는 안정적인 지점이 선택되지만,
가중치 상한(clipping)이나 focal loss 로 완화할 여지가 있다.

### 4. 남은 약점

Scratch(0.391), Loc(0.486), Center(0.523) 이 여전히 낮다.
특히 **Loc 은 어떤 기법으로도 개선되지 않았고 E1(0.571)보다 오히려 떨어졌다**.
Loc 은 "국소 결함"이라 위치와 형태가 일정하지 않아 회전 증강의 이득이 없고,
support 가 1,973장으로 적지 않아 class weight 이득도 없다. 별도 접근이 필요하다.

## 문헌 대비

공식 split + 불균형 유지 조건의 공개 수치는 macro-F1 0.7 수준이 확인된다
([Defect_KAN](https://github.com/judahobi/Defect_KAN) 0.703, 단 학습 시 공식 Test 행을 배제하지 않은 누수가 있어 낙관 편향).
현재 0.6545 는 그에 근접했으나 아직 아래다.

98~99% 대 수치는 balanced 파생 벤치마크이거나 결함 8클래스 조건이라 비교 대상이 아니다.
[인코더 선택 조사](../research/encoder_selection/README.md) 참조.

2. **Loc 개선** — 회전 증강과 class weight 모두 듣지 않는 유일한 클래스. 혼동 행렬로 어디로 잘못 가는지 확인 필요.

4. epoch 수를 늘려 수렴 여부 확인. 현재 15 epoch 에서 loss 가 계속 내려가는 중이다.

# 2차 사이클 — 손실 함수와 사후 보정 (2026-08-21)

## focal loss 가 class weight 를 대체한다

역빈도 class weight 를 빼고 focal(gamma=2)로 바꾸자 test macro-F1 이 0.6545 에서 0.6705 로 올랐다.
가설대로다. class weight 는 클래스 전체에 고정 배율을 걸어 극소수 클래스에 106.7(none 의 648배)이
붙고 batch 의 76.6% 에 그 클래스가 없어 gradient 가 스파이크로 들어왔다. focal 의 배율은
샘플별이고 (1-p)^gamma 로 유계라 같은 문제를 덜 파괴적으로 다룬다.

**둘을 겹치면 오히려 나쁘다.** focal + alpha 는 0.5810 으로 크게 떨어졌다.
증강과 class weight 가 겹쳤던 것과 같은 이유로, 경계를 소수 클래스 쪽으로 미는 축을
두 번 조작하면 과잉 이동이 된다.

**gradient clipping 도 도움이 안 됐다**(0.5903). 불안정이 성능의 주 원인이 아니었다는 뜻이다.

## 사후 보정 — 두 번 실패하고 세 번째에 성공

| 방법 | test macro-F1 | 판정 |
|---|---:|---|
| 스칼라 logit adjustment (Menon 식 9) | 0.6712 (+0.0007) | 무의미 |
| 클래스별 오프셋, val 에서 튜닝 | 0.6554 (-0.0150) | **해로움** |
| 클래스별 오프셋, **타겟 재가중 val** | **0.6851 (+0.0146)** | **성공** |
| (참고) oracle, test 로 직접 튜닝 | 0.6974 (+0.0269) | 상한 |

**스칼라 tau 가 무의미한 이유.** 최적 tau 가 -0.05 로 0 근처였다. 표준 long-tail 연구는
test 가 균형잡혀 있다고 보고 tau > 0 으로 경계를 희소 클래스 쪽으로 미는데,
우리 test 는 none 93.3% 로 train(67.4%)보다 **더** 쏠려 있어 방향이 반대다.
게다가 오프셋을 log(prior) 방향 한 축으로만 움직여 자유도가 부족하다.

**val 튜닝이 해로운 이유.** 이론적 설명이 있다. test 의 93.3% 가 none 이므로
none 에서 오탐률이 0.3% 만 생겨도 결함 클래스의 precision 이 무너진다.
따라서 test 에서 macro-F1 을 최대화하는 결정 규칙은 val 에서보다 결함 예측에
**더 보수적**이어야 하는데, val(none 67.4%)에서 튜닝하면 정반대로 밀린다.
E3 의 Edge-Ring recall 0.930 / precision 0.250 이 이 현상의 실물이다.

**재가중이 통한 이유.** val 표본에 w_y = q_target(y) / p_val(y) 를 곱하면
val 라벨만으로 "타겟 분포에서의 macro-F1" 을 근사하게 된다.
타겟 사전확률은 모델이 라벨 없는 test 에 매긴 예측 빈도(classify-and-count)로 추정했고,
none 0.928 추정 대 0.933 실제로 오차 0.005 였다. **test 라벨은 최종 평가에만 썼다.**

이 경로의 남은 여지는 0.6851 대 oracle 0.6974 로 0.012 다.

## 다음 — 수렴이 더 큰 지렛대다

문헌 조사 결과, 9-class WM-811K 에서 불균형 기법을 의도적으로 쓰지 않은 논문이
macro-F1 0.9098 을, ResNet-18 이 0.895 를 보고한다. 다만 **대부분 자체 랜덤 분할**이라
우리 공식 split 수치와 직접 비교할 수 없다. 실제로 우리 val 은 0.8922 로 그 대역 안이다.

직접 비교 가능한 부분은 학습량이다. 우리 2,520 step 은 레퍼런스 구현의 약 15% 이고
15 epoch 에서 loss 가 계속 내려가는 중이었다. **미수렴 상태의 기법 비교는 잠정적이다.**
E6(focal 40 epoch, cosine, seed 2개), E7(plain CE 40/80 epoch)을 실행 중이다.

또한 문헌의 병목 클래스가 Edge-Loc(5,189장), Loc(3,593장), Scratch(1,193장)로
**희귀 클래스가 아니라 중간 빈도**라는 점이 우리 관측(Loc, Scratch 최저)과 일치한다.
이는 병목이 불균형이 아니라 클래스 간 의미적 혼동일 가능성을 시사하며,
그렇다면 재가중 계열로는 한계가 있다.

# 3차 사이클 — 수렴 (2026-08-21)

## 40 epoch 이 지금까지의 모든 기법을 합친 것보다 컸다

E5 와 동일한 구성(focal gamma=2, dihedral 증강)에서 epoch 만 15 에서 40 으로 늘리고
cosine 스케줄과 warmup 3 을 붙였다.

| | val macro-F1 | test macro-F1 | test accuracy |
|---|---:|---:|---:|
| E5 (15 epoch, 고정 lr) | 0.8922 | 0.6705 | 0.9555 |
| **E6 (40 epoch, cosine)** | **0.9452** | **0.7251** | 0.9589 |

**+0.0546.** 비교하자면 증강이 +0.101, class weight 가 +0.099, focal 이 +0.016,
재가중 오프셋이 +0.015 였다. 손실 설계를 바꾸는 것보다 충분히 학습시키는 것이 컸다.

**40 epoch 는 거의 수렴점**이다. 80 epoch(E7b)로 남은 여지를 확인 중이다.

### 함의

1차, 2차 사이클의 기법 비교는 전부 **미수렴 상태에서 이뤄졌으므로 잠정적이다.**
특히 "증강과 class weight 가 겹친다", "focal 이 class weight 를 대체한다" 같은 결론은
수렴 후 재검증이 필요하다. 진행 중인 E7(plain CE 40/80 epoch)이 그 대조군이다.

한편 val 0.9452 는 문헌이 보고하는 대역(0.84~0.93) 안이다. test 0.7251 과의 격차 0.22 는
여전히 분포 이동에서 온다. 이 격차는 학습으로 좁혀지지 않는 부분이다.


## run-to-run 분산 — 실험 해석의 기준선

같은 설정을 seed 만 바꿔 두 번 돌렸다.

| seed | val macro-F1 | test macro-F1 | test accuracy |
|---|---:|---:|---:|
| 0 | 0.9452 | 0.7251 | 0.9589 |
| 1 | 0.9451 | 0.7340 | 0.9629 |
| 차이 | 0.0001 | **+0.0089** | +0.0040 |

**val 은 사실상 동일한데 test 는 0.0089 벌어진다.**
학습을 다시 돌려서 비교하는 경우 이 정도 차이는 잡음이다.

이 기준으로 앞선 결론들을 다시 보면,

- E5 focal(0.6705) 대 E4b(0.6545)의 +0.016 은 잡음 경계에 가깝다. focal 이 낫다는 결론은 약하다.
- 반면 **재가중 오프셋의 +0.0146 은 성격이 다르다.** 같은 체크포인트에 결정 규칙만 바꾼
  짝지은 비교라 학습 분산이 개입하지 않는다. 이쪽은 유효하다.

**앞으로 설정 비교는 최소 2 seed 로 하고, 단일 실행 차이로 결론짓지 않는다.**


## focal 은 수렴 후에는 값어치가 없다

동일 조건에서 손실만 바꿔 비교했다.

| 구성 | test macro-F1 |
|---|---:|
| E6 focal (seed 0) | 0.7251 |
| E6 focal (seed 1) | 0.7340 |
| focal 평균 | **0.7295** |
| E7 plain CE | **0.7269** |
| 차이 | -0.0026 |

**차이 0.0026 는 잡음 기준선 0.0089 의 3분의 1 이하다. 구분되지 않는다.**

### 이것이 앞선 사이클 전체에 대한 판정이다

1차, 2차 사이클에서 class weight, focal, alpha, gradient clipping 으로 손실을 조정하며
얻은 차이들은 미수렴 모델 위에서 측정된 것이었다. 충분히 학습시키자 그 차이가 사라졌다.

문헌이 경고한 바와 일치한다. focal 은 샘플 단위 난이도를 조정할 뿐 클래스 단위 불균형을
직접 다루지 않으며, long-tailed 벤치마크에서도 baseline 대비 효과가 없거나 음수로 보고된다.

**실용적 결론: plain CE 를 쓴다.** 성능이 같은데 하이퍼파라미터(gamma)가 하나 줄어든다.

| Edge-Ring | 1,126 | 0.764 | 0.788 | 0.778 |

| Random | 257 | 0.745 | 0.741 | 0.707 |
| Scratch | 693 | 0.605 | 0.634 | 0.606 |
| Near-full | 95 | 0.944 | 0.929 | 0.939 |

소수 클래스의 seed 간 변동(Edge-Loc ±0.049, Scratch ±0.029)이 손실 함수 간 차이보다 크다.
클래스별 수치로 결론을 내리려면 seed 를 더 늘려야 한다.

## 남은 병목

수렴, 증강, 손실 설계, 사후 보정을 모두 시도한 뒤 test macro-F1 은 0.73 근처다.
val 0.946 과의 격차 0.21 은 전부 분포 이동에서 온다. 이 격차는 학습으로 좁혀지지 않았다.

다음 후보는 학습이나 손실이 아니라 **입력과 표현** 쪽이다.
- 64x64 리사이즈로 인한 정보 손실. 진단에서 Scratch 가 train median 52x52 대 test 31x31 로
  같은 클래스가 픽셀 수준에서 다른 그림이 된다는 것이 확인됐다. `mode: pad` 캐시 비교가 남아 있다.
- 웨이퍼 크기를 명시 변수로 다루기. 크기 버킷별 층화 평가와 크기 조건부 결정 규칙.
- 미라벨 638,507장을 이용한 자기지도 사전학습.


## 수렴을 넘어선 학습은 해롭다

epoch 만 40 에서 80 으로 늘렸다.

| | val macro-F1 | test macro-F1 | test accuracy |
|---|---:|---:|---:|
| E7 (40 epoch) | 0.9462 | **0.7269** | 0.9570 |
| E7b (80 epoch) | **0.9491** | 0.7088 | 0.9467 |
| 변화 | +0.0029 | **-0.0181** | -0.0104 |

**val 은 오르는데 test 는 0.0181 떨어진다.** 잡음 기준선 0.0089 의 2배다.
학습 분포에 과적합된 것이며, 분포 이동이 있는 상황에서 수렴 이후의 학습은 손해다.

### val 이 방향을 잘못 알려준 세 번째 사례

| 변경 | val 변화 | test 변화 | 판정 |
|---|---:|---:|---|
| E3 dihedral 증강 | +0.016 | +0.101 | 과소평가 |
| E4 역빈도 class weight | -0.007 | +0.099 | 부호 반대 |
| E7b 80 epoch | +0.003 | -0.018 | 부호 반대 |

val 은 Training 분포(none 67.4%)를 물려받고 test 는 none 93.3% 다. 이 격차 때문에
val 은 **기법 선택뿐 아니라 학습 중단 시점 결정에도 쓸 수 없다.**

40 epoch 가 80 보다 나은 것은 확인됐지만, 40 이 최적이라는 근거는 없다. 더 이른 지점이
더 나을 수 있다. 현재 파이프라인은 val macro-F1 최고 시점의 체크포인트 하나만 저장하므로
소급 검증이 불가능하다. **에폭별 체크포인트를 남기도록 바꿔야 한다.**

이것은 실무적으로 곤란한 상황이다. 라벨 없는 test 로는 중단 시점을 고를 수 없고,
val 은 방향을 잘못 알려준다. 타겟 재가중을 학습 중 검증에도 적용하는 것이 후보다
(현재는 사후 오프셋 튜닝에만 쓰고 있다).

### 예측한 메커니즘과 실제가 다르다

진단은 Scratch 가 train median 52x52, test 31x31 로 크기가 갈리니 pad 가 Scratch 를

seed 분산 범위일 수 있다.

# 6차 사이클 — 테스트 시점 적응 (2026-08-22)

하이퍼파라미터 조정을 멈추고 접근을 바꿨다. 남은 격차가 전부 분포 이동이므로,
**모델에 타겟 분포를 보여주는** 방향이다. 첫 시도는 BatchNorm 통계 재추정이다.
가중치는 그대로 두고 라벨 없는 데이터로 running mean, var 만 다시 잰다.

## 결과 — 파국적 실패

기준선은 E8(pad, BN 층 20개).

| 조건 | test macro-F1 | test accuracy | 변화 |
|---|---:|---:|---:|
| 기준선 | 0.7485 | 0.9640 | — |
| **BN <- test** | **0.4532** | 0.7868 | **-0.2953** |
| BN <- val (대조군) | 0.7323 | 0.9601 | -0.0162 |
| BN <- test (momentum 0.05) | 0.4262 | 0.7402 | -0.3223 |

## 대조군이 원인을 짚어냈다

val 로 재추정하면 0.0162 손해인데
test 로 하면 0.2953 손해다. 차이가 크다.

두 집합의 차이는 클래스 구성이다. val 은 none 67.4% 로 학습과 같고 test 는 93.3% 다.

**BN 통계 재추정은 covariate shift 를 겨냥한 기법인데 우리 이동은 주로 label shift 다.**
test 의 93.3% 가 none 이므로 그것으로 통계를 다시 재면 모든 층의 정규화가
"정상 웨이퍼" 의 통계로 끌려간다. 결함 특징이 잘못 정규화되면서 표현이 무너진다.
momentum 을 낮춰 일부만 섞어도 방향은 같다.

기각 조건을 실험 전에 적어둔 것이 값을 했다. 대조군 없이 test 결과만 봤다면
"BN 적응은 이 문제에 안 통한다" 에서 멈췄을 것이다. 지금은 **왜 안 통하는지,
어떤 조건이면 통할지**까지 안다. 클래스 구성이 유지된 채 입력 특성만 변하는 이동이라면
같은 기법이 유효할 수 있다.

## 함의

타겟 분포를 그대로 모델에 먹이는 접근은 label shift 상황에서 위험하다.
다음 시도는 클래스 구성에 오염되지 않는 방향이어야 한다.
- 웨이퍼 크기를 명시 입력으로 주기(진단이 지목한 원인을 모델이 추론하게 두지 않는다)
- 미라벨 638,507장 자기지도 사전학습(라벨 구성과 무관한 표현 학습)


## 해상도가 아니라 상대적 스케일이 이득의 원인이다

pad 가 이긴 것이 "정보 손실이 줄어서" 인지 "크기 신호가 생겨서" 인지 가르기 위해
해상도만 올린 조건을 함께 봤다.

| 표현 | test macro-F1 | test accuracy | vs resize 64 |
|---|---:|---:|---:|
| resize 64 (E7) | 0.7269 | 0.9570 | — |
| resize 96 (E8b) | 0.7320 | 0.9592 | +0.0051 |
| **pad 64 (E8)** | **0.7485** | **0.9640** | **+0.0216** |

**해상도를 1.5배 올린 이득 +0.0051 는 잡음 기준선 0.0089 안이다.**
반면 pad 는 +0.0216 로 그 2.4배다.

resize 96 은 픽셀 수가 2.25배지만 여전히 모든 웨이퍼를 프레임에 꽉 채운다.
즉 정보량은 늘었어도 **크기 신호는 없다.** 이 대조가 두 설명을 갈라 준다.
이득의 원인은 해상도가 아니라 웨이퍼가 캔버스에서 차지하는 상대적 비율이다.

이것이 E11(웨이퍼 크기를 명시 입력으로)의 직접적 근거다. pad 는 그 신호를 암묵적으로
전달하는데, 명시적으로 주면 더 나은지 확인한다.

# 7차 사이클 — 에폭 곡선 (E9, 2026-08-22)

60-epoch cosine 스케줄로 5 epoch 마다 스냅샷을 남기고 전부 test 로 평가했다.

| epoch | val macro-F1 | test macro-F1 |
|---:|---:|---:|
| 40 | 0.9289 | 0.7046 |
| 50 | **0.9498** (val 최고) | 0.7129 |
| 55 | 0.9445 | **0.7191** (test 최고) |

## 두 가지를 정정했다

60-epoch 런의 epoch 40 스냅샷은 0.7046 인데, 같은 40 epoch 를 스케줄 끝까지 돈 E7 은 0.7269 다.
차이는 **cosine 이 끝까지 감쇠했는지 여부**다. lr 궤적이 다른 것을 학습량 차이로 읽고 있었다.

# 9차 사이클 — val 을 고칠 수 있는가 (E13, 2026-08-22)

val 을 test 사전확률로 재가중하면 설정을 고를 수 있을 것으로 봤다.
순위 상관(Spearman)으로 쟀다.

| 선택 지표 | 발견에 쓴 5 실행 | **held-out pad 3 seed** |
|---|---:|---:|
| 현행 val | +0.100 | -0.500 |
| 재가중, CC 추정 | +0.100 | |
| 재가중, **BBSE** 추정 | +0.100 | |
| 재가중, **결함률만** 추정 | +0.600 | **-0.500** |
| 재가중, 실제 test 분포 (oracle) | **+0.900** | |

oracle 로는 거의 완벽해지므로 메커니즘은 맞다. 그러나 BBSE 는 CC 를 전혀 개선하지 못했고
(TV 0.0129 대 0.0128), 사후에 찾은 "결함률만 보정" 은 발견에 쓴 5개에서만 통하고
held-out 에서 무너졌다. **둘 다 기각.**

## 실패가 진단을 바꿨다

문제는 val 의 **분포**가 아니라 **표본**이다.

| none -> Scratch 오검출 | seed 0 | seed 1 | seed 2 |
|---|---:|---:|---:|
| val (none 7,581장 중) | 26 | **24** | 2 |
| test (none 110,701장 중) | 292 | **2,007** | 115 |

**test 에서 붕괴하는 seed 가 val 에서는 26 대 24 로 구별되지 않는다.**
신호가 애초에 없으니 재가중으로 만들 수 없다. val 은 Scratch 92 장, Near-full 9 장이고
9개 클래스 F1 이 전부 0.84 이상이라 포화돼 있다.

**결론: 고르지 말고 3 seed 평균과 범위를 보고한다. 선택 대신 집계한다.**

# 13차 사이클 — 극좌표 (E15, E15b, 2026-08-22)

웨이퍼는 원형이고 결함 절반이 반지름으로 정의되니 극좌표가 맞을 것으로 봤다.
캐시에서 Edge-Ring 은 62/64 행에, Center 는 0 행에 몰리는 것도 확인했다.

## 1차 시도는 내 설계 결함으로 폐기했다

첫 실행이 **0.5206** 이 나왔다. 원인은 극좌표가 아니라 증강이었다 —
`--augment` 가 dihedral 을 걸었는데 극좌표에서 `rot90` 은 **반지름 축과 각도 축을 맞바꾼다.**

## 정정 후에도 실패했고, 이번엔 이유가 달랐다

| | test macro-F1 |
|---|---:|
| e15b_polar_s0 | 0.5333 |
| e15b_polar_s1 | 0.5337 |

**범위가 0.0004 다.** pad 가 0.0495 였으니 이건 잡음이 아니라 계통적 실패다.
none 110,701 장 중 **27,038 장(24.4%)** 을 결함이라 부른다.

원인은 **웨이퍼 크기**다. 극좌표는 반지름으로 정규화하므로 원본 다이 하나가 극좌표에서
몇 셀을 덮는지가 크기로 정해진다 — **크기가 표현에 새겨진다.**

| dieSize | train 비중 | 극좌표 오검출률 | pad 오검출률 |
|---|---:|---:|---:|

학습 데이터가 몰린 구간에서는 멀쩡하고 희박한 구간에서 무너진다. pad 는 전 구간 평평하다.

첫 가설("작은 웨이퍼가 흐려진다")은 틀렸다 — 실패가 크기에 단조롭지 않고 **학습 커버리지**를 따라간다.

# 14차 사이클 — 자기지도와 두 개의 정정 (E12, 2026-08-22)

마스킹 다이 복원으로 인코더를 사전학습했다. 설정은 tag 외에 동일하고 **데이터만 다르다.**

| 조건 | n | 평균 | seed 범위 |
|---|---:|---:|---:|
| 무작위 초기화 (기준선) | 3 | **0.7261** | 0.0495 |
| SSL 172K 라벨만 (대조군) | 2 | 0.7079 | 0.0062 |
| SSL 811K 미라벨 포함 | 2 | 0.6887 | 0.0025 |

**미라벨 638K 는 확실히 해롭다** — ssl_all 최고(0.6899)가 ssl_lab 최저(0.7049)보다 낮아
두 조건이 겹치지 않는다. 반면 ssl_lab 은 기준선 범위 안이라 **판정 불가**다.
따라서 "사전학습 절차가 해롭다" 가 아니라 **"손해가 미라벨 데이터에 특정된다"** 가 결론이다.

용량-반응이 뒷받침한다. 사전학습 데이터가 늘수록 모든 효과가 단조롭게 커진다.

| | 기준선 | 172K | 811K |
|---|---:|---:|---:|
| none 누출 | 2,962 | 4,249 | 6,800 |
| Loc F1 | 0.649 | 0.477 | 0.426 |
| **Scratch F1** | **0.500** | 0.561 | **0.602** |
| seed 범위 | 0.0495 | 0.0062 | **0.0025** |

교란을 밝힌다: epoch 은 같지만 gradient 업데이트가 4.7배 다르다.
**데이터도 연산도 많은 쪽이 더 나빠서 결론에 위협이 없다.**
ssl_all 은 pretext loss 0.0752 로 ssl_lab(0.0859)보다 잘 배웠는데 전이는 더 못했다.

LOO -0.010 으로 미채택. 다만 **SSL 은 Scratch 붕괴 모드를 없앤다**(seed 범위 20배 감소).
그 안정화만 떼어올 수 있는지는 안 해봤다.

## 이 사이클에서 두 결론이 뒤집혔다 — 둘 다 범위 제한 착시

구성원이 8개(0.699~0.749)에서 13개(0.533~0.749)로 넓어지자 드러났다.

**1. "단독 성능과 앙상블 기여는 별개다" 가 틀렸다.** n=13 에서 r=**+0.942** 다.
이전 관측은 모두가 0.05 폭 안에 있던 풀에서 나왔고, 그 띠 안에서는 지금도 참이다
(유일한 resize96 이 1위, 중복된 resize64 둘이 꼴찌). **띠 밖에서는 품질이 지배한다.**
단독 성능과 누출량은 얽혀 있어 어느 쪽이 원인인지는 이 데이터로 못 가린다.

**2. "val 은 못 쓴다" 가 과했다.**

| val 대 test 상관 | r | n |
|---|---:|---:|
| 전체 | **+0.779** | 13 |
| 극좌표 제외 | +0.070 | 12 |
| 극좌표+SSL 제외 | **-0.319** | 10 |

양의 상관 전부가 이상치 하나에서 온다. **val 은 품질을 재지 못하고 파국을 감지한다.**
val 최하위 4개에 test 1위인 e8_pad 가 들어 있다.

## 그리고 "고르지 않아도 된다" 에 전제가 붙었다

망가진 5개를 넣자 앙상블이 **0.7809 -> 0.7769 로 내려갔다.**
"전부 넣기" 는 후보 품질이 비슷할 때만 성립한다. val 로는 그것들을 걸러낼 수 없다.

**같은 실수를 두 번 했다: 좁은 표본의 결론을 넓은 범위로 옮긴 것.**
잡음 기준선도 n=2 에서 5.6배 과소추정했다. 둘 다 표본을 넓히자 뒤집혔다.

## E18 백본 계열 교체 — 구현 완료, 대기 중

E11 의 `SizeAwareNet` 이 leave-one-out -0.0003 이었던 이유가 **백본이 같아서**였으므로
이번엔 계열 자체를 바꾼다. `src/a19_backbones.py` (30개 시험).

| 백본 | 계열 | 파라미터 | feature map |
|---|---|---:|---|
| resnet18 (기준) | residual | 11.2M | 8x8 |
| shufflenet_v2 | 채널 셔플 | 1.3M | 8x8 |
| mobilenet_v3 | inverted residual + SE | 4.2M | 4x4 |
| convnext_tiny | 대형 커널 depthwise | 27.8M | 8x8 |
| efficientnet_b0 | compound scaling + SE | 4.0M | 4x4 |

전부 stem 을 고쳐 64x64 붕괴를 막았다. `build_model` 에 `backbone` 인자를 추가하고
a4(평가), a6(로짓 캐시)까지 열어 체크포인트를 되읽을 수 있게 했다.
**기본값은 resnet18 로 두었다** — 기존 13개 체크포인트와 호출부 여섯 곳이 그것을 전제한다.

## E19 EMA — 구현 완료, 대기 중

`src/a20_ema.py` (12개 시험). 이 프로젝트에서 통한 것이 전부 평균내기 계열이다 —
앙상블은 여러 **실행**, TTA 는 여러 **변환**, EMA 는 한 실행의 여러 **시점**.
배치마다 갱신하고 원본과 EMA 가중치를 둘 다 저장해 **같은 실행 안에서 짝지어** 비교한다.

## 시험이 잡은 것 두 개

**1. 백본별 입력 의존성 시험이 처음에 틀렸다.** 학습 전 eval 모드에서 MobileNetV3 와
EfficientNet 이 서로 다른 입력에 **정확히 같은 출력**을 냈다(maxdiff 0.000e+00).
BN running stats 가 초기값(mean 0, var 1)이라 Hardswish 와 SE 게이트가 포화한 것이고,
학습하면 사라진다. train 모드에서는 다섯 백본 모두 1.6e-2 ~ 1.1e-1 로 반응한다.
**실제로 일어나지 않는 상태를 검사하고 있었다.**

**2. EMA 의 device 버그를 스모크 테스트가 잡았다.** a3 는 CPU 에서 모델을 만들고
학습 루프 첫 스텝에서 `.to(device)` 하는데, 그 사이에 만들어진 EMA 는 shadow 가 CPU 에 남아
첫 update 에서 터졌다. 단위 시험은 전부 CPU 라 통과했다 —
**1 에폭 스모크 테스트가 아니었으면 3시간짜리 큐가 첫 배치에서 죽었을 것이다.**
EMA 시험에 CUDA 이동 경로를 추가했다.

## E18 백본 계열 — 기각 (구조 다양성은 표현 다양성의 1/5)

단독 성능은 갈리지 않았다 — shufflenet 0.7291, mobilenet 0.7256, efficientnet 0.7178 로

판정은 다양성 집계였고 **첫 집계가 교란돼 있었다.** 전체 풀로 재면
구조 1종 0.7725 > 2종 0.7720 > 3종 0.7683 으로 다양성이 해로워 보였는데,
1종 그룹에 translate 4개(전부 resnet18, 단독 0.76대로 가장 강함)가 몰려 있었다.
**다양성이 아니라 품질을 재고 있었다.**

1종 0.7629, 2종 0.7695(+0.0066), 3종 0.7685(+0.0056)로 **양수지만 약하다.**

구조 축은 표현 축의 약 1/5 이고 2종에서 3종으로 갈 때 오히려 미세하게 준다.

(mobilenet_s0 +0.0072, efficientnet_s0 -0.0056). **백본 계열이 기여를 정하지 않는다.**

`convnext_tiny` 2 seed 는 아직 학습 중이라 이 판정은 백본 3종 기준이다.

## 진단 1 — 해상도 축은 닫혀 있다

`src/diag_native_resolution.py`. 상세 [research/input_resolution/](../../research/input_resolution/README.md).

| | 값 |
|---|---:|
| test 원본 H, W 중앙값 | **34 x 34** |
| **64 를 넘는 웨이퍼** | **325장 (0.3%)** |
| **96 을 넘는 웨이퍼** | **0장** |

`pad_center` 는 원본이 목표보다 클 때만 줄인다. 그러므로 **test 의 0.3% 만이 해상도로
정보를 잃는다.** 병목인 Edge-Loc 은 0.1%(4장), Scratch 는 1.0%(7장)다.
7장으로 F1 0.710 을 설명할 수 없다.

**정정 하나.** 처음에 test 만 세고 "96 초과 0장" 이라고 적었는데, train 은 다르다 —
중앙값 27x27, 최대 212x204 로 5.78% 가 64 를, 1.92% 가 96 을 넘는다.
그래도 **test 에서 쓸 수 있는 추가 정보는 0** 이라 결론은 유지된다.
덤으로 **분할 간 크기 이동이 하나 더 드러났다**(train 27x27 대 test 34x34).

**딸린 정정: `resize 96` 이 앙상블에 기여한 것(LOO +0.0044)은 정보량 때문이 아니다.**
96 을 넘는 test 웨이퍼가 0장이라 전부 확대만 된다. pad64/resize64/resize96 이
담은 정보는 사실상 같고, 다른 것은 **웨이퍼가 conv 수용영역 대비 몇 배로 놓이는가**
(1.0x / 1.9x / 2.8x)뿐이다. **표현 다양성은 척도 다양성이었다.**
"표현 다양성이 통한다" 는 결론은 그대로 유지되고 메커니즘만 좁혀진다.

| **F1 평균 대 F1 범위** | -0.267 | **+0.091** |

**성능은 `none -> 결함` 누출의 수준이 정하고, seed 분산은 누출의 퍼짐이 정한다.

자기지도, 추가 증강, EMA 가 한 일은 **누출의 목적지를 seed 마다 일정하게 만든 것**이고
총량을 줄인 것이 아니다. 총량을 줄인 것은 translate 하나다(2,962 -> 1,190).

**앞으로 "분산이 줄었으니 평균도 오를 것" 이라는 기대로 자원을 쓰지 않는다. 상관이 0 이다.**
다만 **왜 translate 만 총량을 줄이는지는 여전히 모른다.** 그건 설명 없는 관측으로 남긴다.

## 정정 — 위 "같은 편" 은 선택 효과였다 (`src/diag_signal_headroom.py`)

`FP 대 TN` 은 **모델의 예측으로 조건을 건** 비교다. 예측은 모델 점수의 함수이고
모델 점수는 밀도와 상관이 있으니, "모델이 결함이라 부른 것" 을 고르는 순간
이미 밀도가 높은 쪽을 고른 것이다. 증거는 표 안에 있었다 —
같은 비교에서 **모델 자신의 점수가 0.9999 / 0.0008** 이 나온다. 정의상 그럴 수밖에 없다.
**신호가 아니라 선택을 재고 있었다.**

같은 예측을 받은 것끼리 비교하면 방향이 반대다.

| 신호 | FP 대 TP | FN 대 TN | (층화 후) FP 대 TP | (층화 후) FN 대 TN |
|---|---:|---:|---:|---:|
| 모델 자신 점수 | 0.1197 | 0.9138 | — | — |
| 국소 밀도 k=5 | **0.3143** | **0.8416** | 0.4962 | **0.8230** |
| 선 L=11 온전창 | **0.2338** | **0.8566** | **0.3843** | **0.8488** |
| lot 문맥 | 0.4632 | 0.5884 | 0.5213 | 0.4268 |

**밀도와 선 필터는 쓸모 있는 방향이다.** 모델 확신도 10분위로 층화한 뒤에도
**놓친 결함 방향에 0.82~0.85 가 남는다.** lot 문맥만 층화하면 전부 사라진다.

**그런데 결정 규칙에 넣으면 아무것도 안 오른다.** `rank(모델) + w*rank(보조)` 의
w 와 임계값을 test 라벨로 직접 최적화해도 **세 신호 모두 최적 w = 0** 이다
(0.7922 대 flat 0.7931). 불균형 때문이다 — 되살릴 놓친 결함이 1,529장인데
그 옆의 맞힌 none 이 109,644장이라 어떤 임계값도 되살리는 것보다 더 망친다.

**정확한 결론: 정보는 있고 스칼라 규칙으로는 못 쓴다.**
15차의 "결정 규칙 축이 닫혔다" 가 더 강해졌다 — 모델 로짓뿐 아니라
**새 신호를 가져와 섞어도** 닫혀 있다. 그리고 이것은 **채널 경로를 반박하지 않는다.**
조건부 정보가 0.82 나 남아 있다는 것은 그 정보가 어딘가 있다는 뜻이고
스칼라가 못 꺼낼 뿐이다. E20 첫 seed 가 대조군을 넘은 것과 모순되지 않는다.

**셔플은 단독도 누출도 대조군 범위 안이다** — 채널을 붙이는 것 자체로는 아무 일도 없다.
밀도는 범위 밖이다. **차이 +0.0101 은 밀도 seed 범위(0.0015)의 7배다. 정보 때문이다.**
E11(크기 명시 입력)은 셔플과 0.007 차이라 못 갈랐는데 **이번엔 갈렸다.**

사전 등록한 채택 조건 "LOO >= +0.005 **이고** 셔플보다 높을 것" 에서
**뒷 조건은 만족하고 앞 조건이 안 된다.** 기각이지만 뜻은
"밀도 정보가 쓸모없다" 가 아니라 **"앙상블이 흡수한다"** 다.

**셔플도 다양성을 못 만든다** — 밀도와의 오류 상관 0.8608 로 밀도끼리(0.8622)와 같다.
**정보를 담든 안 담든 결정론적 채널을 붙이면 구성원이 서로 닮아진다.**

### 평균을 더할수록 이득이 사라진다

| 무엇을 평균했나 | translate | 밀도 | 차이 |
|---|---:|---:|---:|
| 아무것도 | 0.7645 | 0.7712 | **+0.0067** |
| + TTA (8배) | 0.7712 | 0.7751 | **+0.0039** |
| + 앙상블 | 0.7755 | 0.7763 | **+0.0008** |

**우위가 반씩 줄어든다.** 평균내기가 밀도 채널이 해 준 일을 이미 하고 있다.

### 남는 것 — TTA 없는 단일 모델 최고

0.7674 -> **0.7721**(최고), 3 seed 평균 0.7712, 범위 0.0015(기준선의 1/33).
**단 TTA 를 걸면 0.7768 로 기존 최고 0.7769(translate+TTA)와 구분되지 않는다.**
사전 등록한 판정 기준이 아니므로 "채택" 이라 쓰지 않는다.
**추론을 한 번밖에 못 하는 상황에서는 지금까지 중 최선의 구성**이다.


## E18 백본 — 4종으로 재집계, 기각 유지 (밀린 것)

`convnext_tiny_s0` 이 4.6시간(16,656초) 만에 끝나 4종으로 다시 집계했다.
품질을 맞춘 비교에서 1종 0.7629 -> 2종 0.7696 -> 3종 0.7699 로,
**최대 +0.0070 이다. 사전 등록한 요구치 +0.015 의 절반도 안 된다. 기각 유지.**

`convnext_tiny_s0` 자체는 좋은 구성원이다(단독 0.7476 으로 풀 2위, LOO +0.0056 으로 2위).
**개별 구성원이 좋은 것과 구조 축이 다양성을 만드는 것은 다르다.**

**`s1` 은 못 돌렸다.** 4.6시간이 필요한데 03:55 에 자동으로 시작된 것을 **PID 로 죽였다** —
마감까지 못 끝내면서 E20 의 사전 등록된 셔플 대조군을 막고 있었다.
그래서 **convnext 만 1 seed 이고 batch 도 64(다른 백본 256)** 인 상태다.

## E21 선 필터 채널 — 사전 등록과 진단만, 학습은 다음 사이클

GPU 슬롯이 하나뿐이라 학습을 못 돌렸다. 구현, 시험 10개, GPU 1 에폭 스모크까지 끝냈다.
`./exe/run_e21.sh 0 1 2` 로 바로 시작할 수 있다.

학습 없는 진단이 남긴 근거는 둘이다.
1. **Scratch 대 none AUROC 0.712(정사각) -> 0.920(선 L=11).** Edge-Loc 은 반대로 내려간다.
2. **모델 확신도로 층화한 뒤에도 양방향으로 정보가 남는다**(FP 0.3843, FN 0.8488).
   밀도는 FP 방향에서 0.4962 로 아무것도 안 남는다.

**그리고 예측을 하나 박아 뒀다** — 선 필터도 결정론적 함수이므로 **E20 과 같은 일이
일어날 것이다**(단독은 오르고 LOO 는 0 근처). 맞으면 **"손으로 만든 채널" 축 전체가
앙상블 기준에서 닫힌다.**

## 이 사이클의 한 줄

**개별 모델을 좋게 만드는 것으로는 앙상블이 안 오른다.**
E20 이 그것을 깨끗하게 보였다 — 단독은 대조군을 전부 넘는데 앙상블은 제자리이고,
이유는 구성원끼리 더 닮아졌기 때문이다.
그리고 **상한이 0.93 이 아니라 0.83 이다.** 남은 길은 좁고,
**다양성을 만드는 축**과 **라벨 애매성** 둘뿐으로 보인다.

## 덧 — 어느 축이 다양성을 만드는가 (E20 뒤에 이어서 잰 것)

E20 이 "채널을 붙여도 앙상블이 안 오른다" 를 보였으니 **무엇을 바꾸면 다양해지는지**를
같은 자로 쟀다(`src/diag_member_diversity.py`). 오류 상관은 오류 개수와 얽히므로
**오류 개수가 400 이내인 짝만** 쓰고 망가진 모델은 뺐다.

| 두 모델 사이에서 다른 것 | 짝 수 | **오류 상관** |
|---|---:|---:|
| **백본 계열** | 7 | **0.6238** |
| seed 만 | 12 | 0.8285 |
| **입력 채널 추가** | 16 | **0.8287** |

**채널 추가는 seed 를 바꾸는 것과 정확히 같은 만큼의 다양성을 만든다 — 즉 아무것도 안 만든다.**
가설 C 의 가장 간결한 형태다. **백본 계열만 뚜렷하게 낮다.**

E18 이 백본 다양성을 기각한 것과 모순이 아니다. 다양성은 가장 큰데 앙상블 이득이 작았던 이유는
**백본 모델들이 개별적으로 약해서**다. 그 예외가 `convnext_tiny_s0`
(단독 0.7476 으로 풀 2위, LOO +0.0056 으로 2위)이고, **다양하면서 좋으면 좋은 구성원**이 된다.

그리고 `*_train.json` 을 확인했더니 **백본 모델은 전부 `extra_augment=[]` 로 돌았다.**
**다양성을 가장 크게 만드는 축(백본)과 개별 품질을 가장 크게 올리는 것(translate, +0.038)을
같이 건 적이 없다.** 이것이 이 사이클이 남기는 가장 구체적인 다음 실험이다.


##### 현재 최고 풀 안에서도 같은 그림이다

지금 최선인 TTA 18개 풀 안에서 군별 기여를 쟀다.

| 군 | n | LOO 평균 | 단독 평균 |
|---|---:|---:|---:|
| **translate (resnet18)** | 4 | **+0.0028** | **0.7713** |
| 다른 백본 | 6 | -0.0002 | 0.7531 |
| 기존 resnet18 | 8 | -0.0013 | 0.7398 |

**백본 구성원은 가장 다양한데도 기여가 0 이다 — 단독이 0.7531 로 약해서다.**
translate 구성원은 강한데(0.7713) 다양성은 seed 수준이다.

**translate 가 다른 백본에서도 resnet18 에서와 같은 +0.038 을 낸다면**
그 구성원은 0.79 대의 단독 성능과 백본 수준의 다양성(오류 상관 0.62)을 동시에 갖게 된다.
**단 그 전이는 가정이지 측정한 것이 아니다.** 그것을 재는 것이 다음 실험이다.


### E21 선 필터 채널 — 내 예측이 틀렸다 (17차, 2 seed)

E20 뒤에 GPU 가 비어 2 seed 를 돌렸다. **사전 등록은 3 seed 를 요구하므로 형식상 판정 보류이나,
채택 분기는 닫혔다.**

| | 단독 | 범위 | none 누출 | **LOO 군 평균** |
|---|---:|---:|---:|---:|
| 대조군 translate (3채널, 4 seed) | **0.7645** | 0.0067 | 1,190 | +0.0005 |
| 밀도 k=5,7 (5채널, 3 seed) | **0.7712** | 0.0015 | 1,135 | **+0.0015** |
| 셔플 대조군 (5채널, 정보 없음, 1 seed) | 0.7612 | — | 1,032 | **-0.0028** |
| **선 L=11 (4채널, 2 seed)** | **0.7602** | **0.0007** | 1,034 | **-0.0018** |

#### 사전 등록한 예측이 반증됐다

E20 을 보고 이렇게 적어 뒀다 — **"선 필터도 결정론적 함수이므로 E20 과 같은 일이 일어난다:
단독은 오르고 LOO 는 0 근처."**

**절반이 틀렸다. 단독이 오르지 않고 내려갔다**(0.7602, 대조군 범위 0.7607~0.7674 **밖 아래**).
그리고 **셔플 대조군(0.7612, LOO -0.0028)과 구분되지 않는다** —
정보를 담은 채널인데 정보가 없는 채널처럼 행동한다.

**학습 없는 진단에서는 이 신호가 가장 강했다.** Scratch 대 none AUROC 0.920(정사각 0.712),
모델 확신도로 층화한 뒤에도 양방향에 정보가 남는 유일한 신호(FP 0.3843, FN 0.8488).
**그런데 채널로 주니 해로웠다.** 학습 없는 판별력과 채널로서의 유용성이 다르다.

#### 왜인지 — 부분적인 설명 하나

`min_dies=length` 가드가 원인일 수 있다. **길이 11 창이 통째로 다이 영역 안에 들어가야**
값이 생기므로, **웨이퍼 가장자리에서는 구조적으로 0** 이 된다.

| 채널 | 다이 칸 중 0 인 비율 | 평균 | 표준편차 |
|---|---:|---:|---:|
| 밀도 k=5 | **0.025** | 0.1477 | 0.1048 |
| 밀도 k=7 | 0.010 | 0.1465 | 0.0870 |
| 선 L=7 온전창 | 0.188 | 0.2230 | 0.1628 |
| **선 L=11 온전창** | **0.275** | 0.1661 | 0.1416 |

**선 채널은 다이 칸의 27.5% 에서 0 이다**(밀도는 2.5%). 그리고 그 0 은 무작위가 아니라
**웨이퍼 가장자리에 몰린다** — Edge-Loc, Edge-Ring 이 정의되는 바로 그 영역이다.

**이건 그럴듯한 설명이지 검증된 원인이 아니다.** 가드를 뺀 판(포화 문제가 있는)이나
L=7(0 비율 0.188)로 다시 돌려 가르지 않았다. **안 해봤다.**

#### 두 채널 실험이 함께 말하는 것

| 채널 | 단독 | LOO |
|---|---|---|
| 국소 밀도 k=5,7 | **오른다** (+0.0067) | **0 근처** (+0.0015) |
| 선 필터 L=11 | **내려간다** (-0.0043) | **0 근처, 셔플 수준** (-0.0018) |

**손으로 만든 채널 둘 중 어느 것도 앙상블을 올리지 못했다**(둘 다 기각선 +0.003 아래).
단독 성능은 하나는 올리고 하나는 내렸다. **"채널을 붙이면 표현이 하나 더 생긴다" 는
생각은 이 프로젝트에서 두 번 틀렸다.**

## 17차 마무리 — 이 사이클의 한 줄 (수정)

앞에서 "개별 모델을 좋게 만드는 것으로는 앙상블이 안 오른다" 라고 적었다.
E21 이 그것을 한 단계 더 밀었다.

| 손으로 만든 채널 | 단독 | LOO |
|---|---|---|
| 국소 밀도 k=5,7 (3 seed) | **오른다** +0.0067 | +0.0015 |
| 선 필터 L=11 (2 seed) | **내려간다** -0.0043 | -0.0018 (셔플 수준) |

**둘 다 앙상블 기준으로 기각선(+0.003) 아래다.** 그리고 **학습 없는 판별력이 가장 강했던
선 필터가 채널로는 가장 나빴다** — 스칼라로서의 판별력과 채널로서의 유용성은 다르다.

**내가 실행 전에 박은 예측("선 필터도 단독은 오르고 LOO 는 0 근처")은 절반이 틀렸다.**
단독이 내려갔다. 부분적인 설명은 `min_dies` 가드가 다이 칸의 27.5% 를 0 으로 만들고
그 0 이 웨이퍼 가장자리에 몰린다는 것인데, **검증하지 않았다.**


#### 정정 — 세 번째 seed 가 위의 2 seed 판독을 뒤집었다 (06:06)

위 절은 **2 seed**(0.7605, 0.7598, 범위 0.0007)로 "단독이 대조군 범위 밖 아래" 라고 적었다.
**세 번째 seed 가 0.7676 으로 나왔다. 취소한다.**

| | 값 | 범위 | none 누출 | **LOO 군 평균** |
|---|---|---:|---:|---:|
| 대조군 translate (4 seed) | 0.7674 / 0.7660 / 0.7640 / 0.7607, 평균 **0.7645** | 0.0067 | 1,190 | +0.0004 |
| **선 L=11 (3 seed)** | 0.7605 / 0.7598 / **0.7676**, 평균 **0.7626** | **0.0078** | 1,098 | **-0.0010** |

**2 seed 범위 0.0007 이 3 seed 에서 0.0078 로 11배가 됐다.**
그리고 세 번째 값 0.7676 은 **대조군 최고(0.7674)보다도 높다.**

정확한 판독은 이것이다. **선 필터 단독 성능은 대조군과 구분되지 않는다**
(평균 차이 -0.0019, 범위가 서로 겹친다). "범위 밖 아래" 는 **틀렸다.**

**이 프로젝트가 같은 실수를 세 번째로 했다.** 잡음 기준선을 n=2 로 재서 5.6배
과소추정한 것이 첫 번째(교훈 0), 앙상블 기여를 좁은 풀에서 재서 일반화한 것이 두 번째,
그리고 이번이 세 번째다. **n=2 의 범위는 범위가 아니다.**
(E20 의 밀도 3 seed 범위가 0.0015 로 극히 좁았던 것이 방심하게 만들었다 —
좁은 범위가 관측된다고 그 조건이 원래 안정적인 것은 아니다.)

**판정은 그대로 기각이다** — LOO -0.0010 으로 기각선(+0.003) 아래이고
셔플 대조군(-0.0026)과 크게 다르지 않다. **바뀐 것은 "왜" 다.**
단독이 나빠서가 아니라 **단독이 대조군과 같은데 다양성도 안 만들어서**다.
이는 E20 과 정확히 같은 결론이고, `min_dies` 가 27.5% 를 0 으로 만든다는
앞 절의 설명은 **더 이상 필요하지 않다**(설명할 손해 자체가 없다).
그 설명은 취소하지 않고 남기되 **근거가 사라졌다고 표시한다.**
