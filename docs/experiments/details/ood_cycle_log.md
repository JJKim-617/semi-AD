# 1차 사이클 — 기획과 바닥 측정 (2026-08-22)

## 무엇을 왜 했는가

주제는 **정상 웨이퍼만 학습에 쓰고 결함을 이상으로 탐지하는 것**이다.
실제 팹이 결함 유형을 미리 열거할 수 없다는 조건과 맞고, 같은 연구실의 3D-AD 작업이 쓰는 설정과도 같다.

지시는 "가능한 한 높은 출발점에서 시작하라" 였다. 그래서 순서를
**조사 → 바닥 측정 → 기획 → TDD 뼈대** 로 잡았다. 바닥을 먼저 잰 것이 결과적으로 기획 전체를 바꿨다.

## 조사에서 막힌 것

**웹 검색 예산이 세션에서 소진**돼(200/200) 광범위 조사를 못 했다.
대신 arXiv 초록을 WebFetch 로 직접 확인하고, 레포의 기존 조사 문서를 썼다.
**확인 못 한 것은 문서에 그렇게 표시했다.**

| 방법 | 확인된 것 | 출처 |
|---|---|---|
| PatchCore | 정상 patch feature memory bank, **ImageNet 임베딩**, MVTec image AUROC 최대 99.6% | arXiv 2106.08265 초록 |
| PaDiM | 사전학습 CNN patch 임베딩, **patch 위치별 다변량 가우시안**, one-class | arXiv 2011.08785 초록 |

둘 다 **ImageNet 특징에 의존**하는데, `docs/research/encoder_selection/README.md` 가
이 데이터에서 그 전이가 약하다는 근거를 이미 모아뒀다(17만 장 규모에서 이득 소멸,
웨이퍼맵 실측에서 scratch CNN 83.14 vs MobileNetV2 fine-tune 59.46).
PaDiM 의 위치별 가우시안은 공간 정렬을 가정하는데 우리 웨이퍼는 크기가 크게 달라
**극좌표가 실패한 것과 같은 함정**으로 보인다 — 미검증 우려로만 기록했다.

## E0 — 바닥이 예상보다 훨씬 높다

학습이 전혀 없는 스칼라 통계를 공식 test 전수로 쟀다.

| 스칼라 | AUROC | AUPR | FPR@95TPR |
|---|---:|---:|---:|
| 불량 다이 개수 | **0.8167** | 0.3633 | 0.7367 |
| 불량 다이 비율 | 0.7899 | **0.3856** | 0.7364 |
| 웨이퍼 크기 | 0.5037 | 0.0650 | 0.9562 |
| 불량 공간 퍼짐 | 0.4727 | 0.0625 | 0.9926 |
| 불량 이심률 | 0.5064 | 0.0709 | 0.9548 |
| 무작위 | 0.5000 | 0.0666 | 0.95 |

**세 가지가 이 표에서 나왔다.**

**1. 원래 기획서의 목표가 약했다.** `ad_baseline_plan.md` §6 이 "AD: AUROC 0.90 을 1차 기준" 으로
제안했는데, 불량 다이를 세기만 해도 0.8167 이다. **바닥 위로 겨우 +0.083.**
목표를 AUPR 0.3856 기준으로 다시 세웠다.

**2. AUROC 만 보면 안 된다.** FPR@95TPR 0.7367 — 결함의 95% 를 잡으려면 정상의 74%,
약 8만 장을 같이 띄운다. AUROC 0.82 는 실무에서 무의미하다.
**주 지표를 AUPR 로 두고 FPR@95TPR 을 함께 보기로 했다.**

**3. 내가 만든 공간 통계가 무용지물이었다.** 불량 좌표의 2차 모멘트로 만든 퍼짐이
**무작위보다 낮은 0.4727**, 이심률은 0.5064 로 무작위다. 전역 통계로는 결함 구조가 안 잡힌다.
9-class 쪽에서 none→Scratch 오검출 웨이퍼를 전역 통계로 구분하지 못한 것과 같은 결과다.

### 값어치가 어디 남아 있는가

| 결함 | AUROC (개수 기준) |
|---|---:|
| Near-full / Random / Donut | 1.000 / 0.997 / 0.984 |
| Edge-Ring / Edge-Loc / Loc | 0.895 / 0.817 / 0.810 |
| Center | 0.754 |
| **Scratch** | **0.656** |

**절반은 이미 끝난 문제다.** 남은 것은 **Scratch, Center, Loc** — 개수가 아니라 공간 구조로
정의되는 것들이다. 전체 평균만 보면 개선이 쉬운 쪽에서 온 것처럼 보일 수 있어
**클래스별 표를 반증 조건에 넣었다.**

# 2차 사이클 — O1 template 잔차, 그리고 바닥을 다시 재다 (2026-08-22 22:30~24:00)

## 무엇을 왜 했는가

사다리의 O1(정상 통계 template 잔차)을 하기로 돼 있었고, 그 **핵심 설계 결정은
크기 정규화**였다. 옆 워크스트림에서 극좌표가 정확히 그 지점에서 무너졌기 때문이다.
GPU 0번은 9-class 쪽 E18/convnext 가 쓰고 있어 **이 사이클도 CPU 만 썼다.**

중간에 **범위가 바뀌었다.** OOD 가 파이프라인 1단계가 되고
(OOD 탐지 → 다이 단위 국소화 → MLLM 8종 분류 → 유저 질의응답),
**다이 단위 잔차 맵이 1급 산출물**이 됐다. 기획서에 §9 범위 확장 절로 적었다
(정정이 아니다 — 프로젝트 정의가 바뀐 것이다).

## 순서

1. `docs/experiments/candidate/ood_template_residual.md` 에 **반증 조건 6개를 실행 전에** 박음
2. TDD — `tests/test_a22_ood_template.py` 먼저 쓰고 실패 확인 후 `src/a22_ood_template.py` 구현
3. `src/a23_ood_template_eval.py` 로 12 arm 채점
4. 결과를 보고 **짝지은 부트스트랩이 필요하다는 것을 알게 됨** → 정정
5. `ood_residual_pooling.md` 에 뭉개기 반증 조건을 **실행 전에** 박고 48 arm 채점
6. 결과가 너무 좋아 **빠진 대조군을 찾음** → 국소 밀도 대조군 실행 → 결론이 뒤집힘
7. 맵 내보내기와 대표 사례 시각화

## O1 template 잔차 — 탐지기로 전부 기각

세 좌표계(절대 pad / 리사이즈 / 자기 반경 정규화)와 두 채점기(NLL 잔차 /
불량률을 맞춘 뒤의 구조 점수 S_llr)를 균일 template 대조군과 함께 쟀다.

- **단독 최고 T-RESIZE S_nll AUPR 0.3619** — 바닥 0.3856 에 짝지은 검정으로 진다
  (-0.0237, p=0.0000). 반증 조건 1 로 기각.
- **융합(불량률 + T-PAD S_llr)은 AUPR 0.4058 로 바닥을 이긴다**(+0.0201, p=0.0000).
  그런데 Scratch 0.5794 / Center 0.6224 / Loc 0.7092 로 **값어치 남은 세 클래스가 전부
  나빠졌다.** 이득은 이미 끝난 클래스(Random, Near-full, Edge-Loc)에서 왔다.
  **반증 조건 2 가 정확히 이걸 잡으라고 박은 것이라 융합도 기각했다.**
  조건 1 만 봤으면 채택했을 것이다 — 사전등록이 실제로 일한 지점이다.

### 크기 정규화 질문에는 답이 나왔다

균일 template 대조군과 짝지어 재니 깔끔하게 갈렸다.

| | 균일 대조군 대비 AUPR 차이 | p |
|---|---:|---:|
| T-RESIZE (정규화 좌표) | [+0.0538, +0.0724] | 0.0000 |
| T-PAD (절대 좌표) | [-0.0003, +0.0022] | 0.1320 |
| T-RADIAL (반경 전용) | [-0.0051, -0.0028] | 0.0000 |

**정규화 좌표에서만 위치 template 이 균일 상수보다 정보를 담는다.**
절대 좌표에서 "학습" 한 위치 통계는 **균일 상수와 구분되지 않았다** —
train-none 이 64x64 격자 4096칸 중 **822칸(20.1%)을 한 번도 안 밟는다.**
큰 test 웨이퍼는 반드시 그 구멍 위에서 채점되고, `>1600` 구간 AUPR 이
0.1777 → 0.0826 으로 무너진다. **극좌표와 같은 실패의 재현이고, 원인도 같다.**

### 실행 전에 적은 예측이 4개 중 3개 틀렸다

"정상은 가장자리에서 더 자주 불량이 나므로 S_llr 이 Center/Scratch/Loc 을 돕고
Edge 계열을 해친다" 고 적었다. Edge 쪽은 맞았다(Edge-Ring 0.0282, 예상보다 훨씬 크게).
**Center 는 정반대로 갔다**(0.4096, 무작위 아래).

**전제가 틀렸다.** 정상 웨이퍼는 가장자리에서만 자주 죽는 게 아니라 **중심에서 더 죽는다.**
- train-none 웨이퍼의 **중심 최근접 다이는 58.9% 가 불량**이다(전체 다이 불량률 11.6%).
- 반경 프로파일이 U 자다: 중심 0.55 → 중간 0.085 → 가장자리 0.34.

그래서 Center 결함은 template 이 **이미 높은 자리**에 불량을 놓는 셈이 된다.
**왜 중심 다이가 그런지는 모른다.** WM-811K 는 6개 컬럼뿐이라 확인할 방법이 없다.

### 기각했지만 버리지 않은 것

S_llr 의 Edge-Ring AUROC 0.023 은 정보가 없다는 게 아니라 **부호가 반대**라는 뜻이다.
결함끼리만 놓고 보면 **학습 없는 스칼라 하나가 Edge-Ring 대 Scratch 를 AUROC 0.983 으로
가른다**(불량 다이 개수는 0.171, 뒤집어도 0.829). **1단계에서 기각된 것이 3단계에서
값어치가 있을 수 있다.** §9.4 간접 평가로 확인할 일이다.

## 정정 1 — 내가 박은 반증 조건 6 이 틀린 검정이었다

"두 arm 의 **독립 CI 가 겹치지 않아야** 이겼다고 한다" 고 적었는데,
두 점수는 **같은 118,595장** 위에서 계산되므로 표본 변동을 공유한다.
독립 CI 겹침은 짝지은 비교에 지나치게 보수적이다.
실제로 융합 [0.3950, 0.4168] 과 바닥 [0.3753, 0.3958] 이 0.0008 폭으로 겹쳐
"경계선" 으로 읽혔지만, 짝지은 검정으로는 +0.0201 [+0.0121, +0.0280], p=0.0000 로 명확하다.

`a23_ood_template_eval.paired_aupr_diff_ci` 를 TDD 로 추가했다.
재표본 가중치를 원 인덱스 위에서 한 번 뽑고 두 점수의 정렬 순서로 재배열해 넣어,
**두 arm 이 문자 그대로 같은 웨이퍼 묶음**을 보게 한다.

## 뭉개기 — 수치가 뒤집혔다

O1 의 두 스칼라는 사실 **다이별 잔차 맵의 합**이고, 합은 공간 구조에 가장 둔한 요약이다.
맵을 8가지로 뭉개 48 arm 을 쟀다.

**`smooth5_max`(5x5 이웃 평균의 최대)가 AUPR 0.6808 을 냈다.** 바닥의 1.8배다.

## 정정 2 — 그 점수는 template 이 낸 게 아니었다 (빠진 대조군)

결과가 너무 좋아 교란을 찾았고, 대수적으로 찾았다.
`pool_smoothed_max` 는 창 안 잔차 합을 **창 안 다이 개수로 나눈다.** 균일 template 이면

```
창 평균 = -log(1-p) + f * log((1-p)/p),   f = 창 안 불량 다이 비율
```

**기울기 양수인 아핀 함수**다. 즉 **균일 template + smooth_k_max = 국소 불량 밀도의 최대**이고
template 기여가 0 이다. 내가 후보 문서에 적은 대조군은 `sum` 뭉개기와 E0 스칼라뿐이었다 —
**뭉개기를 바꾸면 대조군도 같이 바뀌어야 한다는 것을 놓쳤다.**

대조군을 넣고 다시 재니:

| 창 | 반경 template | 균일(= 국소 밀도) | 짝지은 차이 | p |
|---|---:|---:|---:|---:|
| k=3 | 0.6034 | 0.4968 | [+0.0956, +0.1177] | 0.0000 |
| k=5 | 0.6808 | **0.6885** | [-0.0135, -0.0020] | 0.0060 |
| k=7 | 0.7033 | **0.7147** | [-0.0159, -0.0070] | 0.0000 |
| k=9 | 0.6828 | **0.7007** | [-0.0217, -0.0142] | 0.0000 |

**창이 5 이상이면 반경 template 은 순전한 손해다.**

## 정정 3 — O0 이 잡은 바닥 자체가 틀렸다

**국소 밀도는 학습이 0 이다.** template 도 파라미터도 train 자료도 안 쓴다.
그런데 AUPR 0.7147 을 낸다. O0 이 "학습 없는 자명한 스칼라" 를 잰다면서
**전역 스칼라만 쟀고** 바닥을 0.3856 이라고 적었다.

**진짜 바닥은 0.3856 이 아니라 0.7147 이다.**
1차 사이클에서 E0 의 전역 2차 모멘트가 무작위보다 낮은 것을 보고
"전역 통계로는 결함 구조가 안 잡힌다" 고 **옳게** 적어 놓고도,
그 다음 질문("그럼 국소 통계는?")을 O1 학습 사다리로 미뤘다.
**학습 없는 국소 통계를 먼저 쟀어야 했다.**

이전 사이클에서 "융합이 0.4058 로 바닥을 이겼다" 고 적은 것은
**잘못된 바닥에 대고 이긴 것**이다. 새 바닥에는 한참 못 미친다.
새 바닥은 `tests/test_a24_local_density_pin.py` 로 고정했다.

### 그래도 클래스별로는 template 이 이긴다 — 둘 다 참이다

| | Scratch | Center | Loc | Edge-Loc | Edge-Ring |
|---|---:|---:|---:|---:|---:|
| 대조 균일/smooth7_max | 0.7586 | 0.7455 | 0.9150 | **0.9844** | **0.9692** |
| T-RADIAL/smooth7_max | **0.8111** | **0.7495** | **0.9477** | 0.9666 | 0.9375 |
| T-RADIAL/smooth3_max | 0.8090 | **0.8558** | **0.9702** | 0.9358 | 0.9006 |

전체 AUPR 은 Edge 계열이 지배한다(결함 7,894 중 3,898장 = 49.4%).
template 이 Edge 를 깎고 Scratch/Loc 을 올리니 **합계는 지고 값어치 남은 곳에서는 이긴다.**
**하나만 쓰면 거짓말이 된다.**

## 정정 4 — 등가성을 argsort 로 박으려다 실패했다

"국소 밀도 = 균일 template 잔차 뭉개기" 를 처음에 `argsort` 결과가 같다로 박으려 했는데
테스트가 깨졌다. 항등식 오차는 8e-16 인데 **아핀 변환이 1 ULP 차이를 없애거나 만들어
동점 구조가 달라진다**(동점 3개 vs 4개). 그러면 순열이 달라지고 AUROC 도
0.5006 대 0.5019 로 갈린다. **등식 자체와 기울기 부호를 박고,
값이 실제로 다른 쌍의 대소만 비교하는 것**으로 고쳤다.

# 3차 사이클 — 창 모양을 결함 모양에 맞춰 봤고, 정상 웨이퍼에 대해 알게 됐다 (2026-08-23 00:15~01:00)

## 무엇을 왜 했는가

2차 사이클의 정성 관찰에서 **놓치는 이유가 보였다**: 놓친 Scratch 는 선이 창보다 가늘다.
7x7 창에 길이 7 짜리 1픽셀 선이 들어오면 밀도가 7/49 = 0.14 인데
같은 창의 5x5 덩어리는 20/49 = 0.41 이다. **정사각 창이 선을 조직적으로 희석한다.**

→ 창을 선 모양으로 바꾸면 같은 선이 1.0 이 된다. 학습이 아니라
**결함 모양에 대한 사전지식을 창 모양에 넣는 것**이라 여전히 train 자료를 안 쓴다.

**주 arm 을 하나로 미리 고정했다**(`line7_8dir`: 길이 7, 폭 1, 8방향, 방향과 위치에 대해 최대).
변형을 여러 개 재고 최고를 고르면 test 로 고른 것이라 누수이기 때문이다.
나머지 7개는 탐색용으로 표시하고 판정에 쓰지 않았다.

GPU 0번은 계속 9-class 쪽이 쓰고 있어 **이번에도 CPU 만 썼다.**

## 주 arm 은 참담하게 실패했다

**AUPR 0.0804** — 유병률 0.0666 바로 위다. 대조 정사각 k=7(0.7145) 대비
짝지은 차이 **[-0.6430, -0.6256], p=0.0000**. Scratch 도 0.7586 → 0.6332 로 떨어졌다.
반증 조건 1, 2, 4, 5 를 전부 위반해 기각.

## 왜 — 포화

클래스별 AUROC 에서 **다섯 클래스가 정확히 같은 값(0.6490)** 이 나온 게 단서였다.
점수의 **고유값이 13개뿐**이다.

**정상 웨이퍼의 70.21% 가 어딘가에 불량 7칸짜리 직선을 갖고 있다.**
창이 포화하면 점수가 상수가 되고 순위가 무너진다.
길이별로: line5 정상 포화 95.24%, line7 70.21%, line9 54.72%, line11 50.73%,
정사각 k=7 은 **0.00%**.

### 첫 설명이 양적으로 틀렸다 (자기 정정)

"창 후보가 8방향 x 수천 위치라 다중비교로 우연히 걸린다" 고 읽었는데 **계산이 안 맞는다.**
독립 Bernoulli 아래 기대 포화 창 수는 `8 x 800 x 0.116^7 = 0.002`,
즉 **0.2% 여야 하는데 70% 다. 350배 차이다.**
우연이 아니라 **정상 웨이퍼의 불량이 실제로 뭉쳐 있다.**

### 어디에 뭉쳐 있는가 — 가장자리 링

포화된 창의 정규화 반경을 재니 **정상 포화의 95.49% 가 반경 0.85 바깥**이었다.
기작 확인용으로(사전등록 arm 아님) 안쪽만 보게 하니
정상 포화 70.63% → 19.19%, AUROC 0.6371 → 0.8047 로 움직였다.
**원인이 가장자리 링이라는 것이 확인된다.**

**→ 새 사실: 정상 웨이퍼의 바깥 링에는 연속으로 죽은 다이가 줄줄이 있다.**
왜 그런지는 모른다.

## 예측 채점 — 기작은 맞혔고 파급은 못 맞혔다

실행 전에 "정상 웨이퍼의 가장자리 링을 선 창이 따라가 정상에서도 밀도 1.0 이 쉽게 나올 것이고,
그래서 Edge 가 나빠질 것" 이라고 적었다. **기작은 정확히 맞았다.**
그런데 "Scratch 는 오른다" 는 틀렸고, 파급도 과소평가했다 —
정상 쪽이 천장에 붙으면 Edge 만이 아니라 **순위 전체**가 무너진다.

2차 사이클에서는 예측이 4개 중 3개 틀렸고 이번에는 기작을 맞혔다.
**실행 전 예측을 적어 두는 것이 교정 기록으로 값어치를 내기 시작했다.**

## 탐색 arm — 판정에 안 쓰지만 기록한다

### 다중척도 결합이 대조군을 이겼다 (미확인)

k=3,5,7,9 정사각 밀도를 train-none 백분위로 바꿔 Fisher 결합:
**AUPR 0.7264 [0.7176, 0.7346]**, 짝지은 차이 **[+0.0096, +0.0142], p=0.0000**,
**FPR@95TPR 0.4295**(대조군 0.4844).
**Center 가 0.7458 [0.7285,0.7624] → 0.7971 [0.7814,0.8116] 로 CI 가 안 겹치게 오른다.**
Scratch 는 0.7586 → 0.7451 로 조금 나빠진다(CI 겹침).

**선택 위험을 명시한다**: 탐색 arm 7개 중 1개가 이겼고 **무엇을 부각할지는 결과를 보고 정했다.**
효과 크기(+0.012)도 k=3 대 k=7 차이(+0.216)에 비하면 작다.
**주 arm 으로 사전등록해 다시 재기 전에는 채택하지 않는다.**

### 중심 다이 제외는 Center 를 돕지 않았다 — 내 가설이 틀렸다

정상의 중심 최근접 다이가 58.9% 불량이라 빼면 Center 가 좋아질 줄 알았는데
**오히려 조금 나빠졌다**(Center 0.7458 → 0.7380, 전체 0.7145 → 0.7135).
중심 한 칸은 7x7 창 49칸 중 하나라 밀도에 거의 영향이 없다.
**중심 다이 교란은 셀 하나짜리 통계(반경 template)에서만 문제였고 창 통계에서는 아니다.**

### 창 셀 수가 shape 보다 중요하다 — 다만 shape 도 남는다

셀 수 순으로 대체로 좋아진다(5칸 0.0658 → 49칸 0.7145). 밀도 추정의 표본 크기라서다.
그런데 **정사각 k=3(9칸) 0.4986 과 line9(9칸) 0.0943 은 같은 셀 수인데 5배 넘게 갈린다.**
차이는 **최대를 취하는 후보 집합의 크기**다 — 정사각은 방향 1개, 선은 8개라
정상도 8배 많은 기회를 갖는다. **`max` 뭉개기는 창 모양뿐 아니라 후보 수에도 민감하다.**

## 운영 지점 표를 상설로 만들었다

**AUPR 총합은 어디서 무너지는지를 가린다.** `a21_ood_metrics.operating_points` 를 TDD 로 추가하고
보고서에 상설로 넣기로 했다. 팹이 감당하는 것은 곡선 아래 넓이가 아니라 헛경보 장수다.

| arm | 재현율 50% | 재현율 80% | 재현율 95% |
|---|---|---|---|
| | precision / 헛경보 | precision / 헛경보 | precision / 헛경보 |
| E0 불량 다이 비율 | 0.247 / 12,024 | 0.121 / 46,016 | 0.084 / 81,522 |
| 국소 밀도 k=3 | 0.486 / 4,174 | 0.278 / 16,414 | **0.133** / 48,894 |
| 국소 밀도 k=5 | 0.791 / 1,043 | **0.364** / 11,059 | 0.133 / 48,927 |
| 국소 밀도 k=7 | **0.863** / 628 | 0.356 / 11,402 | 0.123 / 53,621 |
| 국소 밀도 k=9 | 0.839 / 759 | 0.327 / 12,980 | 0.116 / 56,933 |
| **반경보정 밀도 k=7** | **0.880 / 540** | **0.464 / 7,290** | **0.158 / 39,889** |

**50% → 80% 사이에서 precision 이 반토막 난다**(k=7: 0.863 → 0.356).
반경 보정이 그 구간을 가장 크게 올린다(0.356 → 0.464, 헛경보 11,402 → 7,290).

**창 크기는 운영 지점마다 우열이 갈린다 — 하나가 지배하지 않는다.**
50% 에서는 k=7, 80% 에서는 k=5, 95% 에서는 k=3 이 최고 precision 이다.
**단일 최적 k 를 고르면 안 된다.**

## 발견한 문제 — 다음 사이클로 넘긴다

운영 지점을 재면서 동점 민감도를 같이 쟀는데 **k=3 에서 심각하다.**

| arm | 고유값 | 결정론적 AUPR | 동점 무작위 해소 AUPR |
|---|---:|---:|---|
| 국소 밀도 k=3 | 108 | **0.4986** | **[0.4112, 0.4248]** |
| 국소 밀도 k=5 | 875 | 0.6876 | [0.6819, 0.6856] |
| 국소 밀도 k=7 | 2,017 | 0.7145 | [0.7144, 0.7151] |
| E0 불량 다이 비율 | 7,986 | 0.3856 | [0.3857, 0.3857] |

**k=3 의 결정론적 값이 무작위 해소 범위 바깥에 있다.** 우연이 아니라 편향이다 —
동점 안에서 원래 인덱스 순서를 쓰는데, test 배열 위치와 결함 여부에 약한 상관이 있다
(전체 0.0116, 3사분위 결함비율 0.0967 대 나머지 약 0.055).
즉 **동점 처리를 통해 라벨 정보가 샌다.**

조정자가 준 k=3 AUPR 0.3845 와 내 0.4986 이 다른 이유가 이것으로 설명된다.
**둘 다 각자의 관례에서는 맞다.** 그렇다면 그 지점의 AUPR 은 관례를 밝히지 않으면
정의되지 않는 값이다. **5차 사이클에서 동점을 블록으로 묶는 관례로 고친다.**

덤으로 하나 더: 점수를 npz 에 **float32 로 저장**하면 동점이 새로 생긴다.
같은 k=3 점수가 메모리에서는 고유값 108개인데 float32 로 저장했다 읽으면 24개다.
**저장 후 다시 잰 지표와 메모리에서 잰 지표가 다를 수 있다.**
