# 가설 — 웨이퍼 크기를 명시 입력으로 주면 크기 이동에 강해진다

제안일 2026-08-22. 상태: 실험 예정.

## 근거

진단에서 클래스 조건부 분포가 split 간 다르다는 것이 확인됐다. 같은 Scratch 가
train 은 median 52x52(32% 가 다운샘플), test 는 31x31(99% 가 업샘플)이다.
pad 표현이 resize 를 이긴 것(+0.0216)도 크기 정보가 유용하다는 증거다.

다만 pad 는 크기를 **암묵적으로** 전달한다. 모델이 캔버스에서 웨이퍼가 차지하는
비율을 픽셀에서 추론해야 한다. `dieSize` 는 캐시에 이미 들어 있으므로 직접 줄 수 있다.

## 가설

크기를 스칼라 특징으로 분류 헤드에 이어 붙이면, 모델이 크기 조건부로 판단을 조정할 수 있다.
BN 적응과 달리 이 정보는 **클래스 구성에 오염되지 않는다.** 웨이퍼 크기는 라벨 분포와 무관하게
각 표본의 고유 속성이다.

## 검증 설계

기준선은 E8(pad, 0.7485). 입력 표현과 학습 설정을 모두 고정하고 크기 특징만 추가한다.

| 태그 | 조건 | 답하는 질문 |
|---|---|---|
| `e11_size` | pad + dieSize 를 헤드에 concat | 크기 정보가 도움이 되는가 |
| `e11_shuffle` | **대조군.** 크기 값을 무작위로 섞어서 넣음 | 이득이 크기 정보 때문인가, 아니면 단순히 파라미터가 늘어서인가 |

두 번째가 핵심이다. 크기를 셔플하면 정보는 파괴되지만 모델 용량과 학습 동역학은 동일하다.
`e11_shuffle` 이 `e11_size` 만큼 오르면 이득의 원인은 크기 정보가 아니다.

## 기각 조건

- `e11_size` 가 기준선을 잡음 기준선(0.0089) 이상으로 못 넘으면 크기는 이미 pad 로 충분히 전달된 것이다.
- `e11_shuffle` 이 `e11_size` 와 비슷하면 관측된 이득은 정보가 아니라 용량 효과다.

## 전처리 주의

dieSize 는 값 범위가 넓다(수백~수만). 정규화하지 않으면 스칼라 하나가 512차원 특징을
압도한다. train 통계로 표준화하고, test 통계는 쓰지 않는다.
