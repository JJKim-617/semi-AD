# 요소 가중 — Fisher 의 독립 가정을 정상 데이터로 고친다, 착수 전 사전등록

작성 2026-08-23 16:1x, 브랜치 `exp/ood-oneclass`. **한 줄도 실행하기 전에 쓴다.**
판정은 §9 에 append 한다.

## 1. 무엇이 문제인가 — 채점기의 가정이 데이터와 안 맞는다

현재 최선은 세 요소 점수를 **train-none 백분위**로 바꾼 뒤 **Fisher 결합**한다.

```
s = sum_i -2 log(1 - u_i),   u_i = train-none 경험분포에서의 백분위
```

**Fisher 의 결합 통계량은 p 값들이 서로 독립일 때만 그 분포를 갖는다.**
그런데 요소 A(k2 5x5 + 반경 대역 보정)와 요소 C(k2 3x3)는 **둘 다 k2 밀도의 최대값**이다.
창 크기만 다르고 같은 것을 센다. **구조적으로 독립일 수 없다.**

독립이 아닌 것을 독립으로 취급하면 **겹치는 신호를 두 번 세게 된다.**
지금 셋을 똑같이 세므로, 서로 닮은 A 와 C 가 사실상 **2표**를 갖고
혼자 다른 것을 보는 B(온전창 선 L=11)가 **1표**를 갖는다.

## 2. 이 가설은 정상 데이터만으로 정당화된다

**이 문서의 주장은 test 도 val 도 안 보고 확인할 수 있다.**
요소 간 상관은 **train-none 29,149장에서** 재면 된다. 그것이 §5-1 의 첫 측정이다.

**출처를 정직하게 적는다**: 이 가설을 떠올린 계기는 12차 사이클의 `val_unseen` 관측이었다
(`candidate/ood_scratch_shift.md` — 이심률 상관이 A -0.343, C -0.296, **B +0.127**).
val 을 **방법 선택**에 쓰지 말라는 규약이 있으므로 이 점을 숨기지 않는다.
다만 **arm 자체는 val 을 전혀 참조하지 않고 정의된다** —
가중은 **train-none 공분산 하나**에서 나오고, 평가는 `test_dev` 에서 한다.
**val 이 한 일은 우선순위를 바꾼 것이지 arm 을 고른 것이 아니다.**
그리고 §1 의 논거(A 와 C 는 둘 다 k2 밀도다)는 val 없이도 성립한다.

## 3. arm — 가중을 정상 데이터에서 유도한다 (범위 A)

백분위 `u_i` 를 정규 분위수로 바꾼다: `z_i = Phi^-1(u_i)`.
**train-none 에서** `z` 의 공분산 `S` 를 잰다(정상만 쓴다. test 도 val 도 안 본다).

| arm | 점수 | 지위 |
|---|---|---|
| **W1** | `s = 1' S^-1 z` | **주 arm** |
| W0 | `s = sum z_i` (동일 가중, S=I) | **대조군.** 백분위→probit 변환만의 효과를 뺀다 |
| fuse3 | 현재 채택 (Fisher) | 기준선. `test_dev` **0.8304** |
| (탐색) W2 | `s = z' S^-1 z` 의 한쪽 꼬리 | 탐색. **별도 사전등록 없이 채택하지 않는다** |

**W0 대조군이 반드시 필요하다.** W1 이 이기면 그 이득이
**(a) 가중** 때문인지 **(b) Fisher 대신 probit 합을 써서**인지 가려야 한다.
이 워크스트림의 정정 2, 9, 12 가 전부 "한 축을 바꾸면서 딸린 것을 안 바꿨다" 였다.

`1' S^-1 z` 는 **공통 평균 이동을 상관 잡음 아래에서 검출하는 최적 선형 결합**이다.
가중이 데이터에서 **유도**되지 손으로 고르는 손잡이가 아니다 —
**test 로 고르는 자유도가 0 이다.**

## 4. 어디서 재는가

- **개발과 판정은 `test_dev`(87,695장, 결함 5,799)에서만.** `test_sealed` 는 열지 않는다.
- `S` 는 **train-none 에서만** 적합한다. `assert_one_class` 와 `assert_not_sealed` 를 통과해야 한다.
- 결정론적이므로 seed 면제. 대신 **부트스트랩 CI**(§6-4 의 대안).

## 5. 무엇을 측정하는가

1. **train-none 에서 z 의 상관행렬.** A-C 상관이 높지 않으면 §1 의 전제가 틀린 것이다 —
   그 경우에도 **그대로 보고한다**(예측 3의 채점).
2. `1' S^-1 z` 의 **요소별 가중**을 그대로 적는다. 어떤 요소가 눌리고 어떤 요소가 커지는가.
3. blocked AUPR, AUROC, FPR@95TPR, **고유값 개수**, 운영 지점 50/80/95%,
   **클래스별**, **dieSize 구간별**.
4. fuse3 대비, W0 대비 **짝지은** blocked AUPR 차이 CI.

## 6. 반증 조건 — 하나라도 걸리면 기각이다

1. **`test_dev` 에서 fuse3 대비 짝지은 blocked AUPR 차이 CI 하한 <= 0 이면 기각.**
2. **W0 대비 CI 가 0 을 포함하면, 이득을 "가중" 이라 부르지 않는다** — probit 변환 효과다.
3. **Scratch, Center, Loc 중 하나라도 CI 가 겹치지 않게 내려가면 기각**(기획서 §6-2).
   **평균만 오르는 개선은 채택하지 않는다.**
4. **고유값 개수가 1,000 미만이면 채택 보류.** 운영 지점을 못 고르는 채점기다.
5. **dieSize `562-776` 또는 `1090-1334` 에서 fuse3 보다 나빠지면 기각**(기획서 §6-5).
6. **`S` 를 train-none 밖에서 적합했으면 전체 무효.** 코드에 가드를 둔다.
7. **`test_sealed` 를 열었으면 전체 무효.**

## 7. 실행 전 예측 — 실행 후 채점한다

1. **W1 이 fuse3 를 이기지만 +0.02 를 못 넘는다.** 요소가 셋뿐이라 가중으로 얻을 것이 작다.
2. **Scratch 가 가장 많이 오른다.** B 가 눌려 있던 클래스다.
3. **train-none 에서 A-C 상관이 A-B, B-C 상관보다 높다.** 둘 다 k2 밀도이기 때문이다.
4. **`1' S^-1 z` 에서 B 의 가중이 가장 크다.** 혼자 다른 것을 보므로.
5. **W0(동일 가중 probit 합)는 fuse3 와 거의 같다** — 둘 다 동일 가중이고
   단조 변환 차이뿐이다. 차이가 크면 **Fisher 의 꼬리 강조가 실제로 일을 하고 있었다**는 뜻이고
   그건 예상 밖이므로 그렇게 보고한다.

## 8. 이 사이클이 못 하는 것

- **요소를 새로 만들지 않는다.** A, B, C 는 그대로 두고 결합만 바꾼다.
- **12차 사이클이 찾은 약점(가는 긁힘)을 직접 겨냥해 필터를 고치지 않는다.**
  그건 val 에 적합시키는 것이다. 여기서 고치는 것은 **결합 규칙의 잘못된 가정**뿐이고,
  그 잘못은 val 없이도 지적된다(§2).
- **큰 웨이퍼(`>1600`) 커버리지 구멍은 이 arm 으로 안 메워진다**(정정 13).

### 손해가 어디서 왔는지가 이 사이클의 산출물이다

**손해 -0.0130 중 -0.0118 이 probit 변환에서 오고 -0.0012 만 가중에서 온다.**

즉 **가중은 거의 무관하고, 진짜로 일하고 있던 것은 Fisher 의 꼬리 강조였다.**
Fisher 는 `-2 log(1-u)` 라 `u -> 1` 에서 발산한다. probit 은 훨씬 완만하다.
**백분위 상위 극단을 얼마나 세게 볼 것인가가 이 채점기의 실질 손잡이였고,
나는 그것을 "독립 가정" 문제로 오인했다.**

**이건 예측 5 의 반증이다.** 나는 "W0 는 fuse3 와 거의 같을 것" 이라 적고
"차이가 크면 Fisher 의 꼬리 강조가 실제로 일을 하고 있었다는 뜻이고 그건 예상 밖이므로
그렇게 보고한다" 고 실행 전에 못 박아 두었다. **그 조항을 그대로 적용한다.**

**Scratch 가 가장 많이 올랐다 — 예측 2 적중.** 12차 사이클이 예고한 그대로다.

이유는 상관행렬과 클래스별 단독 성능을 같이 보면 보인다.
**C 는 A 와 가장 닮았지만(0.800), 동시에 Center 를 가장 잘 보는 요소다**
(단독 Center: C **0.9588** > A 0.8710 > B 0.8118).
`1' S^-1 1` 은 **"세 요소가 같은 공통 이동을 잰다"** 고 가정하고 중복을 깎는데,
**이 데이터에서 요소들은 같은 것을 재지 않는다 — 서로 다른 결함을 잰다.**
그러니 "중복" 으로 깎인 C 가 사실은 Center 전담이었고, 깎으니 Center 가 무너진다.

**Fisher 의 독립 가정이 틀렸다는 §1 의 지적은 맞다. 그러나 그것을
"공통 이동" 모형으로 고치는 것은 더 틀린 가정을 넣는 일이었다.**

### 결론 — 무엇을 배웠나

1. **채택 arm 을 바꾸지 않는다.** fuse3 가 유지된다.
2. **요소 셋은 정상 웨이퍼에서 0.68~0.80 으로 상관돼 있다.** Fisher 의 독립 가정은
   실제로 틀렸다. 그런데 그 틀림이 **성능을 깎고 있지 않았다.**
3. **진짜 손잡이는 꼬리 강조였다.** `-2 log(1-u)` 의 발산이 probit 보다 낫다.
   **이건 새 방향이다** — 결합 규칙을 "독립이냐" 가 아니라 "꼬리를 얼마나 세게 보느냐" 로
   봐야 한다. 다만 그 강도를 **test 로 고르면 안 된다.** 정상만으로 정하는 방법이
   있는지는 **모른다.**
4. **가중은 12차 사이클이 예고한 방향으로 정확히 움직였다**(Scratch↑ Center↓).
   기작에 대한 이해는 맞았고 **처방이 틀렸다.**

### 미확인

- **꼬리 강도를 정상 데이터만으로 고르는 방법**이 있는지 안 알아봤다.
- 요소를 **클래스별로 다르게** 가중하는 것은 결함 라벨을 쓰는 일이라 **범위 C 다.** 안 한다.
