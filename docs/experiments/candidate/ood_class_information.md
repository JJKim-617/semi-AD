# 후보 — 이 신호들은 결함 **종류**를 아는가 (3단계 준비)

## 무엇을 묻는가

파이프라인은 **탐지 → 국소화 → MLLM 8종 분류 → 질의응답**이다(기획서 §9).
1단계는 여기까지 왔다(blocked AUPR 0.8325). **3단계에 무엇을 넘길지가 다음 질문이다.**

2차 사이클에서 이미 단서가 있었다: 구조 점수 S_llr 은 탐지에는 최악(Edge-Ring 0.023)인데
**결함끼리 놓고 보면 Edge-Ring 대 Scratch 를 AUROC 0.983 으로 갈랐다.**
탐지 성능과 클래스 판별력은 다른 축이라는 것이다.

지금 손에 있는 세 신호는 **설계상 서로 다른 모양을 본다** — A는 전반, B는 선, C는 작은 덩어리.
그렇다면 **결함 종류를 구분하는 정보도 서로 다르게 갖고 있어야 한다.**
이 사이클은 그걸 **잰다**. 분류기를 만들지 않는다.

## 무엇을 재는가

**결함 웨이퍼끼리만** 놓고 8종 중 두 종을 고르는 이진 문제 28쌍에 대해,
각 신호 하나로 매긴 AUROC. **학습이 없다** — 점수를 그대로 순위로 쓴다.
라벨은 **평가에만** 쓴다(기획서 §1).

측정 대상:

| 신호 | 비고 |
|---|---|
| 대조: 불량 다이 개수 | E0. 학습 없음 |
| A: k² 5x5 + 반경보정 | |
| B: 온전창 선 L=11 | |
| C: k² 3x3 | |
| 융합 fuse3 | 탐지 최선 |
| **파생: log(B) - log(C)** | **선다움 대 덩어리다움.** 사전지식을 쓰므로 **범위 B**(기획서 §10) |

`B/C` 비율만 범위 B 다 — "긁힘은 선, Center 는 덩어리" 라는 모양 사전지식을 쓴다.
**A-arm 과 분리 표시한다.**

## 반증 조건 (실행 전 확정)

1. **어떤 신호도 28쌍 중 AUROC >= 0.80 인 쌍을 3개 이상 만들지 못하면,
   이 신호들은 클래스 정보를 실질적으로 안 갖고 있다.** 그러면 3단계는
   원본 웨이퍼맵에서 정보를 얻어야 하고, 맵을 넘기는 값어치가 낮다고 적는다.
2. **A, B, C 가 서로 다른 쌍을 잘 가르지 못하면**(즉 잘 가르는 쌍 집합이 거의 겹치면)
   **"세 맵을 다 넘길 이유" 가 약해진다.** 겹침을 정량으로 낸다.
3. **어떤 신호도 대조군(불량 다이 개수)을 못 넘는 쌍이 과반이면**,
   새 신호가 클래스 정보 면에서는 자명한 기준선 이상이 아니다.
4. **파생 `B/C` 가 Scratch 대 Center 를 AUROC 0.85 이상으로 가르지 못하면**
   그 사전지식은 값어치가 없다고 적는다(범위 B 를 쓸 이유가 없다).
5. **표본이 적은 클래스(Near-full 95, Donut 146, Random 257)는 CI 를 병기**하고,
   CI 폭이 0.15 를 넘으면 그 쌍의 결론을 내지 않는다.

## 실행 전 예측

- **B 가 Scratch 관련 쌍을 잘 가른다.** 선 필터가 선을 보므로.
- **C 가 Center 관련 쌍을 잘 가른다.**
- **불량 다이 개수도 꽤 잘 가른다** — Near-full, Random 은 개수만으로 이미 갈렸으니
  개수 축과 상관된 쌍은 대조군이 강할 것이다.
- **파생 B/C 가 Scratch 대 Center 에서 가장 강할 것이다** (설계상 그러라고 만든 것이다).
- **28쌍 중 상당수는 어떤 신호로도 안 갈릴 것이다** — 특히 Edge-Loc 대 Edge-Ring,
  Loc 대 Edge-Loc 처럼 모양이 이어져 있는 쌍.

## 이것이 아닌 것

- **분류기를 만드는 것이 아니다.** 학습이 없다.
- **8종 macro-F1 을 내는 것이 아니다.** 그건 MLLM 을 붙이는 사이클의 일이다(§9.4).
- 여기 수치는 **"3단계에 무엇을 넘길지" 를 정하는 근거**이지 3단계의 성능이 아니다.

### 한 줄

**탐지력과 클래스 판별력은 다른 축이고, 내 탐지 개선은 클래스 판별로 옮겨가지 않았다.**
자명한 불량 다이 개수가 **여전히 가장 강한 단일 클래스 신호**다(28쌍 중 18쌍).
다만 새 신호들은 **서로 다른 쌍**을 가르고, 설계한 파생 특징 하나는
개수가 원리적으로 못 가르는 쌍(Scratch 대 Center)을 0.909 로 가른다.

### 신호별 요약 (결함끼리 28쌍, 학습 없음)

| 신호 | 분리도 >= 0.80 인 쌍 | 평균 분리도 | 최대 |
|---|---:|---:|---:|
| **대조: 불량 다이 개수 (A)** | **18/28** | **0.8360** | 1.0000 |
| A: k² 5x5 + 반경보정 (A) | 13/28 | 0.7746 | 0.9791 |

| C: k² 3x3 (A) | 12/28 | 0.7603 | 0.9885 |

| 파생 log(B)-log(C) (**B범위**) | 7/28 | 0.7277 | 0.9269 |

### 반증 조건별 판정

**1. 강한 쌍이 3개 이상 있는가 → 전부 있다. 통과.**
최소가 파생 특징의 7쌍이다. **신호들은 클래스 정보를 실제로 갖고 있다.**

**2. 서로 다른 쌍을 가르는가 → 그렇다. 통과. 이게 이 사이클의 주 결과다.**

| 쌍 | 강한 쌍 교집합 / 합집합 | Jaccard |
|---|---:|---:|
| A vs B | 7 / 16 | 0.44 |
| A vs C | 11 / 14 | 0.79 |
| **B vs C** | **5 / 17** | **0.29** |

셋을 합치면 **17/28** 이고 각각은 13, 10, 12 다.
**B 와 C 가 가장 안 겹친다** — 설계대로 선과 덩어리를 따로 본다.
**세 맵을 다 하류로 넘길 근거가 된다.**

**3. 대조군을 과반의 쌍에서 넘는가 → 아니다. 기각.**

| 신호 | 28쌍 중 대조군을 넘는 쌍 |
|---|---:|
| A | 7 |
| B | 6 |
| C | 6 |
| 융합 fuse3 | 6 |
| **파생 log(B)-log(C)** | **10** |

**과반(15)에 한참 못 미친다.** 게다가 세 신호를 합친 17쌍조차 대조군 단독 18쌍보다 적다.

**왜 그런가.** 8종 중 많은 쌍이 **불량이 몇 개나 났는가**로 갈린다
(Near-full 대 무엇이든, Random 대 Scratch). 개수는 그걸 그대로 잰다.
내 신호들은 **크기와 양을 정규화해 없앤 것들**이다 — 백분위, 비율, 창 안 밀도.
**정규화가 탐지를 좋게 만든 바로 그 성질이 클래스 판별에서는 정보를 버린다.**

**4. 파생 `B/C` 가 Scratch 대 Center 를 0.85 이상으로 가르는가 → 통과. 0.9090.**

| 신호 | Scratch 대 Center 분리도 |
|---|---:|
| 대조 불량 다이 개수 | 0.5991 |
| 융합 fuse3 | 0.5845 |
| A | 0.6437 |
| B | 0.7300 |
| C | 0.8058 |
| **파생 log(B)-log(C) (B범위)** | **0.9090** |

**개수는 이 쌍을 거의 못 가른다(0.599). 탐지 최선인 융합도 못 가른다(0.585).**
"긁힘은 선, Center 는 덩어리" 라는 **모양 사전지식을 명시적으로 넣은 특징 하나**가 0.909 를 낸다.
그리고 이 특징의 강한 쌍 7개 중 5개가 `Center|X` 다 — **Center 대 나머지 판별자**로 작동한다.

**이것이 기획서 §10 의 범위 B 가 값어치를 낸 첫 사례다.**
동시에 그 대가도 분명하다 — 이 특징은 **결함 모양을 미리 안다고 가정**한다.

**5. 표본이 적은 클래스는 CI 병기.** Near-full(95), Donut(146), Random(257) 이 낀 쌍에
부트스트랩 CI 를 붙였고 **폭이 0.15 를 넘는 쌍은 없었다.** 결론 보류한 쌍 없음.
(표시 주의: AUROC < 0.5 인 쌍은 분리도를 1-AUROC 로 적고 CI 는 **AUROC 기준**으로 적었다.
예: `Random|Scratch 분리도 0.9722, CI 0.019~0.036` 은 AUROC CI 다.)

## 3단계에 무엇을 넘길 것인가 — 이 사이클의 실질 산출물

**하나로 줄이지 않는다. 어느 것도 지배하지 않는다.**

1. **불량 다이 개수** — 가장 강한 단일 클래스 신호(18/28). 자명하지만 빼면 손해다.
2. **세 요소 맵 A, B, C** — 서로 다른 쌍을 가른다(Jaccard 0.29~0.79).
3. **파생 log(B)-log(C)** — 개수가 못 가르는 Scratch 대 Center 를 가른다.
   **단 범위 B 이므로 A-arm 과 분리 보고한다.**

## 설명 없는 관측

- **왜 융합(fuse3)이 클래스 판별에서는 구성 요소보다 안 나은가.**
  탐지에서는 셋을 합치면 올랐는데 클래스 쌍에서는 13/28 로 A 와 같다.
  Fisher 결합이 "얼마나 이상한가" 한 축으로 접기 때문일 수 있으나 **검증하지 않았다.**
- **B 의 상위 쌍이 왜 `Center|X` 인가.** 선 필터인데 Center 를 잘 가른다.
  Center 가 선 점수를 **낮게** 받아서일 텐데(부호를 보면 그렇다) 그건 "선이 아님" 을
  재는 것이지 "선임" 을 재는 게 아니다. 그 구분을 이번에 안 팠다.
