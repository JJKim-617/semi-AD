# E13 후보 — 선택 지표를 고친다 (모델이 아니라 자를 바꾼다)

작성일 2026-08-22. **실행 전에 쓴다.** 반증 조건을 먼저 박아둔다.

## 문제

지금까지 8 사이클 동안 기법을 골라온 자(尺)가 망가져 있다. val macro-F1 은
test macro-F1 순위를 못 맞힌다.

캐시된 로짓이 있는 수렴 실행 5개로 잰 Spearman 상관이다.

| 선택 지표 | test 순위와의 rho | 1위로 고르는 실행 |
|---|---:|---|
| 현행 val macro-F1 | **+0.100** | e7_ce_long80 (실제 4위, test 0.7088) |

E10 이 더 나쁜 사례를 보여줬다. 같은 설정 3 seed 에서 val 1위(0.9401)가 test 꼴찌(0.6991)다.
**val 로 고르면 최악을 고른다.**

원인은 분포다. val 은 train 분포를 물려받아 결함이 31.9% 인데 test 는 6.7% 다.
val 에서 결함을 적극적으로 예측하는 모델이 유리하지만, test 에서는 none 110,701 장에서
오탐이 조금만 늘어도 결함 precision 이 무너진다. 두 분포에서 좋은 모델이 서로 다르다.

## 가설

val 표본에 `w[y] = q_test[y] / p_val[y]` 를 걸어 가중 macro-F1 을 재면
**test 분포에서의 성능을 val 라벨만으로 근사**할 수 있고, 순위가 맞아떨어진다.

같은 5개 실행에서 이미 확인했다.

| 선택 지표 | test 순위와의 rho | 1위로 고르는 실행 |
|---|---:|---|
| 현행 val macro-F1 | +0.100 | e7_ce_long80 (test 0.7088) |
| **재가중 val, q 를 실제 test 분포로 (oracle)** | **+0.900** | e7_ce_long (test 0.7269, 실제 1위와 0.0071 차) |
| 재가중 val, q 를 classify-and-count 로 추정 | +0.100 | e7_ce_long80 (test 0.7088) |

**메커니즘은 확인됐고 추정기가 문제다.** oracle q 를 쓰면 자가 거의 완벽해지므로
"val 이 근본적으로 못 쓸 물건"이 아니라 "사전확률만 알면 쓸 수 있는 물건"이다.

classify-and-count 가 실패하는 이유도 명확하다. 분류기 자신의 편향을 그대로 물려받는다.

| 클래스 | 실제 test 비율 | CC 추정 | 비 |
|---|---:|---:|---:|
| Edge-Loc | 0.02337 | 0.04505 | **1.93** |
| Scratch | 0.00584 | 0.00922 | **1.58** |
| Donut | 0.00123 | 0.00182 | 1.48 |
| Random | 0.00217 | 0.00139 | **0.64** |
| none | 0.93344 | 0.91220 | 0.98 |

none 이 새어 들어가는 클래스(Edge-Loc, Scratch)에서 정확히 과대추정된다.
이는 CC 의 알려진 편향이고, 그 편향을 보정하는 표준 기법이 BBSE 다.

## 시험할 것

**BBSE** (Lipton et al. 2018, *Detecting and Correcting for Label Shift with Black Box Predictors*).
val 에서 측정한 혼동행렬로 분류기의 오류율을 보정한다.

    C[i,j] = P_val(pred=i, y=j)          # val 라벨 사용 (합법)
    mu[i]  = P_test(pred=i)              # test 라벨 미사용
    C w = mu  를 풀어  q[j] = w[j] * p_val[j]

CC 는 `q = mu` 라고 가정하는 BBSE 의 특수한 경우다(분류기가 완벽할 때만 옳다).

## 반증 조건 (먼저 박아둔다)

1. **BBSE 가 CC 보다 사전확률을 정확히 추정하지 못하면 기각한다.**
   판정: 실제 test 사전확률과의 총변동거리(TV)가 CC 보다 작아야 한다.
2. **추정이 나아져도 순위가 안 맞으면 기각한다.**
   판정: BBSE 재가중 val 의 Spearman 이 **+0.6 이상**이어야 한다.
   (oracle 이 +0.900, 현행이 +0.100 이다. 그 사이 어디에도 못 가면 실용성이 없다.)
3. **표본이 작다는 것을 인정한다.** n=5 에서 rho +0.900 의 단측 p 는 0.037 이다.
   pad 3 seed 의 로짓이 확보되면 n=8 로 재검한다. **n=5 결과만으로 결론 내지 않는다.**
4. **대조군.** 순수 label shift 가정이 깨져 있을 가능성(같은 Scratch 가 train median 52x52,
   test 31x31)을 배제하지 못한다. 따라서 oracle q 를 항상 함께 보고해
   "추정 오차" 와 "가정 위반" 을 분리한다. oracle 조차 rho 가 낮은 데이터가 나오면
   재가중 접근 전체가 이 데이터셋에서 안 되는 것이다.

## 왜 이것이 다른 후보들보다 먼저인가

- **비용이 거의 0 이다.** 학습이 없다. 이미 디스크에 있는 로짓만 쓴다.
- **다른 모든 실험의 전제조건이다.** 자가 틀린 채로 E11(크기 입력), E12(자기지도),
  2단계 계층 분류를 돌리면 결과를 읽을 수 없다. 실제로 지난 8 사이클이 그랬다.
- 2단계 계층 분류는 상한이 0.852 로 크지만, 검토 결과 그 이득의 대부분이
  flat 에서도 가능한 임계값 조정과 겹친다(stage-2 가 새로 고칠 수 있는 것은
  결함↔결함 혼동 702 장뿐이고 flat 은 이미 그 구간에서 88.7% 를 맞힌다).
  선택 지표를 고친 뒤에 다시 판단한다.

## 이것이 성공하면 따라오는 것

지금까지 "효과 없음" 으로 기록한 기법 중 일부는 **효과가 없었던 게 아니라
잘못된 체크포인트를 골랐던 것**일 수 있다. 재가중 val 로 기존 실행들의
체크포인트를 다시 고르면 재학습 없이 개선될 가능성이 있다. 그것부터 확인한다.

# 결과 — 기각 (2026-08-22)

## 반증 조건 1, 2 모두 실패

| | 요구 | 실측 | 판정 |
|---|---|---:|---|
| BBSE 의 사전확률 추정이 CC 보다 정확 | TV 가 더 작아야 | 0.0129 vs CC 0.0128 | **실패** |
| BBSE 재가중 val 의 순위 상관 | rho >= +0.6 | **+0.100** | **실패** |

BBSE 는 CC 를 전혀 개선하지 못했다. 그런데 oracle q 는 여전히 +0.900 이므로
"q 를 알면 자가 고쳐진다" 는 사실 자체는 유지된다. 문제는 필요한 정밀도다.
TV 0.013 이라는 **작은 절대오차가 순위를 완전히 파괴한다.** 가중치가 q/p_val 이라
문제가 되는 것은 절대오차가 아니라 비율오차이고, 참 비율이 0.0008 인 Near-full 에서
비율오차가 폭발하기 때문이다.

## 사후 발견과 그 기각

축을 쪼개보니 순위 능력의 대부분이 **결함률 하나**에서 나왔다.

| 보정 | rho | 1위로 고르는 실행 |
|---|---:|---|
| 없음 (현행 val) | +0.100 | 실제 4위 |
| **결함률만** | **+0.700** | **실제 1위** |
| 구성만 | +0.300 | 실제 2위 |
| 둘 다 (oracle) | +0.900 | 실제 2위 |

결함률은 숫자 하나라 이진 BBSE 로 정확히 추정된다(추정 0.0637~0.0929, 참값 0.0666).
무라벨 추정을 써도 rho +0.600 이 나왔다. 여기까지는 좋아 보였다.

**그러나 이 발견은 사후적이고, held-out 에서 무너졌다.** 발견에 쓰지 않은
pad 3 seed 로 검증했다.

| | 현행 val | 결함률 보정 val | 실제 1위 |
|---|---|---|---|
| pad 3 seed (held-out) | rho -0.500, seed 1 선택 | rho **-0.500**, seed 2 선택 | seed 0 |
| 전체 8 실행 | rho +0.024 | rho +0.262 | seed 0 |

**결함률 보정도 held-out 에서 실패한다.** 5개 실행에서 얻은 +0.700 은 5개 점에
과적합한 것이었다. 두 접근 모두 기각한다.

## 왜 실패했는가 — 재가중으로는 못 고치는 문제였다

진단이 틀렸다. 문제는 val 의 **분포**가 아니라 val 의 **표본**이다.
재가중은 val 이 이미 가진 답의 무게를 바꿀 뿐, 없는 정보를 만들지 못한다.

pad 3 seed 를 val 과 test 에서 나란히 보면 명확하다.

| 클래스 | val 장수 | val F1 범위 | test 장수 | test F1 범위 |
|---|---:|---:|---:|---:|
| **Scratch** | **92** | 0.110 | 693 | **0.334** |
| Near-full | **9** | **0.000** | 95 | 0.130 |
| Edge-Loc | 502 | 0.023 | 2,772 | 0.094 |
| none | 7,581 | 0.001 | 110,701 | 0.014 |

붕괴의 원인인 none 누출을 직접 비교하면 결정적이다.

| none -> Scratch 오검출 | seed 0 | seed 1 | seed 2 |
|---|---:|---:|---:|
| val (none 7,581장 중) | 26 | **24** | 2 |
| test (none 110,701장 중) | 292 | **2,007** | 115 |

**test 에서 붕괴하는 seed 1 이 val 에서는 26 대 24 로 seed 0 과 구별되지 않는다.**
val 의 none 이 7,581 장뿐이라 1.8% 누출은 136 장 규모여야 보이는데,
실제로 val 에서 그런 일이 일어나지 않는다. 신호가 애초에 없다.

게다가 val 은 포화돼 있다. 9개 클래스 F1 이 전부 0.84 이상이고 대부분 0.95 이상이라
seed 간 차이를 잴 해상도가 없다.

## 남는 결론

**이 데이터셋의 공식 split 에서는 val 기반 설정 선택이 성립하지 않는다.**
재가중으로도, 더 나은 사전확률 추정으로도 고칠 수 없다.
Training 에서 잘라낸 val 은 (a) 희소 클래스 표본이 수십 장 수준이고
(b) test 와 P(x|y) 가 다르며 (c) 포화돼 있다.

따라서 실행 규약을 바꾼다.

1. **고르지 않는다.** 설정마다 3 seed 를 돌리고 평균과 범위를 보고한다.
2. **선택 대신 집계한다.** 앙상블은 고를 필요가 없다 —
   그리고 실제로 통했다(아래 앙상블 결과 참조, +0.0303).
3. val 은 한 실행 안에서 epoch 를 고르는 데만 계속 쓴다(그 용도는 E9 에서 검증됐다).
