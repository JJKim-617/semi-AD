# E25 후보 — 준지도 학습 (미라벨 638,507장)

작성일 2026-08-23 (18차), **실행 전에 쓴다. 이 문서를 쓰는 시점에 E25 학습은 0 런이다.**
**18차는 이것을 돌리지 않는다** — 마감 안에 3 seed 가 안 들어간다.
다음 사이클을 위한 사전 등록이다.

## 왜 — 18차가 남긴 그림

이번 사이클이 확인한 것들이 이 방향을 가리킨다.

1. **앙상블은 포화했다.** k=4 에서 0.7903, k=25 에서 0.7957.
   **새 구성원을 만드는 실험은 전부 같은 벽에 부딪힌다**(E20, E21, E22 가 그 증거).
2. **운영점은 이미 최적이다.** 오라클로 훑어도 b=0 이 최선이다.
3. **이진 판별은 AUROC 0.983 이고 남은 것은 꼬리 2,457장**(오검출 903 + 미검출 1,554)이다.
4. **미검출은 어떤 조리법으로도 안 움직인다**(±13%). 그리고 **미검출된 결함은
   불변 기술자 공간에서 none 이웃에 81% 둘러싸여 있다** — 겹침 영역에 산다.
5. **손으로 만든 신호는 전부 닫혔다**(밀도, 선, lot, 크기, 극좌표).

**남은 것은 "겹침 영역에서 결함과 none 을 가르는 새 정보" 이고,
쓰지 않은 자원이 하나 있다 — 미라벨 638,507장이다.**

| | 장수 |
|---|---:|
| 라벨된 학습 | 43,223 |
| **미라벨** | **638,507** |
| 배율 | **14.8배** |

`data/wm811k/cache/wm811k_64pad_all.npz` 에 **이미 캐시돼 있다**(라벨 표현과 동일한 pad64).

## 이것은 닫힌 축이 아니다

**자기지도 사전학습(E12)은 닫혀 있다** — SimCLR 식으로 인코더를 미리 학습하고
미세조정하는 것이었고 0.687~0.711 로 실패했다.

**준지도는 다른 것이다.** 사전학습이 아니라 **라벨된 손실과 미라벨 손실을 같이 최적화**한다.
미라벨 표본이 **결정 경계를 직접 민다**.

**레포에 이 축의 실험이나 조사는 없다. 다만 "언급" 은 있다** — 정확히 적는다.
`docs/plans/ad_baseline_plan.md` 의 **"9. 범위 밖 (향후 과제)"** 에
*"미라벨 638K를 이용한 자기지도/준지도 학습"* 이 들어 있고,
`docs/specs/data_cache.md` 가 미라벨 캐시를 *"자기지도/준지도용"* 이라고 적어 뒀다.

**즉 이것은 놓친 것이 아니라 처음부터 범위 밖으로 정해 둔 것이다.**
여는 것은 **범위 결정**이지 빈틈을 메우는 것이 아니다.
자기지도 쪽(E12)은 그 뒤 실제로 열렸다가 닫혔고, **준지도 쪽은 열린 적이 없다.**

## 무엇을 돌리나

`configs/cls_e17.yaml` 기반(resnet18, pad64, dihedral, translate). 바뀌는 것은 손실 하나.

**FixMatch 식 일관성 정칙화**를 쓴다.

- **약한 증강** = dihedral (기준선이 이미 쓰는 것)
- **강한 증강** = dihedral + translate
- 미라벨 배치에서 약한 판의 예측이 임계 `tau` 를 넘으면 그것을 의사 라벨로 삼아
  **강한 판**에 교차엔트로피를 건다.

> **이 데이터에서 강한 증강을 고를 여지가 거의 없다는 것을 밝힌다.**
> 18차가 확인한 대로 **라벨을 보존하는 변환은 dihedral 과 정수 이동 둘뿐**이다.
> scale, noise, dropout 은 라벨을 깨고(누출을 1.3~3.9배로 늘린다),
> 자유 각도 회전은 격자를 부순다(불량 다이 2.3~3.3% 손실).
> **따라서 "강한 증강" 이 약한 증강보다 아주 조금만 강하다.**
> **이것이 이 실험의 가장 큰 구조적 약점이고, 실패하면 첫 번째 용의자다.**

| 팔 | 조건 | seed |
|---|---|---|
| **A** | translate + 준지도 (미라벨 사용) | 0,1,2 |
| 대조군 | `e17_translate_s0~3` (이미 있다, 0.7645) | — |

## 반증 조건 — **실행 전에 박는다**

### H1 — 단독 성능

- 대조군 `e17_translate` 4 seed 평균 **0.7645**, seed 범위 **0.0067**.
- **채택 방향**: 팔 A 3 seed 평균이 **0.7712**(= 0.7645 + 0.0067) 초과.
- **반증**: 0.7645 이하이면 미라벨이 아무것도 안 준 것이다.

### H2 — **이 실험의 진짜 물음. 미검출을 움직이는가**

18차가 잰 것: **어떤 조리법도 미검출을 1,296~1,625 밖으로 못 움직였다**
(오검출은 1,105~7,496 으로 7배 움직였는데도).

- **채택**: 미검출 **1,250 미만** (지금까지 관측된 최소 1,296 아래).
- **반증**: 1,296~1,625 대역 안이면 **준지도도 그 벽을 못 넘는 것**이고,
  **"미검출은 학습 조리법으로 안 움직인다" 가 한 단계 더 강해진다.**
- **어느 쪽이든 값어치가 있다.** 지금까지 그 벽을 시험한 것 중 가장 다른 종류의 개입이다.

### H3 — **판정 기준을 바꾼다. 이유를 적는다**

**E20, E21, E22 를 판정한 "LOO >= +0.003" 을 그대로 쓰지 않는다.**
18차가 그 선이 **지금 풀에서 도달 불가능**함을 쟀기 때문이다 —
구성원 하나의 평균 기여가 **+0.0002** 이고, 개별 LOO 는 **seed 잡음**이 지배한다
(seed 안 sd 0.0018 > 백본 사이 sd 0.0011).

**대신 이진 오류 총합을 쓴다.** 그것이 상한을 정하는 양이고 운영점에 불변이 아니다.

| | 오검출 | 미검출 | 합 |
|---|---:|---:|---:|
| 무증강 대조군 | 1,925 | 1,608 | 3,533 |
| **translate (기준)** | **1,190** | **1,436** | **2,627** |

- **채택: 팔 A 의 이진 오류 합 < 2,527** (translate 대비 100장 이상 감소).
- **기각: 2,527 이상.**
- **반드시 두 방향을 같이 보고한다** — 한쪽만 줄고 다른 쪽이 늘면 운영점을 옮긴 것이다.

### H4 — 확증 편향 점검 (**실패 모드를 미리 박는다**)

의사 라벨은 **지금 모델의 예측**이다. 그런데 그 모델은
**16배짜리 반지름 규칙**을 따르고 오류가 겹침 영역에 몰려 있다.
**미라벨에 의사 라벨을 붙이면 그 규칙이 증폭될 수 있다.**

- **점검**: 국소 3종 오검출률의 **Q5/Q1 기울기**를 잰다. 대조군(건강) **1.71**, translate **1.67**.
- **경고 신호**: 팔 A 의 기울기가 **1.9 초과**면 확증 편향이 일어난 것이고,
  H1/H2 가 통과하더라도 **그 사실을 결론에 반드시 적는다.**

## 실행 전에 밝히는 한계

1. **미라벨 638,507장의 참 클래스 분포를 모른다.** 라벨된 부분이 93% none 이므로
   미라벨도 그럴 가능성이 높고, 그러면 **의사 라벨이 none 으로 쏠려 미검출을 악화**시킬 수 있다.
   `tau` 를 넘는 표본의 클래스 분포를 **반드시 같이 보고한다.**
2. **강한 증강이 약하다**(위 상자). 이 실험의 최대 약점이다.
3. **`tau` 를 고르는 것은 하이퍼파라미터 조정이다.** 하나로 고정하고
   (문헌 관례인 0.95) **여러 값을 시험해 고르지 않는다.** 안 되면 안 되는 것으로 적는다.
4. **비용**: 미라벨이 14.8배라 에폭당 시간이 크게 는다. **1 에폭 스모크 테스트를 먼저 하고
   실제 소요를 재서 3 seed 가 들어가는지 확인한 뒤 큐를 건다.**
5. 나는 **H1 은 아슬아슬하고 H2 는 실패할 것**으로 본다. 미검출이 안 움직인 이유가
   조리법이 아니라 **겹침 그 자체**라면 미라벨을 더 넣어도 같은 겹침을 더 볼 뿐이다.
   **그래도 시험할 값어치가 있다** — 지금까지 그 벽을 친 것 중 가장 다른 개입이고,
   실패하면 **"겹침이 본질" 이라는 쪽이 크게 강해진다.**

## 비용 측정 결과 (18차에 실측, 2026-08-23 20:55)

후보 문서가 비용을 "모른다, 스모크로 재고 큐를 걸어라" 로 남겨 뒀으므로 **재서 넘긴다.**

### mu=7, batch 256 은 **메모리에 안 들어간다**

`torch.OutOfMemoryError` — 스텝당 256 + 256x7x2 = **4,096장**이 한 번에 통과한다.
24GB 로 부족하다. **이것은 튜닝 선택이 아니라 하드웨어 제약이다.**

### 들어가는 설정과 실측

| | 값 |
|---|---|
| 설정 | **batch 128, mu=3** (스텝당 128 + 128x3x2 = 896장) |
| 스텝당 | **463 ms** |
| 에폭당 | **156 초** (337 스텝) |
| 40 에폭 | **1.74 시간** |
| **3 seed** | **5.21 시간** |

**한 사이클(14시간) 안에 충분히 들어간다.**
참고로 라벨만 쓰는 기준선은 에폭당 35초이므로 **약 4.5배**다.

### tau 를 넘는 미라벨 비율

**학습 초기 모델에서 24.1%** 다. 학습이 진행되면 오른다.
**0% 가 아니라는 것이 중요하다** — 일관성 손실이 처음부터 신호를 준다는 뜻이다.
다만 **초기의 24.1% 는 대부분 none 일 가능성이 높다**(후보 문서 한계 1번).
**tau 를 넘은 표본의 클래스 분포를 반드시 같이 보고해야 한다.**

### 18차가 안 돌린 이유

**측정 시점이 20:55 이고 마감이 05:30 이었다.** 5.21시간 학습은 들어가지만,
**제대로 된 학습 스크립트**(cosine 일정, val 기반 체크포인트 선택, 평가 연결)를
그 시각에 새로 쓰고 스모크까지 돌린 뒤 시작해야 했다.
`src/a26_semisup.py` 의 `main()` 은 **비용 측정용 하네스**이지 학습 스크립트가 아니다.

**급하게 쓴 학습 루프가 조용히 틀리면 결과가 없는 것보다 나쁘다** —
이 사이클에서 그런 종류의 오염을 다섯 번 잡았다.
**사전 등록 + 구현 + 시험 + 실측 비용까지 넘기는 편이 낫다고 판단했다.**

## 학습 스크립트 완성 (18차 마무리, 2026-08-24 02:45). **여전히 안 돌렸다**

앞 절에서 "없는 것 = 학습 스크립트" 라고 적었다. **그것을 썼다.**

### 무엇을 만들었나

| | 위치 |
|---|---|
| 배선 | `a3_train_wm811k_cls.train_one_epoch(..., unlabeled=, mu=, tau=, lambda_u=)` |
| 배선 시험 6개 | `tests/test_a3_semisup_wiring.py` |
| CLI | `--unlabeled-cache --mu --tau --lambda-u` |
| 실행 스크립트 | `exe/run_e25.sh` (`--smoke` 로 1에폭 확인 가능) |

**새 학습 스크립트를 따로 쓰지 않고 `a3` 안에 넣었다.**
cosine 일정, warmup, **val 기반 체크포인트 선택**, `a4` 평가 연결이 **이미 거기 있고
시험돼 있기** 때문이다. 급하게 쓴 학습 루프가 조용히 틀리는 것이 이 프로젝트에서
가장 비싼 사고이고, 이번 사이클에 그런 오염을 다섯 번 잡았다.

**가장 중요한 시험**: `unlabeled=None` 이면 **비트 단위로 예전과 같다.**
바뀌면 기존 체크포인트 42개의 재현이 깨진다. 시험으로 박았다.
**`tau` 를 1 초과로 두면 통과 표본이 없어 라벨 전용과 완전히 같아진다**는 것도 박았다 —
일관성 항이 마스크를 정말 존중하는지를 가르는 시험이다.

### 1에폭 스모크 통과

```
[semisup] 미라벨 638,507장 (라벨 학습의 14.8배)  mu=3 tau=0.95 lambda_u=1.0
  ep  1  loss 0.2317  val macro-F1 0.5939  acc 0.9059 *
[done] best val macro-F1 0.5939  (155s)
```

**에폭당 155초로 사전 실측(156초)과 일치한다. 40에폭 1.72시간, 3 seed 5.17시간.**

### **새로 드러난 교란 — 반드시 대조군을 하나 더 돌려야 한다**

**E25 는 batch 128 로 돌 수밖에 없다**(mu=3 에서 그것이 24GB 상한이다).
그런데 **대조군 `e17_translate` 는 batch 256** 이다.

> **batch 크기가 다르면 그 차이가 준지도의 효과로 오인된다.**
> **다음 세션은 `--batch-size 128` 로 translate 대조군을 3 seed 먼저 돌려야 한다.**
> 없으면 E25 가 무엇을 보였든 해석할 수 없다.

이것은 **18차가 스모크를 돌리다 발견한 것**이고 사전 등록 당시에는 몰랐다.
**반증 조건을 바꾸는 것이 아니라 대조군을 추가하는 것이므로 설계를 강화한다.**

### 판정할 때 같이 볼 것

사전 등록한 **이진 오류 총합**(translate 기준 2,626)은 **batch 128 대조군 기준으로
다시 잡아야 한다.** 그 값이 나오기 전에는 절대 기준을 쓰지 말고
**batch 를 맞춘 대조군과의 차이**로만 판정한다.

그리고 **tau 를 넘은 미라벨의 클래스 분포를 반드시 보고한다**(한계 1번).
초기 모델에서 통과율이 24.1% 였는데 **그 대부분이 none 일 가능성이 높고,
그러면 의사 라벨이 none 으로 쏠려 미검출을 악화시킨다.**

## 그 batch 대조군은 **18차가 돌렸다** (E27, 2026-08-24 03:13)

위에서 *"다음 세션은 `--batch-size 128` translate 대조군을 3 seed 먼저 돌려야 한다"* 고
적었다. **18차가 마감 전에 돌렸다.** 상세는
[batch_control.md](batch_control.md).

**결과: 사전 등록한 네 통계가 모두 batch 256 의 seed 범위 안 -> 구분되지 않는다.**
(macro-F1 0.7670, 오검출 1,044, 미검출 1,560, 이진 총합 **2,605**. 단측 치환 p 0.229.)

**그러므로 E25 를 기존 batch 256 대조군과 견줘도 해석이 깨지지 않는다.**
**다만 기준점은 옳은 대조군에 다시 묶었다:**

> ### **E25 채택선 = 이진 오류 총합 < 2,505**
> (batch 128 대조군 **2,605** 대비 100장 감소. 위에 적힌 2,626 은 batch 256 기준이다.)
> **반증 조건의 형태("대조군 대비 100장 이상 감소")는 그대로이고,
> 그 "대조군" 이 무엇인지가 정확해진 것이다.**

**그리고 18차가 마감 전에 E27 을 6 seed 로 넓혔다.**
`null_resolution(10,6)` = C=210, 양측 최소 p **0.0095** -> **alpha=0.05 도달 가능**,
**그 상태에서도 주 통계 양측 치환 p = 0.2619 로 못 갈랐다.**

> ### **E25 채택선(최종) = 이진 오류 총합 < 2,482**
