# 후보 — 95% 재현율에 남은 19,027장은 모델 탓인가 라벨 탓인가

**반증 조건은 실행 전에 적는다.** 판정은 아래 별도 절에 append 한다.
작성 2026-08-23 03:5x KST (실행 전).

## 무엇을 묻는가

클래스별 병목은 사라졌다(최저 Scratch 0.9251). **남은 병목은 운영 지점**이다 —
결함 95% 를 잡으려면 아직 **정상 19,027장**을 같이 띄운다.

그 19,027장이 **모델이 아직 못 가른 것**인지, **라벨이 원래 그런 것**인지를 안 쟀다.
2차 사이클에서 이미 실마리가 있었다:

> `none` 은 "불량 다이가 없다" 가 아니라 **"알아볼 만한 패턴이 없다"** 이다.
> 정상의 불량 다이 비율 중앙값이 0.0883, Scratch 가 0.1037 이다.

**둘은 대응이 완전히 다르다.** 모델 탓이면 더 나은 표현을 찾으면 되고,
라벨 탓이면 **웨이퍼맵만으로는 못 넘는 천장**이라 다른 정보(공정 이력 등)가 필요하다.

## 무엇을 재는가

fuse3 의 95% 재현율 문턱에서 갈라 두 집단을 본다.

- **헛경보 정상** 약 19,000장
- **놓친 결함** 약 395장 (결함 7,894 의 5%)

각각을 **독립적인 자명한 자**로 잰다 — fuse3 자신이 아니라 **불량 다이 개수/비율**로.
자기 점수로 자기 오류를 설명하면 순환이다.

## 반증 조건 (실행 전 확정)

1. **헛경보 정상의 과반이 "참 결함 하위 25% 보다 불량 다이 비율이 높다" 면,
   그 웨이퍼들은 독립적인 자로 봐도 결함처럼 보인다** → 천장은 상당 부분 라벨 탓이다.
   과반에 못 미치면 모델 탓이 크다고 적는다.
2. **놓친 결함의 과반이 "정상 중앙값(0.0883)보다 불량 다이 비율이 낮다" 면,
   그것들은 웨이퍼맵에 볼 것이 거의 없는 것**이다 → 표현을 바꿔도 못 잡는다.
3. **놓친 결함의 클래스 분포가 전체 결함 분포와 크게 다르면**(특정 클래스에 몰리면)
   그 클래스가 남은 표적이다. 고르게 퍼져 있으면 **클래스별 접근은 끝났다**고 적는다.
4. **헛경보 정상이 특정 lot 에 몰려 있으면** 그건 웨이퍼 단위가 아니라 **lot 단위 현상**이다.
   상위 10개 lot 이 헛경보의 20% 를 넘으면 그렇게 적는다.
5. 위 판정은 **fuse3 점수를 쓰지 않고** 내린다. 문턱 결정에만 쓴다.

## 실행 전 예측

- **조건 1 은 참일 것이다.** 2차 사이클의 밀도 겹침(정상 39.7% 가 불량률 0.10 초과)을 보면
  헛경보 다수가 진짜로 불량이 많은 웨이퍼일 것이다.
- **조건 2 도 참일 것이다.** 6차 그림에서 놓친 Scratch 의 불량률이 0.016~0.051 이었다.
- **놓친 결함은 Scratch 와 Loc 에 조금 더 몰릴 것이다** — 가장 옅은 결함들이다.
- **lot 쏠림은 약할 것이다.** 웨이퍼 단위 현상으로 본다.

## 이것이 아닌 것

- 새 채점기를 만드는 것이 아니다. **진단이다.**
- 여기서 나온 수치로 arm 을 고르지 않는다. **다음 사이클의 방향을 정하는 데만 쓴다.**

### 한 줄

**남은 오류는 대부분 모델 탓이 아니다.**
헛경보 정상의 **78%** 는 독립적인 자로 봐도 결함처럼 보이고,
놓친 결함의 **51%** 는 정상 중앙값보다도 불량 다이가 적다.
**웨이퍼맵만으로 도달 가능한 천장에 가까이 왔다.**

95% 재현율 문턱에서 헛경보 정상 **19,028장**, 놓친 결함 **393장**.
(운영 지점 표의 19,027장은 문턱 **직전까지의 누적** 개수이고, 여기 19,028장은
`점수 >= 문턱` 으로 센 것이다. 문턱에 18장이 동점이라 1장 차이가 난다.)

### 조건 1 — 헛경보는 진짜로 결함처럼 생겼다

독립적인 자(불량 다이 비율, fuse3 를 안 씀)로 재면:

| | 참 결함 하위 25%(0.1060)보다 불량률이 높은 비율 |
|---|---:|
| **헛경보 정상 19,028장** | **0.7804** |
| 전체 정상 110,701장 | 0.3488 |

**헛경보로 걸린 정상의 78% 가 "참 결함 넷 중 하나보다 불량 다이가 많은" 웨이퍼다.**
전체 정상에서는 35% 인데 헛경보 집단에서는 78% 다 — **채점기가 임의로 고른 게 아니다.**

`none` 은 "불량 다이가 없다" 가 아니라 **"알아볼 만한 패턴이 없다"** 이므로
(2차 사이클), 불량이 많아도 패턴이 없으면 none 이다.
**그 웨이퍼들을 결함과 가르는 정보는 웨이퍼맵에 없을 수 있다.**

### 조건 2 — 놓친 결함은 볼 것이 거의 없다

| | 불량 다이 비율 분위 [10, 50, 90] |
|---|---|
| 놓친 결함 393장 | 0.0396 / **0.0867** / 0.1477 |
| 전체 결함 7,894장 | 0.0785 / 0.1484 / 0.2857 |

**놓친 결함의 51.40% 가 정상 중앙값(0.0883)보다도 불량률이 낮다.**
중앙값이 0.0867 로 **정상 중앙값보다 낮다.**
6차 사이클 그림에서 본 것과 일치한다 — 놓친 Scratch 는 선이 너무 옅어 창에 안 잡혔다.
**표현을 바꿔도 안 잡힌다.**

### 조건 3 — 클래스별로는 퍼져 있다, 다만 셋이 두드러진다

| 클래스 | 전체 | 놓침 | 놓침률 | 놓친 것 중 몫 |
|---|---:|---:|---:|---:|
| **Scratch** | 693 | 94 | **0.1356** | 0.2392 |
| **Center** | 832 | 87 | **0.1046** | 0.2214 |
| **Edge-Ring** | 1,126 | 101 | **0.0897** | 0.2570 |
| Loc | 1,973 | 48 | 0.0243 | 0.1221 |
| Edge-Loc | 2,772 | 63 | 0.0227 | 0.1603 |
| Donut / Random / Near-full | 549 | **0** | 0.0000 | 0.0000 |

**Donut, Random, Near-full 은 한 장도 안 놓친다.**
남은 것은 Scratch, Center, Edge-Ring 셋인데 **셋이 고르게 나눠 갖는다**(0.22~0.26).
**"한 클래스만 고치면 되는" 상황이 아니다.**

Edge-Ring 이 여기 낀 것은 **대가의 증거다** — 융합이 가장자리를 눌러서
Edge-Ring 이 die k=7 의 0.9692 에서 0.9540 으로 내려왔고, 그 손실이 여기 나타난다.

### 조건 4 — lot 쏠림은 없다

헛경보가 **4,025개 lot** 에 퍼져 있다(전체 정상 lot 4,937개).
**상위 10개 lot 이 헛경보의 1.24% 뿐**이다(기준 20%).
**웨이퍼 단위 현상이지 lot 단위가 아니다** — lot 수준 정보로 걷어낼 수 있는 게 아니다.

## 이것이 다음 단계에 뜻하는 것

1. **웨이퍼맵만 쓰는 한 큰 이득은 안 남았다.** 헛경보의 78% 는 라벨 정의상
   결함과 구분되지 않고, 놓친 것의 51% 는 볼 것이 없다.
2. **더 나은 표현보다 더 많은 정보가 필요하다** — 공정 이력, 인접 웨이퍼, lot 문맥.
   다만 lot 쏠림이 없으므로 **단순한 lot 집계로는 안 된다.**
3. **Edge-Ring 손실은 융합의 대가다.** 되돌리려면 가장자리를 덜 누르는 arm 을
   융합에 하나 더 넣는 방향인데, 그러면 헛경보가 는다. **저울질이지 개선이 아니다.**
4. **O2/O3(학습된 표현)의 기대치를 낮춰 잡아야 한다.** 학습이 고칠 수 있는 몫은
   놓친 결함의 49%(볼 것이 남은 쪽)와 헛경보의 22% 정도가 상한이다.

## 설명 없는 관측

- **왜 Center 가 놓침률 2위(10.46%)인가.** Center 는 융합 AUROC 0.9412 로 높은 편인데
  95% 문턱에서는 많이 놓친다. 꼬리가 두꺼운 것 같은데 분해하지 않았다.
- 헛경보 정상의 78% 라는 수치가 **문턱에 얼마나 민감한지** 재지 않았다.
  90% 나 99% 재현율에서도 같은지 모른다.
