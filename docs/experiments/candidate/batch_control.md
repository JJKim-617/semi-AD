# E27 — batch 128 대조군 (E25 설계를 완성하는 것)

작성일 2026-08-24 02:00 (18차 마무리), **실행 전에 쓴다. 이 시점에 E27 학습은 0 런이다.**

## 왜 — 새 축이 아니다

E25(준지도)의 스모크를 돌리다 찾은 것:

> **E25 는 `batch 128` 로 돌 수밖에 없다**(mu=3 에서 24GB 상한. mu=7, batch 256 은 OOM).
> **그런데 대조군 `e17_translate` 는 `batch 256` 이다.**

**batch 차이가 준지도의 효과로 오인된다.** 이 대조군이 없으면 다음 세션이
5.17시간을 써서 E25 를 돌려도 **결과를 해석할 수 없다.**
**E25 설계의 빠진 조각을 채우는 것이지 새 축을 여는 것이 아니다.**

## 무엇을 돌리나

`configs/cls_e17.yaml` + `--extra-augment translate`, **`--batch-size 128` 하나만 바꾼다.**
나머지(pad64, dihedral, Adam 1e-3, 40 epoch, cosine, warmup 3)는 `e17_translate` 와 동일.
**seed 0, 1, 2. 태그 `e27_b128_s{seed}`.**

**대조군의 대조군이므로 다른 것을 같이 바꾸지 않는다.** 그것이 이 실험의 전부다.

비용 실측(1에폭): **38초/에폭** -> 40에폭 약 26분 -> **3 seed 약 82분.**
(batch 256 은 35초/에폭이었다. 거의 같다.)

## 무엇을 묻나 — **어느 쪽이 나은가가 아니다**

> **묻는 것: batch 128 이 batch 256 과 다른가.**

- **다르지 않으면** 좋은 소식이다. E25 를 **기존 batch 256 대조군과 비교해도 되고**,
  사전 등록한 이진 오류 총합 기준 **2,626 이 그대로 선다.**
- **다르면** 그 차이만큼이 **E25 판정에서 걷어내야 할 몫**이고,
  기준점을 **batch 128 값으로 다시 묶어야 한다.**

## 실행 전에 정하는 통계 (넷)

`e17_translate` 4 seed 를 기준으로 아래 넷을 나란히 낸다.

| 통계 | batch 256 기준값 | seed 범위 |
|---|---:|---|
| 단독 macro-F1 | 0.7645 | 0.7607 ~ 0.7674 |
| **오검출** (none -> 결함) | **1,190** | 875 ~ 1,527 |
| **미검출** (결함 -> none) | **1,436** | — |
| **이진 오류 총합** | **2,626** | — |

**판정 규칙(실행 전에 박는다)**

1. **각 통계에서 batch 128 3 seed 의 군 평균이 batch 256 의 seed 범위 안에 들면
   "구분되지 않는다"** 로 읽는다.
2. **범위 밖이면 "다르다"** 로 읽고, **그 차이를 E25 판정에서 걷어낼 몫으로 기록한다.**
3. **이진 오류 총합의 기준점을 batch 128 값으로 다시 묶는다** —
   차이가 있든 없든 **옳은 대조군에 묶는 것**이 맞다.

## **먼저 밝힌다 — 이 비교는 형식 검정을 할 해상도가 없다**

오늘 유도한 규칙을 여기에 그대로 적용한다
([research/loo_criterion](../../research/loo_criterion/README.md)).

`null_resolution(N=7, g=3)` = **C(7,3) = 35 가지, 최소 단측 p = 0.0286.**
**양측으로는 최소 p 가 0.057 이라 alpha=0.05 를 만들 수 없다.**

> **그러므로 이 대조군에서 "유의한 차이" 를 주장하지 않는다.**
> **기술 통계(군 평균과 범위 겹침)로만 읽고, 그 한계를 결론에 적는다.**
> 이것은 실패가 아니라 **설계 단계에서 해상도를 확인하라는 오늘의 규칙을 지킨 것**이다.
> (E24 팔 A 는 그것을 안 해서 판정 불가능한 설계가 됐다.)

**그리고 이 실험의 목적은 유의성이 아니라 크기다** — E25 가 보여야 할 효과
(이진 오류 총합 100장 감소) 대비 batch 차이가 얼마나 큰지가 실제 질문이다.

## 실행 전에 밝히는 한계

1. **3 seed 다.** 오늘 배운 대로 대조군은 6 seed 가 바람직하지만
   마감까지 82분짜리 큐 하나가 한계다. **6 seed 로 넓히는 것은 다음 세션 몫이다.**
2. **batch 를 바꾸면 유효 학습률도 바뀐다.** lr 을 함께 조정하지 **않았다** —
   그것이 `e17_translate` 와의 유일한 차이를 batch 하나로 유지하는 방법이다.
   **따라서 여기서 "batch 효과" 는 "batch + 유효 lr 효과" 다.** 결론에 그대로 적는다.
3. 나는 **차이가 작을 것**으로 본다. 이 데이터셋에서 batch 는 성능을 크게 가르지
   않았고(17차에 convnext 만 batch 64 로 돌았는데 단독 0.7476 으로 정상 범위였다),
   38초 대 35초로 스텝 수가 두 배인데 에폭 시간이 비슷한 것도 GPU 가 놀고 있었다는 뜻이다.
