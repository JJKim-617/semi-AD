# O2 — 자기지도 인코더 + kNN, 착수 전 사전등록

작성 2026-08-23 04:55, 브랜치 `exp/ood-oneclass`. **한 줄도 실행하기 전에 쓴다.**
이 문서가 없으면 O2 를 시작하지 마라. 판정은 §8 에 append 한다.

## 1. 무엇을 묻는가 — 질문이 바뀌었다

원래 질문은 "학습된 표현이 자명한 기준선을 넘는가" 였다. 그건 이미 답이 나왔다 —
**학습이 0 인 창 통계가 blocked AUPR 0.8325 를 낸다.** 그래서 O2 의 질문은 이것이다.

> **웨이퍼맵에서 학습이 더 짜낼 것이 남아 있는가, 아니면 남은 오류는 라벨의 성질인가.**

10차 사이클 진단이 후자 쪽을 가리킨다(§3). **그래서 O2 는 "성능을 올리는 사이클" 이 아니라
"천장이 진짜인지 재는 사이클" 이다.** 이 프레이밍을 실행 전에 박아 둔다 —
안 그러면 결과가 나쁠 때 "더 큰 모델로" 로 흘러간다.

## 2. 넘어야 하는 것 — 전부 학습이 0 인 방법이 낸 값이다

| | 값 | 출처 |
|---|---:|---|
| **주 지표 blocked AUPR** | **0.8325** (dev test 에서 잰 편향된 값) | `result/ood/o1_fuse3/` |
| FPR@95TPR | **0.1719** | 〃 |
| 재현율 80% precision / 헛경보 | **0.695 / 2,778장** | 〃 |
| Scratch / Center / Loc AUROC | **0.9251 / 0.9412 / 0.9830** | 〃 |
| 고유값 개수 | 3,953 | 〃 |

**0.8325 는 봉인 홀드아웃 이전의 숫자라 낙관적으로 편향돼 있다**
(`candidate/ood_sealed_holdout.md` 참조). O2 는 **같은 자로 잰 값끼리** 비교한다 —
즉 O2 도 `test_dev` 에서 개발하고, fuse3 의 `test_dev` 값과 **짝지어** 비교한다.
전체 test 의 0.8325 와 직접 비교하지 않는다.

## 3. 기대치를 어디에 두는가 — 근거 있는 상한

10차 사이클(`candidate/ood_residual_error.md`)이 95% 재현율 문턱에서 남는 오류를
**fuse3 를 쓰지 않고** 독립적인 자(불량 다이 비율)로 쟀다.

| | 값 |
|---|---:|
| 헛경보 정상 19,028장 중 참 결함 하위 25%보다 불량률이 높은 비율 | **0.7804** |
| 놓친 결함 393장 중 정상 중앙값보다 불량률이 낮은 비율 | **0.5140** |

이 둘을 그대로 상한으로 옮기면 이렇게 된다.

- **고칠 수 있는 헛경보는 22% 언저리다.** 19,027 × 0.78 = 14,841장이 남는다면
  **FPR@95TPR 의 현실적 하한은 0.134** 다(14,841/110,701). 지금이 0.1719 이므로
  **O2 가 아무리 잘해도 이 축에서 얻을 수 있는 것은 0.17 → 0.13 근방이다.**
- **고칠 수 있는 놓침은 49% 언저리다.** 나머지 절반은 정상 중앙값보다 불량 다이가 적어
  **웨이퍼맵에 볼 것이 없다.**
- 재현율 80% 운영 지점에서 헛경보 2,778 × 0.78 = **2,167장 아래로 내려가면**
  그것은 **10차 진단이 틀렸다는 증거**다. 그 자체로 값어치 있는 결과이므로 그렇게 보고한다.

**즉 사전 기대치는 "blocked AUPR +0.01~+0.03, FPR@95TPR 0.17 → 0.14 근방" 이다.**
`+0.10` 을 기대하지 않는다. 이 예측을 실행 후 채점한다.

## 4. 설계 제약 — 이 워크스트림이 실측한 것들

1. **크기 불변으로 만든다.** 절대 좌표 표현은 커버리지 구멍에서 무너진다
   (T-PAD template 이 균일 상수와 구분되지 않았다, p=0.1320).
   패치 좌표를 특징에 넣지 않는다.
2. **창이 경계에서 잘리는 것을 먼저 정한다**(정정 11). 웨이퍼 밖이 섞인 패치를
   버릴지, 마스킹할지, 온전 패치만 쓸지를 **코드보다 먼저** 문서에 적는다.
   정정 11 은 이걸 안 정해서 6차 사이클을 통째로 다시 하게 만든 실수다.
3. **정상 웨이퍼 자체를 귀무로 쓴다.** 무작위 배치 귀무는 너무 느슨하다
   (선 창 포화 실측 70% 대 독립 가정 0.2%).
4. **ImageNet 특징을 그대로 쓰지 않는다**(기획서 §4, §7).
5. **명목형을 파괴하는 증강 금지** — 임의 각도 회전, 탄성 변형, 밝기 조정.
   허용: 90도 배수 회전, 뒤집기(격자 정렬이 유지된다).
6. **범위 A 먼저**(결함 모양 사전지식을 안 쓰는 자기지도 과제), B-arm(합성 결함)은
   그 다음이고 **A-arm 과 짝지어** 보고한다(기획서 §10.4).

## 5. 반증 조건 — 하나라도 걸리면 기각이다

1. **`test_dev` 에서 fuse3 대비 짝지은 blocked AUPR 차이 CI 하한이 0 이하면 기각.**
   `paired_aupr_blocked_diff_ci` 를 쓴다(순서 의존 AUPR 금지 — 정정 9).
2. **3 seed 의 blocked AUPR 최소값이 fuse3 를 못 넘으면 기각.**
   O0~O1 은 결정론적이라 면제였지만 O2 는 확률적이다. 레포 실측 run-to-run 범위는 **0.050** 이고
   이는 §3 의 기대 이득(+0.01~+0.03)보다 **크다**. 그러므로 **평균만 보고 채택하지 않는다.**
3. **Scratch, Center, Loc 중 하나라도 CI 가 겹치지 않게 내려가면 기각**(기획서 §6-2).
4. **고유값 개수가 1,000 미만이면 채택 보류.** 운영 지점을 못 고르는 채점기다
   (`k² 5x5` 가 값 25개로 95% 문턱에서 18,790장을 동점으로 만든 전례).
5. **one-class 위반이면 무효.** `tests/test_a37_one_class_endtoend.py` 와 같은 성질을
   O2 파이프라인에도 박는다 — **train 결함 픽셀을 망가뜨려도 test 점수가 비트 단위로 같아야 하고,
   train 정상을 망가뜨리면 달라져야 한다.** 진입점 라벨 검사만으로는 부족하다.
6. **dieSize 구간 `562-776` 또는 `1090-1334` 에서 fuse3 보다 나빠지면 기각**(기획서 §6-5).
   train-none 이 각각 387장, 218장뿐인 진짜 커버리지 구멍이다.
7. **봉인 확인에서 이득이 사라지면 채택하지 않는다.** §6 참조.

## 6. 봉인 홀드아웃 규약 — O2 는 이것부터 지킨다

오늘(11차 사이클) `src/a38_sealed_holdout.py` 로 봉인이 코드에 박혔다.

- **개발과 arm 선택은 `test_dev`(87,695장, 결함 5,799)에서만 한다.**
  `load_partition("test_sealed")` 는 실패한다. 실패하는 게 정상이다.
- **`test_sealed`(30,900장, 결함 2,095)는 O2 의 최종 arm 이 정해진 뒤 딱 한 번 연다.**
  열 때는 새 사전등록과 `unseal=True, reason=...` 이 필요하고 감사 로그에 남는다.
- **봉인에서 짝지은 차이 CI 가 0 을 포함하면 채택하지 않는다.**
  dev 에서 이겼는데 봉인에서 무승부면, 그 이득은 dev 특유일 가능성이 높다.
- 여러 arm 을 봉인에서 비교해 고르지 않는다. **봉인은 고르는 자가 아니라 확인하는 자다.**

## 7. 무엇이면 "학습이 필요 없다" 가 결론인가

**이것도 결과다.** 아래 셋이 다 성립하면 그렇게 적고 사다리를 O3 로 넘긴다.

1. A-arm 이 §5-1 을 못 넘는다(짝지은 CI 하한 ≤ 0)
2. 3 seed 최소값이 fuse3 아래다
3. 헛경보 감소가 §3 의 상한(22%) 안에서 멈춘다

그때의 문장은 **"WM-811K 웨이퍼맵 한 장만 주어지면 학습된 표현이 창 통계를 못 넘는다"** 이고,
그 근거는 10차 진단(남은 오류의 78%/51%)이다. **이 결론은 데이터 탓이지 방법 탓이 아니다** —
그러니 다음 단계는 더 큰 모델이 아니라 **웨이퍼맵 밖의 정보**다(공정 이력, 인접 웨이퍼, lot 문맥).
단 lot 쏠림이 없으므로(상위 10 lot 이 헛경보의 1.24%) **단순 lot 집계는 답이 아니다.**

## 8. 실행 전 예측 — 실행 후 채점한다

1. A-arm 자기지도 + kNN 은 `test_dev` 에서 fuse3 를 **못 넘는다**(짝지은 CI 가 0 을 포함하거나 음수).
2. 넘더라도 **+0.03 을 못 넘는다.**
3. FPR@95TPR 은 **0.13 아래로 안 내려간다**(§3 의 상한).
4. seed 간 변동이 **이득보다 크다**(범위 0.050 대 이득 0.01~0.03).
5. O2 특징과 fuse3 를 **융합하면** 단독보다 낫다 — 서로 다른 결함을 볼 것이기 때문이다.
   (다만 융합 arm 은 별도 arm 으로 보고한다)

## 9. 문헌에 대해

**웹 검색이 이 세션에서 소진됐다.** DRAEM, CutPaste, PatchCore, PaDiM 의 구체적 설계와
보고 수치를 **확인할 수 없다.** 확인 전까지 **그 논문들의 수치나 설계를 인용하지 않는다.**
"DRAEM 식" 같은 표현은 일반적 발상을 가리키는 것이지 재현을 뜻하지 않는다(기획서 §10.5).

# 10. 실행 설계 — 코드보다 먼저 확정한다 (2026-08-23 15:55, 14차 사이클)

§4-2 가 "창이 경계에서 잘리는 것을 **코드보다 먼저** 문서에 적으라" 고 했다(정정 11).
그것만이 아니라 자유도를 여기서 다 못 박는다. **아래를 결과 보고 바꾸면 그건 튜닝이다.**

## 10.1 인코더 — 수용영역을 7x7 로 고정한 얕은 완전합성곱망

3x3 conv 3층(stride 1, padding 1), 채널 **3 → 24 → 32 → 32**, 각 층 뒤 BatchNorm + ReLU.
**수용영역 = 7x7.**

**왜 얕은가.** 질문이 "학습된 표현이 창 통계를 넘는가" 이기 때문이다.
ResNet-18(a11 의 것, 수용영역이 사실상 전역)로 재면 이득이 **수용영역 확대**에서 온 것인지
**학습**에서 온 것인지 못 가른다. 채택된 신호는 3x3, 5x5 창이고
진짜 바닥은 **국소 밀도 7x7** 이다. **같은 7x7 안에서 겨루게 한다.**

**왜 하필 7 인가 — 실측으로 정했다.** "온전 창"(창 안 121칸/81칸/49칸이 전부 다이)
위치 개수를 train-none 에서 셌다.

| 창 | train-none 평균 위치 수 | **유효 위치가 0인 웨이퍼 비율** |
|---:|---:|---:|
| 11x11 | 259.5 | **7.07%** |
| 9x9 | 331.2 | 1.24% |
| **7x7** | **416.1** | **0.11%** |

11x11 이면 train-none 의 7% 가 **점수를 낼 위치가 하나도 없다.** 7x7 은 0.11% 다.

**한계를 미리 적는다**: 요소 B(선 L=11)는 이 수용영역 밖이다.
**그러므로 O2 가 fuse3 를 못 넘어도 "길이 11 짜리 구조를 못 봐서" 라는 설명이 남는다.**
그 설명을 사후에 꺼내지 않기 위해 여기 적어 둔다.

## 10.2 경계 처리 — 온전 창만 점수를 낸다 (정정 11 의 교훈)

- 위치 (i,j) 가 **유효**하다 = 그 7x7 창의 **49칸이 전부 다이**다.
- **자기지도 손실도 유효 위치에서만** 계산한다.
- **뱅크와 질의 둘 다 유효 위치만** 쓴다.
- 유효 위치가 하나도 없는 웨이퍼(0.11%)는 **다이가 가장 많은 창 위치 하나**로 대체하고
  그 개수를 결과에 보고한다. **조용히 빠뜨리지 않는다.**

**입력 인코딩**: 3채널 one-hot(0=다이없음, 1=정상, 2=불량). 웨이퍼 밖은 채널 0.
**패치 좌표를 특징에 넣지 않는다**(§4-1). 완전합성곱이라 구조적으로 안 들어간다.

## 10.3 자기지도 과제 — masked die prediction (범위 A)

- **결함 모양 사전지식을 쓰지 않는다.** 4x4 패치 단위 랜덤 마스크, 비율 0.4.
- 가린 자리는 세 채널 모두 0(어떤 범주도 아님)으로 두고, **가려진 유효 위치에서만**
  3-클래스 교차 엔트로피를 계산한다.
- 픽셀 단위로 흩뿌리지 않는다 — 이웃에서 그대로 베낄 수 있어 과제가 너무 쉬워진다.
- **회전 예측을 쓰지 않는다.** 웨이퍼맵에는 회전 대칭인 클래스가 있다(Edge-Ring).
  옆 워크스트림(`Semi-AD`)이 같은 이유로 masked prediction 을 골랐다.
- 증강은 **90도 배수 회전과 뒤집기만**(§4-5). 임의 각도 회전, 탄성 변형, 밝기 조정 금지.
- 학습 자료는 **train 의 none 29,149장뿐**이다.
  **미라벨 638K 를 쓰지 않는다** — (1) 결함이 섞여 있어 one-class 가 깨지고,
  (2) 9-class 쪽 실측에서 **해로웠다**(macro-F1 0.7261 → 0.6887,
  `../Semi-AD/docs/experiments/candidate/self_supervised.md`).
- Adam lr 1e-3, cosine(warmup 1), 12 epoch, batch 256.

## 10.4 채점 — kNN 패치 메모리 뱅크

- 특징 = 마지막 conv 출력 **32채널**, 위치별로 **L2 정규화**.
- **메모리 뱅크** = train-none 의 유효 위치에서 **고정 시드로 무작위 8,192개**.
  coreset 이 아니라 무작위인 이유: coreset 선택 자체가 손잡이가 되고, 그 손잡이를
  test 로 고르지 않는다는 것을 증명하기 어렵다. **무작위는 시드 하나로 끝난다.**
- 위치 점수 = 뱅크까지 **k=5 최근접 코사인 거리의 평균**.
- **웨이퍼 점수 = 위치 점수의 max.** 채택된 창 통계가 전부 max 라 **같은 집계로 겨룬다.**

## 10.5 대조군 — 무작위 초기화 (이것이 없으면 판정 무효)

**같은 구조, 같은 뱅크·질의·집계, 가중치만 학습하지 않은 arm 을 반드시 같이 낸다.**

이게 없으면 **"자기지도 학습이 이겼다"** 와
**"임의의 비선형 필터뱅크 + kNN 이면 아무거나 이긴다"** 를 못 가른다.
이 워크스트림의 정정 2 가 정확히 빠진 대조군이었고, 9, 12 도 같은 계열이다.

**추가 반증 조건 8**: **학습 arm 이 무작위 초기화 arm 을 짝지은 CI 로 못 넘으면,
blocked AUPR 이 fuse3 를 넘더라도 "자기지도 학습이 기여했다" 고 적지 않는다.**

## 10.6 arm 목록 — 주 arm 과 탐색 arm 을 실행 전에 가른다

| arm | 무엇 | 지위 |
|---|---|---|
| **O2-A1** | 자기지도 학습 인코더 + kNN | **주 arm** |
| **O2-A0** | **무작위 초기화** 같은 구조 + kNN | **주 대조군** (§10.5) |
| **fuse3** | 현재 최선 | 기준선 (`test_dev` 0.8304) |
| (탐색) O2-A1 ⊕ fuse3 | 백분위 → Fisher 융합 | 탐색. 예측 5 를 채점하는 용도 |
| (탐색) 온전 창 가드 없이 전 다이 위치 | 경계 규칙의 반대편 | 탐색. **별도 사전등록 없이 채택하지 않는다** |

## 10.7 seed 와 결정론

- **seed 0, 1, 2** 세 개. 학습 초기화, 마스크, 뱅크 부표집이 전부 시드에 묶인다.
- **무작위 초기화 대조군도 3 seed** — 초기화가 곧 그 arm 의 전부이므로 변동이 더 클 수 있다.
- **평가는 3 seed 의 최소값으로 한다**(§5-2). 평균만 보고 채택하지 않는다.

## 10.8 계산 자원 — CPU 로도 되게 설계했다

GPU 0번은 9-class 학습 큐가 쓰고 있고 1~7번은 **다른 사용자의 작업**이다.
그래서 **CPU 로 끝나게** 규모를 잡았다(64코어).

| 단계 | 추정 |
|---|---|
| 학습 1 seed (29,149장 x 12 epoch) | 약 25분 |
| 특징 + kNN 1회 (train-none + dev 117k장) | 약 12분 |
| 주 arm 2개 x 3 seed | **약 2.5시간** |

**GPU 0번이 비면 쓰되, 9-class 학습 큐를 밀어내지 않는다.**
`nvidia-smi` 만 보고 판단하지 않고 `ps` 로 9-class 학습 프로세스가 없는지 같이 본다
(큐 사이 틈을 큐 종료로 오인하면 남의 학습을 OOM 으로 죽인다).

## 10.9 one-class 를 O2 에서도 비트 단위로 박는다 (§5-5)

`tests/test_a37_one_class_endtoend.py` 와 같은 성질을 O2 파이프라인에 박는다.

- **train 의 결함 웨이퍼 픽셀을 통째로 망가뜨리거나 행을 지워도 test 점수가 비트 단위로 같다**
- **train 의 정상을 망가뜨리면 점수가 달라진다**(안 달라지면 상수 채점기다)

학습이 들어가므로 **시드를 고정한 결정론적 실행**이어야 이 성질을 잴 수 있다.
그래서 학습 루프의 모든 난수를 시드에 묶고, 그것 자체를 테스트로 박는다.

## 정정 — 내가 이 사이클 안에서 두 번 틀렸다

### 정정 A — seed 0 하나로 결론을 내고 기작까지 붙였다

seed 0 이 나온 시점(17:00 경)에 **"자기지도 학습이 표현을 악화시켰다"** 고 중간 보고하면서
유효차원 14.67 → 1.23 이라는 기작까지 붙였다. **seed 1 이 부호를 뒤집었다**(+0.0832).

**더 나쁜 것은 기작 쪽이다.** seed 1 에서 붕괴 진단을 다시 돌렸더니

| | seed 0 | seed 1 |
|---|---|---|
| 유효 차원 (무작위 → 학습) | 14.67 → **1.23** | 13.49 → **1.41** |
| 결함→최근접 정상 거리 (무작위 → 학습) | 0.02951 → **0.00038** | 0.03033 → **0.00078** |
| **성능 (무작위 → 학습)** | 0.4986 → **0.3283 (내려감)** | 0.4692 → **0.5524 (올라감)** |

**붕괴는 두 seed 에서 똑같이 일어나는데 성능은 반대로 간다.**
그러므로 **"붕괴 때문에 나빠졌다" 는 내 인과 주장은 틀렸다.**
이 워크스트림의 정정 6, 11 과 같은 계열이다 — **관측 하나에 기작 이야기를 붙여 사실로 만들었다.**

**살아남는 주장은 이것이다**(그리고 이건 두 seed 에서 재현된다):

> **masked die prediction 은 32차원 표현을 사실상 1차원으로 무너뜨린다**(유효차원 1.2~1.4).
> **그 하나 남은 방향이 좋은 이상 점수인지 아닌지는 초기화가 정하고, 어느 쪽이든
> 창 통계 근처에 못 온다.**

기작도 그 수준에서만 말할 수 있다 — 이 pretext 과제가 실제로 요구하는 출력은
**`P(불량 | 문맥)` 이라는 스칼라 하나**이고, 1x1 conv 머리가 32차원에서 3-클래스 로짓을 뽑으므로
**로그 오즈 방향 하나만 살아 있으면 손실이 최소화된다.** 나머지를 보존할 유인이 없다.
**왜 그 하나가 seed 마다 다른 품질인지는 모른다.**

### 정정 B — 사전등록의 변동 폭 가정이 4배 틀렸다

§5-2 에 **"레포 실측 run-to-run 범위는 0.050 이고 이는 기대 이득(+0.01~+0.03)보다 크다"**
고 적었다. **실측은 학습 arm 0.224, 무작위 초기화 arm 0.141 이다.**

0.050 은 **9-class 분류의 macro-F1 변동**에서 가져온 숫자였다.
**다른 과제, 다른 지표, 다른 모형의 변동 폭을 이 arm 에 옮겨 쓴 것**이고
그건 정정 12 와 같은 실수다 — **어떤 조건에서 잰 값을 그 조건 밖으로 옮겼다.**

**결과적으로 판정이 바뀌지는 않았다**(3 seed 를 이미 요구했으므로).
그러나 **만약 이득이 0.05 근처에서 났다면 3 seed 로도 못 갈랐을 것**이고,
사전등록은 그것을 몰랐다.

## 이 사이클이 남기는 것

1. **채택 arm 은 그대로 fuse3 다.** 학습이 0 인 창 통계가 여전히 최선이다.
2. **무작위 초기화 대조군이 판정을 살렸다.** 그것이 없었으면 "0.33 이니 학습이 약하다" 로
   끝났을 것이고, **"학습이 무작위 초기화보다도 나쁠 수 있다"** 도
   **"seed 에 따라 반대로 간다"** 도 못 봤을 것이다.
3. **작은 n 의 중간 보고가 위험하다는 것을 한 번 더 실증했다.** 이 프로젝트는
   n=2 로 판정했다가 세 번 뒤집혔고, 나는 **n=1 로 보고했다가 뒤집혔다.** 네 번째다.
4. **모르는 것**: 더 큰 수용영역, 다른 pretext 과제, GPU 를 쓴 더 긴 학습.
   전부 **안 재봤다.**
