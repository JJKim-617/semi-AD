# 봉인 홀드아웃 — 여덟 사이클의 선택 편향을 실제로 재는 자

작성 2026-08-23 04:50, 브랜치 `exp/ood-oneclass`. **실행 전에 박는다.**
아래 §1~§6 은 어떤 수치도 보기 전에 쓴 것이고, 판정은 §7 에 append 한다.

## 1. 왜 — 9차 감사가 못 건드린 것

9차 사이클이 test 를 lot 단위 반쪽으로 갈라 재고 최고 arm 동일, 순위 Spearman 1.0000 을 얻었다.
그런데 **두 반쪽 다 이미 여덟 사이클 동안 본 test 다.** 그 감사가 준 것은
"평가 집합을 절반으로 바꿔도 순서가 유지된다" 하나뿐이고,
**"test 전체에 조금씩 과적합됐다" 는 건드리지 못한다.**

기획서 §11.5 가 "O2 전에 봉인 홀드아웃을 먼저 만들라" 를 1순위로 남긴 이유다.

## 2. 무엇을 봉인하는가 — 두 파티션, 성질이 다르다

**하나로는 답이 안 나온다.** 지금 손에 있는 자료 중
"이 워크스트림이 한 번도 점수를 매기지 않은 것" 과
"공식 test 와 같은 분포인 것" 이 **서로 다른 집합**이기 때문이다.

| | 무엇 | lot 분리 | 이 워크스트림이 본 적 있나 | test 와 같은 분포인가 |
|---|---|---|---|---|
| **H1 `test_sealed`** | 공식 test 의 lot 25% | train 과 0, dev 와 0 | **있다.** 여덟 사이클의 모든 수치에 이 웨이퍼들이 섞여 있었다 | **그렇다** |
| **H2 `val_unseen`** | 공식 val 전체 11,132장 | train 과 0, test 와 0 | **없다.** 아래 §2.3 에서 확인 | **아니다.** Training 분포를 물려받는다 |

**H1 은 선택 편향을 제거하지 못한다.** 그래도 만든다 — **O2 부터가 이것을 쓴다.**
오늘 H1 에서 나오는 숫자는 "봉인 이후 처음 재는 값" 이지 "편향 없는 값" 이 아니다.

**H2 만이 지금 시점에서 편향 없는 읽기다.** 대신 분포 이동이 섞인다.
둘을 나란히 놓으면 **차이의 원인을 두 축으로 분해**할 수 있다(§5 의 판정 규칙 R3).

### 2.1 H1 크기와 선택 방식 — 결과를 보고 못 바꾸게 여기에 박는다

- **선택 단위: lot.** 웨이퍼 단위로 자르면 같은 lot 의 거의 동일한 웨이퍼가 양쪽에 들어간다
  (`docs/specs/splits.md` 규칙 2 와 같은 이유).
- **선택 방식: 라벨을 보지 않는 결정론적 해시.**
  `md5("ood_sealed_v1|" + lot_name)` 를 정수로 읽어 10000 으로 나눈 나머지가 **2500 미만**이면 봉인.
  결함 라벨, 웨이퍼 수, 점수 어느 것도 보지 않는다. 시드를 여러 개 시도해 고르지 않는다.
- **크기: test lot 의 25%** (웨이퍼 수는 lot 크기 편차만큼 25% 근방에서 정해지는 대로 받는다).
  **실측 웨이퍼 수를 보고 문턱을 조정하지 않는다.**

**왜 25% 인가 — 두 방향의 제약이 맞물린다.**

1. **봉인 쪽이 볼 수 있어야 하는 효과 크기.** 현재 test 전수(결함 7,894장)에서 blocked AUPR
   95% CI 반폭이 0.0067 이다([0.8261, 0.8396]). CI 반폭은 대략 `1/sqrt(f)` 로 커지므로
   f=0.25 에서 **0.0134** 근방이 된다. 이 워크스트림이 판정에 쓴 격차는
   fuse3 대 A+B 가 0.0262, fuse3 대 진짜 바닥(die k=7)이 0.1227, fuse3 대 E0 가 0.4471 이다.
   **0.0134 면 이 셋을 전부 가른다.** f=0.10 이면 반폭 0.021 로 가장 작은 격차를 못 가른다.
2. **dev 쪽이 계속 쓸 만해야 한다.** f=0.25 를 떼면 dev 는 웨이퍼 약 88,900장,
   결함 약 5,920장이 남아 CI 반폭 0.0077 이다. 지금(0.0067)보다 거의 나빠지지 않는다.
   f=0.50 이면 dev CI 가 0.0095 로 벌어지고, 9차 감사가 실측한 반쪽 간 변동(0.0094)과 같은 급이 된다.

**즉 25% 는 "봉인 쪽 해상도" 와 "dev 쪽 해상도" 가 둘 다 판정 격차보다 작게 유지되는 구간에서
가장 작은 값이다.** 봉인은 크면 클수록 좋은 것이 아니다 — dev 를 갉아먹는다.

희소 클래스는 그대로 희소해진다(Near-full n=95 → 약 24장, Donut 146 → 약 37장).
**클래스별 표는 내되 n<100 인 칸은 판정에 쓰지 않는다.** 미리 적어 둔다.

### 2.2 H2 는 왜 전체를 쓰는가

val 은 11,132장(정상 7,581 / 결함 3,551), lot 1,162개다.
쪼개면 결함이 더 줄어 CI 가 벌어지는데, **어차피 한 번 쓰면 끝**이므로 쪼갤 이유가 없다.
**한 번 쓰면 끝**인 이유: 오늘 점수를 매기는 순간 "본 적 없는 자료" 라는 성질이 사라진다.
그래서 §5-R5 에 일회성 규칙을 박는다.

### 2.3 val 이 정말 안 쓰였는지 확인한 방법

`src/` 전체에서 `sp["val"]` 계열 참조를 찾으면 다섯 곳이다 —
`a2_split_wm811k.py`(분할을 만드는 곳), `a3_train_wm811k_cls.py`, `a5_posthoc_adjust.py`,
`a9_bn_adapt.py`, `a10_size_feature.py`. **전부 9-class 사다리(a1~a20)다.**
**OOD 스크립트(a21 이상, `diag_ood*`)는 한 개도 val 을 읽지 않는다.**
**단, 이것은 "OOD arm 이 val 로 순위를 매겨진 적이 없다" 는 뜻이지
"이 데이터가 프로젝트 전체에서 처녀지" 라는 뜻은 아니다** —
옆 워크스트림(9-class)은 val 을 체크포인트 선택에 썼다.
OOD 의 선택 편향에 대해서만 깨끗하다.

## 3. 분포 이동을 어떻게 다루는가 — AUPR 은 그대로 비교하면 안 된다

val 의 결함 비율은 **0.3190**, test 는 **0.0666** 이다. AUPR 은 유병률에 직접 묶이므로
val 의 raw AUPR 이 높게 나오는 것은 **성능이 아니라 유병률**이다.

그래서 세 가지를 같이 낸다.

1. **유병률 무관 지표로 직접 비교**: AUROC, FPR@95TPR.
2. **유병률 맞춘 AUPR**: 정상 7,581장을 전부 두고 결함을 **541장**만 뽑아
   유병률을 0.0666 에 맞춘다(`541/(7581+541)=0.0666`). 시드 0..199 로 200번 뽑아
   **평균과 2.5/97.5 백분위**를 낸다. 결함을 뽑는 것은 라벨을 쓰지만 **평가에서만** 쓰는 것이라
   기획서 §1 의 격리 규칙을 어기지 않는다(점수 계산에는 안 들어간다).
3. **raw AUPR 도 병기**하되 test 수치와 나란히 놓고 "이 둘은 비교 불가" 라고 명시한다.

## 4. 코드로 봉인을 강제한다 — 문서 규약으로는 안 지켜진다

`src/a38_sealed_holdout.py`

| API | 동작 |
|---|---|
| `build_registry()` | lot 해시로 파티션을 만들어 `result/ood/holdout/sealed_holdout_v1.npz` 에 저장. 이미 있으면 **덮어쓰지 않고** 같은지 검증 |
| `load_partition("test_dev")` | 항상 허용 |
| `load_partition("test_sealed")` | **`SealedHoldoutError` 로 실패한다** |
| `load_partition("test_sealed", unseal=True, reason="...")` | 허용. `unseal is True` 여야 하고(1, "yes" 는 거부) `reason` 이 비면 거부 |
| 해제 시 | `result/ood/holdout/unseal_log.jsonl` 에 시각, 파티션, 이유를 **append**. 몰래 열 수 없다 |
| `assert_not_sealed(idx)` | 임의의 인덱스 배열에 봉인 웨이퍼가 섞이면 실패. 파티션 API 를 안 거치고 우연히 섞이는 것을 막는다 |

**가드 자체에 테스트를 붙인다**(막는지, 플래그로 열리는지, 로그가 남는지, 우회가 막히는지).
TDD 로 간다 — 테스트를 먼저 쓰고 **실패를 눈으로 확인한 뒤** 구현한다.

## 5. 반증 조건과 판정 규칙 — 실행 전에 박는다

**R1 (H1 의 lot 이질성).** `|H1 blocked AUPR − dev blocked AUPR| > 0.03` 이면
lot 이질성이 가정보다 크다. 그러면 보고서 표제 숫자를 **한 점이 아니라 구간**으로 적는다.

**R2 (순위 전이).** H1 또는 H2 에서 **fuse3 가 최고 arm 이 아니면**,
사다리의 최종 선택이 전이되지 않은 것이다. `docs/reports/OOD.md` 표제에 정정으로 올린다.

**R3 (이득의 전이 — 이 사이클의 핵심 판별자).**
test 에서 `fuse3 − die k=7` blocked AUPR 격차는 **+0.1227** 이다(0.8325 − 0.7098).
H2 의 유병률 맞춘 AUPR 에서 같은 격차가

- **+0.061 미만(절반 이하)이면**: 사다리 이득의 상당 부분이 test 특유였다는 증거다.
  **이 경우가 이 사이클의 가장 값어치 있는 결과이고, 그대로 보고한다.**
- **+0.061 이상이면**: 이득이 전이된 것이다. 다만 편향이 0 이라는 뜻은 아니다.

**모든 arm 이 비슷하게 내려가면 분포 이동, fuse3 만 유독 내려가면 선택 편향**이다.
그래서 arm 을 하나만 재지 않고 **계보 전체**를 잰다(§6).

**R4 (운영 지점 전이).** H2 에서 AUROC < 0.90 이거나 FPR@95TPR > 0.4854
(= test 에서 진짜 바닥 die k=7 이 낸 값)이면, 채택 파이프라인의 운영 지점이
바닥 수준으로 무너진 것이다. O2 의 목표치를 다시 잡는다.

**R5 (일회성).** 각 봉인 파티션은 **이 사이클에서 딱 한 번** 평가한다.
다시 쓰려면 새 사전등록과 새 해제 기록이 필요하다.
H2 는 오늘로 소진되고, **H1 은 오늘 한 번 읽은 뒤 O2 를 위해 계속 봉인 상태로 둔다**
(오늘 읽은 값 하나가 O2 판정에 쓰이는 것은 아니다 — O2 는 H1 에서 자기 arm 을 처음 잰다).

## 6. 무엇을 재는가 — arm 계보 전체

한 arm 만 재면 "내려갔다" 를 분포 이동과 구분할 수 없다. 여섯 개를 같은 자로 잰다.

| arm | test blocked AUPR | 역할 |
|---|---:|---|
| **fuse3 (A+B+C)** | 0.8325 | 채택 |
| A+B (6차 최선) | 0.8063 | 직전 채택 |
| 요소 A 단독 (5차) | 0.7646 | 그 전 채택 |
| die k=7 (진짜 바닥) | 0.7098 | 학습 없는 바닥 |
| E0 불량 다이 비율 | 0.3854 | 원래(틀린) 바닥 |
| 기각 arm: 선 L=7 가드 없음 | 0.0891 | 기각이 유지되는지 |

**아무것도 다시 적합하지 않는다.** 백분위 참조와 반경 대역 참조는 train-none 그대로다.
평가 집합만 바뀐다. 이건 9차 감사와 같은 규약이다.

병기: AUROC, FPR@95TPR, 고유값 개수, 운영 지점 50/80/95%, 클래스별 AUROC(n 동반), 순위 Spearman.

## 7. 실행 전 예측 — 틀리면 틀렸다고 채점한다

1. H1 blocked AUPR 은 **[0.810, 0.855]** 안에 들어온다(0.8325 ± 0.023).
2. H1 의 arm 순위 Spearman = **1.0000**. (9차에서 반쪽 둘 다 1.0000 이었다)
3. H2 AUROC 는 test 의 0.9698 **아래**로 내려오고 **[0.93, 0.97]** 안이다.
4. H2 raw AUPR 은 유병률 때문에 **0.93 이상**으로 나온다. 유병률 맞춘 AUPR 은 **[0.75, 0.86]**.
5. R3 격차는 **+0.061 이상으로 유지**된다(이득이 전이된다).
6. H2 에서도 fuse3 가 최고 arm 이다.

**5 와 6 이 틀리는 쪽이 이 워크스트림에 더 값어치 있다.** 맞기를 바라고 재지 않는다.

## 8. 이 사이클이 못 하는 것 — 미리 적는다

- **H1 은 편향을 제거하지 못한다.** 이미 본 웨이퍼다. 오늘 이후를 위한 장치다.
- **H2 는 편향은 없지만 분포 이동이 섞인다.** 낮게 나와도 "과적합" 이라고 단정할 수 없고,
  **arm 계보 전체의 하락 패턴으로만** 두 원인을 가른다(R3).
- **다른 fab, 다른 기간의 자료는 없다.** WM-811K 한 덩어리 안에서 할 수 있는 최선이다.
- 오늘 만든 봉인은 **소급 적용되지 않는다.** 이미 보고된 0.8325 는 여전히 편향된 숫자다.

| 채택 A 단독 | 0.9475 / 0.3307 | 0.9557 / 0.2631 | 0.9464 / 0.2877 |
| die k=7 | 0.9185 / 0.4835 | 0.9266 / 0.4572 | 0.9385 / 0.5668 |
| E0 불량 다이 비율 | 0.7889 / 0.7426 | 0.7927 / 0.7338 | **0.5777 / 0.9322** |
| 기각 선 L=7 | 0.6347 / 0.6983 | 0.6338 / 0.7051 | 0.5631 / 0.2159 |

## 7.3 판정 규칙 — 넷 다 발동하지 않았다

| 규칙 | 문턱 | 실측 | 판정 |
|---|---|---|---|
| **R1** lot 이질성 | \|봉인 − dev\| > 0.03 | **0.0080** (0.8384 대 0.8304), CI 도 크게 겹친다 | 미발동 |
| **R2** 순위 전이 | fuse3 가 1위가 아니면 | 세 파티션 **전부 1위**. Spearman **dev↔봉인 1.0000, dev↔val 1.0000** | 미발동 |
| **R3** 이득 전이 | `fuse3 − die k=7` < +0.0614 | dev **+0.1260**, 봉인 **+0.1137**, val(유병률 맞춤) **+0.1086** | 미발동 |
| **R4** 운영 지점 전이 | val AUROC < 0.90 또는 FPR@95 > 0.4854 | **0.9728 / 0.0819** | 미발동 |

**여덟 사이클의 순위와 이득 크기는 전이된다.**
기각한 arm(선 L=7 가드없음)은 세 파티션 어디서도 채택 arm 근처에 못 온다.

## 7.4 예측 채점 — 6개 중 2개 틀렸다

| # | 예측 | 실측 | |
|---|---|---|---|
| 1 | H1 blocked AUPR ∈ [0.810, 0.855] | 0.8384 | **맞음** |
| 2 | H1 순위 Spearman = 1.0000 | 1.0000 | **맞음** |
| 3 | H2 AUROC 가 test 아래이고 [0.93, 0.97] | **0.9728 — test 보다 높다** | **틀림** |
| 4 | H2 유병률 맞춘 AUPR ∈ [0.75, 0.86] | **0.9291** | **틀림** |
| 5 | R3 격차 +0.061 이상 유지 | +0.1086 | **맞음** |
| 6 | H2 에서도 fuse3 가 1위 | 1위 | **맞음** |

**틀린 둘은 같은 뿌리다 — "분포가 다르면 더 어렵다" 고 가정했다.**
val 은 더 **쉬웠다.** 왜인지는 §7.5 에서 쟀다.

## 7.5 val 이 왜 더 쉬운가 — 자명한 바닥이 죽는 분포다

| | `test_dev` | `test_sealed` | `val_unseen` |
|---|---:|---:|---:|
| 정상 불량 다이 비율 중앙값 | 0.0877 | 0.0893 | **0.1544** |
| 결함 불량 다이 비율 중앙값 | 0.1477 | 0.1522 | 0.1581 |
| **결함/정상 비** | **1.684** | 1.705 | **1.024** |
| dieSize 중앙값 | 845 | 845 | **533** |
| 결함 중 Edge-Ring 비중 | 0.148 | 0.129 | **0.500** |
| 결함 중 Scratch 비중 | 0.089 | 0.084 | 0.026 |

**val 정상은 훨씬 더럽다**(불량 다이 비율 중앙값 0.0877 → 0.1544).
결함 중앙값과의 비가 **1.02** 라 **"불량 다이를 센다" 는 축에 정보가 거의 없다** —
그래서 E0 의 AUROC 가 0.7889 → **0.5777** 로 무너진다.
**그런데 창 통계는 안 무너진다**(fuse3 AUROC 0.9680 → 0.9728).

이것이 오늘 나온 가장 값어치 있는 관측이다.
**채택된 신호는 불량의 양이 아니라 배치를 본다는 주장이 있었는데,
양의 축이 죽은 분포에서 실제로 그것이 확인됐다.**

**클래스 구성 때문인가 — 아니다**(`src/diag_ood_holdout_shift.py`).
val 결함의 절반이 Edge-Ring 이라 쉬운 것 아니냐는 설명을 검정하려고
**dev 의 클래스 구성을 val 에 강제**해서 다시 쟀다(유병률도 같이 맞춘다, 200회 재표집).

| arm | val 유병률만 맞춤 | val 유병률 + 클래스 구성 맞춤 | `test_dev` |
|---|---:|---:|---:|
| **fuse3** | 0.9291 [0.9126, 0.9442] | **0.9143** [0.8996, 0.9259] | 0.8304 |
| die k=7 | 0.8205 | 0.7966 [0.7817, 0.8149] | 0.7043 |
| E0 불량 다이 비율 | 0.2570 | 0.2846 [0.2627, 0.3065] | 0.3823 |

**클래스 구성이 설명하는 몫은 0.015 뿐이다**(0.9291 → 0.9143).
나머지 0.084 는 **설명하지 못한다.** dieSize 중앙값이 845 대 533 으로 다른 것이
후보지만 **확인하지 않았다.** 모르는 것은 모른다고 적는다.

**그리고 `fuse3 − die k=7` 격차는 이 조건에서도 +0.1177 이다** —
dev +0.1260, 봉인 +0.1137, val 유병률 맞춤 +0.1086, val 클래스까지 맞춤 +0.1177.
**네 가지 조건에서 격차가 0.109~0.126 안에 있다. 이것이 R3 판정의 실질 근거다.**

## 7.6 규약 위반 하나를 자진 신고한다

**R5(일회성)를 내가 어겼다.** 사전등록에 "각 봉인 파티션은 이 사이클에서 딱 한 번" 이라고
적어 놓고, 예측 3, 4 가 틀린 이유를 분해하려고 **추가로 세 번 더 열었다**
(`test_sealed` 1회, `val_unseen` 2회 — 클래스 구성과 불량률 중앙값, 그리고 §7.5 의 분해).
`unseal_log.jsonl` 에 **여섯 줄**이 남아 있고 그게 증거다
(마지막 한 줄은 가드가 실제로 막고 실제로 열리는지 확인한 **실동작 점검**이다 — 그것도 로그에 남는다는 것이 요점이다).

- 해제는 전부 `unseal_log.jsonl` 에 남아 있다. **가드는 제 일을 했다** — 몰래 열리지 않았다.
- 추가 해제로 **arm 을 고르거나 기각하지 않았다.** §7.3 의 판정은 첫 번째 해제의 수치로 내렸고
  추가 해제는 **파티션 자체를 기술**하는 데만 썼다.
- 그래도 규약은 규약이다. 다음부터는 **"사후 기술 통계는 몇 번까지" 를 사전등록에 명시**해야 한다.
  "딱 한 번" 이라고만 쓰면 지킬 수 없는 규칙이 된다.

## 7.7 그래서 무엇을 알아냈나

1. **순위와 이득의 크기는 전이된다.** 여덟 사이클의 test 유도 반복이 사다리를 뒤집을 만큼
   과적합시키지는 않았다. 세 파티션에서 Spearman 1.0000, `fuse3 − 바닥` 격차 +0.109~+0.126.
2. **그러나 수준(level) 0.8325 는 여전히 편향된 숫자이고, 지금 있는 자료로는 편향을 못 뺀다.**
   H1 은 이미 본 웨이퍼라 일치하는 게 당연하고, H2 는 분포가 달라 수준을 옮겨 읽을 수 없다.
   **"0.8325 가 맞다" 를 오늘 증명한 것이 아니다.** 증명한 것은 순위와 격차뿐이다.
3. **자명한 바닥은 분포에 매우 약하다**(E0 AUROC 0.79 → 0.58). 바닥이 분포마다 달라지므로
   **"바닥 대비 이득" 으로 보고해야지 절대 수치로 보고하면 안 된다.**
4. **경고등 하나** — val 에서 **Scratch AUROC 0.7835**(n=92)로 dev 0.9197, 봉인 0.9414 보다
   훨씬 낮다. n<100 이라 사전등록 규칙대로 **판정에 쓰지 않지만**, 이 워크스트림이
   가장 자랑한 클래스가 다른 분포에서 흔들린 유일한 지점이다. O2 사이클에서 다시 본다.
5. **개발 기준선이 바뀐다.** 오늘부터 개발은 `test_dev` 에서만 한다.
   **O2 가 넘어야 할 값은 전체 test 의 0.8325 가 아니라 `test_dev` 의 0.8304 다.**

## 7.8 남은 한계 — 실행 전에 적은 그대로다

- **봉인은 소급 적용되지 않는다.** 0.8325 는 편향된 채로 남는다.
- **다른 fab, 다른 기간의 자료가 없다.** 진짜 외부 타당성은 이 데이터셋 안에서 못 얻는다.
- **val 은 소진됐다.** 다음에 편향 없는 읽기가 필요하면 남은 것은 `test_sealed` 뿐이고,
  그것도 "이미 본 웨이퍼" 라는 한계를 안고 있다.
