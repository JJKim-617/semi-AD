# 가설 — 미라벨 638,507장으로 사전학습하면 표현이 좋아진다

제안일 2026-08-22. 상태: 실험 예정.

## 근거

WM-811K 811,457장 중 라벨은 172,950장뿐이고 **638,507장(78.7%)을 전혀 쓰지 않고 있다.**
라벨 데이터의 3.7배다. 지금까지 개선은 전부 라벨 데이터 안에서 짜낸 것이다.

## 왜 masked prediction 인가

pretext task 후보를 검토했다.

- **회전 예측**: 부적합하다. 웨이퍼맵은 회전 대칭인 클래스가 있다(Edge-Ring 은 90도 돌려도
  Edge-Ring 이다). 대칭인 표본에서는 정답이 유일하지 않아 학습 신호가 잡음이 된다.
  우리가 dihedral 증강을 쓰는 것 자체가 이 불변성을 인정한다는 뜻이다.
- **대조 학습(SimCLR 류)**: dihedral 을 view 로 쓰면 이미 증강으로 얻는 불변성과 겹친다.
  음성 표본 설계 부담도 크다.
- **masked die prediction**: 채택. 일부 die 를 가리고 문맥에서 그 상태를 맞힌다.
  대칭 문제가 없고, 결함의 공간적 구조를 배워야 풀리는 과제다.
  "이 자리 옆이 다 불량이면 여기도 불량일 확률이 높다" 는 것이 정확히 결함 패턴 지식이다.

## 설계

- 인코더는 분류와 동일한 ResNet-18(stem 3x3 s1, maxpool 제거). 사전학습 후 그대로 옮긴다.
- 디코더는 가벼운 conv 몇 층. 픽셀별 3-클래스 logit 을 낸다.
- 손실은 **가려진 위치에서만** 계산한다. 안 가린 곳은 그냥 복사하면 되므로 신호가 없다.
- 마스크는 정사각 패치 단위. 픽셀 단위로 흩뿌리면 이웃에서 그대로 베낄 수 있어 과제가 너무 쉽다.

## 검증 설계

기준선은 E8(pad, 0.7485). 사전학습한 인코더로 초기화하고 나머지는 동일하게 학습한다.

| 태그 | 조건 | 답하는 질문 |
|---|---|---|
| `e12_ssl` | 미라벨 638K 로 사전학습 후 fine-tune | 사전학습이 도움이 되는가 |
| `e12_ssl_labeled_only` | **대조군.** 라벨 데이터 172K 만으로 사전학습 후 fine-tune | 이득이 데이터 양 때문인가, 사전학습 자체 때문인가 |

두 번째가 핵심이다. 사전학습 자체가 좋은 것과, 미라벨 데이터가 추가 정보를 준다는 것은
다른 주장이다. 대조군이 없으면 구분할 수 없다.

## 기각 조건

- `e12_ssl` 이 기준선을 잡음 기준선(0.0089) 이상 못 넘으면 사전학습은 이 문제에 무용하다.
- `e12_ssl` 과 `e12_ssl_labeled_only` 가 비슷하면 이득은 미라벨 데이터가 아니라
  사전학습이라는 절차 자체에서 온 것이다.

## 주의

미라벨 638K 의 클래스 구성은 알 수 없다. 라벨된 것과 분포가 다를 수 있고,
그 경우 사전학습이 오히려 편향을 심을 수 있다. BN 적응이 실패한 것과 같은 위험이다.
다만 사전학습은 표현만 배우고 결정 경계는 fine-tune 에서 라벨로 다시 잡으므로
BN 통계 교체보다는 위험이 작다고 본다. 결과로 확인한다.

# 중간 결과와 사전 예측 (2026-08-22 07:30, 대조군 대기 중)

## 관측

| 조건 | n | 평균 macro-F1 | **seed 범위** | 평균 accuracy |
|---|---:|---:|---:|---:|
| 무작위 초기화 (기준선) | 3 | **0.7261** | **0.0495** | 0.9553 |
| SSL 811K (미라벨 포함) | 2 | 0.6887 | **0.0025** | 0.9219 |
| SSL 172K (라벨만, 대조군) | 2 | 진행 중 | | |

평균은 0.037 낮은데 **seed 범위가 20배 작다.** 공유된 사전학습 가중치에서 출발하니
초기화 무작위성이 대부분 제거된 것으로 보인다.

클래스별로는 방향이 갈린다.

| 클래스 | 기준선 | SSL 811K | 차이 |
|---|---:|---:|---:|
| **Loc** | 0.649 | 0.426 | **-0.223** |
| **Edge-Loc** | 0.638 | 0.441 | **-0.197** |
| none | 0.979 | 0.961 | -0.018 |
| **Scratch** | 0.500 | **0.602** | **+0.102** |
| Near-full | 0.881 | 0.916 | +0.035 |

none 누출은 2,962 -> 6,800 으로 2.3배 늘었다.

**Scratch 가 오른 것이 의미심장하다.** 이 프로젝트 seed 분산의 3/4 을 만들던 것이
Scratch 붕괴였는데(기준선 0.613 / 0.280 / 0.608), SSL 모델은 두 seed 다 0.602 로 붕괴가 없다.
SSL 이 그 실패 모드를 없앤 대신 Loc, Edge-Loc 을 크게 잃었다.

## 앙상블 기여에 대한 예측 (재기 전에 쓴다)

E14 에서 단독 성능이 앙상블 기여를 예측하지 못한다는 것이 확인됐으므로,
0.6887 이라는 낮은 점수만으로 판단하지 않는다. 두 가지가 서로 반대로 작용한다.

1. **서로 비슷하다** — seed 범위 0.0025 는 두 SSL 모델이 거의 같은 함수라는 뜻이다.
   따라서 **둘째 SSL 모델은 첫째에 거의 아무것도 못 보탤 것이다.**
2. **기준선과는 다르다** — 클래스별 프로파일이 반대 방향이다(Scratch 강, Loc 약).
   따라서 **첫째 SSL 모델은 기여가 양수일 것이다.**

**예측: e12_ssl_s0 의 leave-one-out 은 양수, 그리고 SSL 을 둘 다 넣은 조합이
하나만 넣은 조합보다 나아지는 폭은 다른 표현을 하나 더 넣는 것보다 작다.**

틀리면 "구성원 간 유사도가 앙상블 기여를 결정한다" 는 내 모형이 틀린 것이다.

# 결과 — 미라벨 데이터가 해로웠다 (2026-08-22)

## 세 조건

설정은 tag 외에 완전히 동일하다(`cls_e8_pad.yaml`, `cls_e12_ssl.yaml`, `cls_e12_ssl_lab.yaml`).
사전학습도 3 epoch, patch 8, mask 0.5 로 같고 **데이터만 다르다.**

| 조건 | n | 평균 macro-F1 | seed 범위 | 값 |
|---|---:|---:|---:|---|
| **무작위 초기화 (기준선)** | 3 | **0.7261** | 0.0495 | 0.7485 / 0.6991 / 0.7308 |
| SSL 172K 라벨만 (대조군) | 2 | 0.7079 | 0.0062 | 0.7049 / 0.7110 |
| SSL 811K 미라벨 포함 | 2 | **0.6887** | 0.0025 | 0.6899 / 0.6874 |

## 판정

사전 등록한 질문은 *"이득(또는 손해)이 미라벨 데이터에서 오는가, 사전학습이라는 절차 자체에서 오는가"* 였다.

**1. 미라벨 638K 는 확실히 해롭다.** `ssl_all` 최고값 0.6899 가 `ssl_lab` 최저값 0.7049 보다 낮다.
두 조건이 겹치지 않는다. 격차 0.015 는 각 조건 내부 범위(0.0025, 0.0062)의 2~6배다.

**2. 라벨만 사전학습은 판정 불가.** 0.7049, 0.7110 이 기준선 범위(0.6991~0.7485) 안에 들어 있다.
평균은 0.018 낮지만 기준선의 seed 범위가 0.0495 라 구별되지 않는다.
**"사전학습 절차 자체가 해롭다" 고 말할 근거는 없다.**

정리하면 **손해는 미라벨 데이터에 특정된다.**

## 용량-반응 관계가 이를 뒷받침한다

사전학습 데이터가 172K -> 811K 로 늘 때 모든 효과가 **단조롭게** 커진다.

| | 기준선 (0) | 172K | 811K |
|---|---:|---:|---:|
| macro-F1 | 0.7261 | 0.7079 | 0.6887 |
| **none -> 결함 누출** | **2,962** | **4,249** | **6,800** |
| Loc F1 | 0.649 | 0.477 | 0.426 |
| Edge-Loc F1 | 0.638 | 0.603 | 0.441 |
| **Scratch F1** | **0.500** | **0.561** | **0.602** |
| seed 범위 | 0.0495 | 0.0062 | 0.0025 |

우연이 이런 정렬을 만들 확률은 낮다. 사전학습 양이 원인이라는 쪽으로 기운다.

## 교란을 밝힌다

epoch 은 3 으로 같지만 **gradient 업데이트는 4.7배 다르다**(243만 대 52만 표본).
"데이터 양" 과 "연산량" 이 얽혀 있다.

**다만 결론을 위협하지 않는다.** 데이터도 많고 연산도 많은 쪽이 **더 나빴기** 때문이다.
반대였다면 둘을 가릴 수 없었을 것이다.

덧붙여 `ssl_all` 은 **사전학습 목표에서는 더 잘 배웠다**(loss 0.0752 대 0.0859).
pretext task 를 더 잘 푼 쪽이 downstream 에서 더 못했다.

## 왜 그런가 (가설, 미검증)

미라벨 638,507 장은 **결함 유형이 라벨링되지 않은** 웨이퍼들이다. 마스킹된 다이를 복원하도록
사전학습하면 인코더가 그 웨이퍼들의 산발적 불량 패턴을 "구조" 로 취급하게 되고,
그래서 정상 웨이퍼의 잡음까지 결함 신호로 읽는 쪽으로 편향된다 — none 누출이
2,962 -> 6,800 으로 단조 증가하는 것이 그 그림과 맞는다. **추측이고 검증하지 않았다.**

## 채택하지 않지만 남는 실마리

앙상블 기여(leave-one-at-a-time)는 -0.010 으로 음수다. 채택하지 않는다.

그러나 **Scratch 안정화는 값어치가 있다.** 이 프로젝트 seed 분산의 3/4 을 만들던 것이
Scratch 붕괴였는데(기준선 0.613 / **0.280** / 0.608), SSL 모델은 두 seed 다 0.602 로 붕괴가 없다.
seed 범위도 0.0495 -> 0.0025 로 20배 줄었다.

사전학습이 Loc, Edge-Loc 을 망가뜨리지 않으면서 그 안정화만 가져올 수 있는지는 안 해봤다.
후보: 더 짧은 사전학습, 인코더 하위 층만 싣기, 미라벨 대신 라벨 데이터만 더 오래.
**전부 추측이다.**
